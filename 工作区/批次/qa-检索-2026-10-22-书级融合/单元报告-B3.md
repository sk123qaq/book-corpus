# B3 单元报告：README 选章

日期 2026-10-22。批次目录 `工作区/批次/qa-检索-2026-10-22-书级融合/`。方案 `工作区/方案/书级融合与按需扩展-2026-10-22.md` §B3。

## 结论

README 解析、章节标题、卷名、首末章、缺 README 回退都做完了，四条实跑与性能门槛全过。**唯一的否定结果是「按标题重合度重排章序」没通过方案自己的 5 点线**：默认参数下章 hit@10 与只用段落完全相同（54/60 对 54/60），把标题权重加到 0.5 也只到 56/60（+3.3 点）。

所以按方案的停止线，**重排机制默认关闭**，章序只由段落分决定。README 仍然保留它的用处：章标题、卷名、首末章、README 顺序作并列时的次序。B4 的 L0 元数据里的章标题和「首尾章名」就来自这里。

## 交付的文件

| 文件 | 行数 | 内容 |
|---|---|---|
| `工作区/脚本/book_readme.py` | 233 | `readme_toc` 解析目录、`select` 选章、`context_line` 首末章、CLI |
| `工作区/批次/qa-检索-2026-10-22-书级融合/test_book_readme.py` | 322 | 五个单元用例、`--counts`、`--compare`、`--perf` |

`book_readme.py` 的实现口径：

- 只读 `## 目录` 到下一个 `## ` 之间的行。跳过图片、锚点、外链、非 md 目标。相对链接先还原 `<...>` 与 `%20`，再按 `库/<book>/md/` 解析，越界目标丢弃。
- 卷名从 `- **第一卷…**` 这类行取，挂在后续的章上。
- 章号与标题：`NNN_标题.md` 取 `标题`。README 缺失时按文件名排序，`readme_status=missing`；有 README 但目标缺失或有未列文件时，已列的按 README 顺序、未列的按文件名补在后面，`readme_status=partial`。
- 选章分：`base * (1 + 0.10*cov + title_weight*title)`。`base` 是该章最高段落分，`cov` 是该章命中的组词比例，`title` 是问句词落在章标题里的比例。`title_weight` 默认 0，CLI 有 `--title-weight`。
- 前三章按检索分排，不是书开头的三章。命中不足三章时有几章返回几章。
- 不索引 README，不写 `md/`，不改 README。长网文的输出只打命中的三章加首末章名。

## 对照实验：README 选章 vs 只用段落

60 题 gold，两把选章器吃同一批命中、同一批 top10 书，只差章序。

```
$ python3 .../test_book_readme.py --compare
题数 60
书 hit@10              0.983
章 hit@10 只用段落     0.900  (54/60)
章 hit@10 README 选章  0.900  (54/60)
章 hit@10 差 +0.000 点
规则 章 hit@10 提升 >= 5 点: FAIL
```

标题权重阶梯（改动只在 `select` 的 `title` 一项，其余不变）：

| title 权重 | 章 hit@10 | 命中题数 |
|---|---|---|
| 0（默认） | 0.900 | 54/60 |
| 0.15 | 0.900 | 54/60 |
| 0.5 | 0.933 | 56/60 |
| 1.0 | 0.933 | 56/60 |
| 2.0 | 0.933 | 56/60 |

权重 0.5 多捞回两道：O05《枪炮、病菌与钢铁》（可接受章全库第 22）与 L03《遮天》（第 8）。剩下四道：

| 题 | 书名次 | 证据章全库名次 | 说明 |
|---|---|---|---|
| L02 完美世界 | 1 | 32 | 书内前三章都是别的章节，标题也不含查询词 |
| L08 史铁生作品全 | 1 | 790 | 证据章的段落分远低于同书其他章 |
| L14 十日终焉 | 1 | 5 | 全库前 5，但同书另有三章段落分更高 |
| S17 长路 | 97 | 154 | 书就没进 top10，与选章无关 |

即使把这四道里能救的三道全救回来，上限是 57/60（0.950），刚好够 5 点线；实际最好到 56/60。

默认参数下两把选章器的章集合在 10/60 题上不同（`cov` 项会换掉个别章），但命中题数一样。

### 天花板与把握度

| 量 | 数 |
|---|---|
| 实践上限 | 59/60 = 0.983（S17 的书排第 97，章级任何选章器都到不了） |
| 段落选章的可达余量 | 5 题（0.900 到 0.983） |
| +5 点需要的题数 | 3 题 |
| README（title 权重 0.5）修好 | 2 题，弄坏 0 题 |
| McNemar 精确检验 | p = 0.500 |

0.900 确实已经接近 0.983 的上限，+5 点等于要吃掉 5 道可达余量里的 3 道。它不是绝对天花板（3 道够得着），但只有 5 个样本，一题就是 1.7 点，这套检验分不出「真的加 3.3 点」和「噪声」。这是方案那条 5 点线在高基线上的局限，不是选章器本身坏了。

## 发现

1. **README 的标题信号有，但不够 5 点。** 权重 0.5 起能救两道，说明「章标题含查询词」是有效信号，只是本 gold 的可救题只剩三道，达不到门槛。要复用这个信号，得等 B4 的按需扩展或 B5 的书卡提供更细的题。
2. **章序不是主要瓶颈。** 目标书自己的最佳章就是可接受章的 47/60，可接受章在书内前三章的 55/60。选章的剩余空间只有 5 道，其中 2 道是证据章段落分太低（L08 第 790），不是排序能解决的。
3. **S17 是书级问题，不是章级问题。** 书排第 97，任何选章器都救不了。
4. **缺 README 只有 3 本，都是单章书。** 回退路径不会在真实库里经常触发，但单元测试覆盖了。
