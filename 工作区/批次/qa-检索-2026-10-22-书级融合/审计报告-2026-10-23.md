## P1：影响验收结论的问题

### P1-1 B5 书卡门槛的对比宽度不对等，`+19` 是宽度差不是卡片收益

- 位置：`book_cards.gate()`：`loop_book = loop_rank[0]`，自动路径只把**第 1 名**送进 `_hit`；卡片侧遍历全部 6 张卡，目标书在任意一张卡里就算命中。
- 等宽复测（`audit_fair_gate.py`，产物 `live/B6/audit-fair-gate.tsv`）：

| 口径（21 道触发题） | 命中 |
|---|---|
| 自动/循环 top1 | 13/21 = 0.619 |
| 循环 top3 | 17/21 = 0.810 |
| 循环 top5 | 17/21 = 0.810 |
| 卡片 top1 | 13/21 = 0.619 |
| 卡片 top3 / top6 | 17/21 = 0.810 |

- 全部 60 题：循环 top5 = 0.883；默认路径（触发卡 + 未触发循环 top5）也是 0.883。**卡片在等宽口径下检索收益为 0**；`+19` 全部来自「1 个展示位 vs 6 个展示位」。
- 影响：`单元报告-B5.md`、`单元报告-B6.md`、`目录/检索/README.md`、`目录/检索/踩坑记录.md`、决策记录 54/55/56 行都引用了 `+19` / `+1.7`。B5 报告已加审计修订注；其余文档待改。
- 建议：`gate()` 增加 `auto_top3/top5`、`loop_top3/top5`、`card_top3` 列；门槛用同宽基线；`recommend` 不再用触发子集单独判过。默认展示可以保留为产品决定，但门槛读数要写成「等宽收益 0」。

### P1-2 B5 gate 未触发题走 auto，B6 接在循环后却没有重跑 gate

- 位置：`book_cards.gate()` 的未触发分支 `card_hit, kept_hit = auto_hit, auto_hit`；而 `book_query` 默认路径是 `p.plan()`（B2.5 循环）之后才开卡。

- 影响：`effective_hit=0.750` 不是默认路径的真实值；默认路径按 top5 是 0.883（见 P1-1）。B6 的「默认值验收」缺少 60 题质量读数。
- 建议：`gate()` 未触发分支改用 `loop_hit`/`loop_long`；卡片命中使用 `default_selection` 前三本；在 `live/B6/` 重跑 gate，并把结果写进 B6 报告。

### P1-6 B4 的预算、超时、调用上限与方案不一致，且没有决策记录

## P2：方案/文档/覆盖问题

- **`rrf5` 不是 RRF**：`book_score.SCHEMES["rrf5"]` 是对本书前 5 段各加 `1/(60+i)`，等价于「命中段数」计数器；B2 报告把它当长书抑制的对照，读数 0.467 是机制假象。要么实现真正的跨排序 RRF，要么改名 `hitcount5` 并在方案/报告注明。
- **`book_query --concept` 丢弃 `exclude`**：`groups, _ = qsearch.load_concept(...)` 丢掉排除词，`Planner.search` 恒传 `[]`；`book_score --concept` 传了 exclude。`--concept 自由` 因此包含「自由邦/自由市场」等段落，与 `book_score` 不是同一批数据；B2.5 报告 Open 已承认 `--concept` 未调。
- **B4 L0 在生产路径不可达**：`run_chapter` 首包固定 `first=1`，全文件没有 level 0 的 `make_packet` 调用；L0 只在单测里直接调。方案说「先给 L0 元数据，再给 L1」，实现是把元数据塞进 prompt 头部。**2026-10-23 判定维持现状**：元数据每轮都在 prompt 头部（路径、字数、行数、最佳命中行），L0 作为层级仍可单独测；不单独占一轮模型调用，因为 24 次硬上限与单次 8–50 秒不支持把首包拆成两轮。
- **B4 L3 `evidence_lines` 窗口洞**：`given.append((packet.window_start, packet.window_end))` 对 grep 使用 `min(used), max(used)`，命中之间的未给行也算合法；邻章包 `(0,0)` 让第 0 行合法。`context` 允许到 20，方案是前后 5 行；`len(out)` 是行数却和 4,000 字预算比。**2026-10-23 22:02 已修**：`targeted` 返回实际给出的连续行区间，`context` 封顶 5，预算按字算，没有窗口文本的包不进 `given`；`test_book_expand.py` 加 4 例到 21 例。
- **B4 长网文跳过摘要未实现**：方案说「长网文默认跳过生成摘要，用 README 章名」，`book_expand` 没有 `subject1`/类型分支，lane 3/4/5 对《凡人修仙传》《完美世界》《剑来》都调了模型。
- **B5 长书占比分母不同**：卡片侧 `/len(cards)`（6），循环侧 `/10`；一本长书在卡片里是 0.167，在 top10 里是 0.100，`long_cards 0.175 vs long_loop 0.153` 部分是分母造成的。`gate_verdict` 注释说「同单位」，实际不同。
- **B5 卡数可能少于 5**：`build_cards` 只取 `ranking[:n]`，`石昊 天人族 收拾` 只有 2 本书命中，于是 2 张卡；方案说「一次显示五到八张」。不是每次都错，但缺「不足时怎么办」的规则。
- **B6 lane-2 只证明确定性**：`probe_b6.lane2()` 跑两遍 `qsearch --book --book-score mix` 比 stdout；两遍相等不证明「旧排序能复现」，baseline 里没有改动前的输出可比。应 diff 一份 B2 阶段的 mix 留档。
- **B6 文档数字漂移**：`目录/检索/README.md` 与 B6 报告首版写 1,374/1,493、缺 119；`baseline/index-gap.txt` 是 1,489/1,374、缺 115（另有 4 本图片书不索引）；15:xx 复跑已是 1,513/1,374、缺 139（实际待索引 135）。数字随 OCR 续跑变化，文档应带 as-of 时间。
- **B5/B6 报告计数过期**：B5 报告写 34 例 / 692 行；B6 加 `cards_for`/`expand_selected` 后是 37 例 / 717 行。B4 报告写 15 例，实际 16；`book_expand.py` 612 行 → 668，`test_book_expand.py` 239 → 269。B6 报告原写 94 例，审计后 95。
- **B4 lane-4 是旧配置**：`live/B4/lane-4.json` 的 `mode=deep`、`calls=6`、`rounds=6`、`budget=60`，mtime 早于 lane-3/5；当前 `deep` 是 `rounds=3`、`budget=80`、`calls=None`。报告把它当当前深挖证据，实际没有覆盖当前配置。
