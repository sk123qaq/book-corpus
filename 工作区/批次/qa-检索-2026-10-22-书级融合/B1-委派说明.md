## qsearch.search 的返回

hits 是 dict 列表，字段 `{id, path, book, line, text, bm25, kana, coverage, score}`。`book` 形如 `文学/网络文学/驭房有术`，`path` 形如 `库/文学/网络文学/驭房有术/md/001_x.md`，`score` 是正数越大越相关，`coverage` 是该段命中的组数（int）。

## book_score.py 规格

模块 docstring 写清公式与 CLI 用法。不写无关注释。

常量与 `qsearch.py` 同一套推导：`DB = 目录/检索/index.db`，`LIBDB = 目录/library.db`。

数据形状：一个 dataclass `BookScore`，字段名固定为
`book, title, type, chapters, best, best_path, best_line, best_text, support, topk, coverage, score, groups, has_prefix, has_queries`
再加四个供对照方案使用的原料字段：`scores`（降序 `list[float]`）、`hits`（int）、`mean`（float）、`total_groups`（int）。
`groups` 是本书命中到的组词 `list[str]`（按首次出现顺序，去重）。`type` 用下面的 genre 口径。

聚合规则：输入 hits、groups（`list[str]`，每个元素是一个组词）、exclude（`list[str]`）、meta、expand_flags。
- 每个 hit 算它命中的组：先用 `re.sub` 把 exclude 词从 text 去掉（与 `qsearch.group_hits` 同口径），再取包含于 text 的组词；一个组词算一个组。全书 `groups` 是并集。
- `coverage = len(groups) / max(1, total_groups)`，`total_groups = len(groups 入参)`。
- `best = max(score)`，`best_path`/`best_line`/`best_text` 取最好那一段（并列取 path、line 更小者）。
- `support = min(5, 满足 score >= 0.75 * best 的段数)`。
- `topk` = 最好的 `min(3, support)` 个 score 的均值。
- 默认 `score = 0.60*best + 0.25*topk + 0.15*coverage + 0.05*log1p(support)`。
- `best <= 0` 的书整条丢弃。
- 并列排序键：`(-score, book, best_path, best_line)`。
- 长度项只在 `best_support_length` 方案里出现：`默认 score - 0.02*log1p(chapters)`。默认方案不含长度项。

章节数：从 `library.db` 读
`SELECT b.path, b.title, b.subject1, b.subject2, d.chapters FROM book b LEFT JOIN derived d ON d.uid=b.uid AND d.kind='md'`。
derived 没有这一行或 chapters 为空时，数 `<ROOT>/库/<book>/md/*.md` 的文件数（book 是库内相对路径）。读不到当 0。不加表不加列。

expand 特征：一次读 `SELECT DISTINCT path, kind FROM expand`，把 path 的 `/md/` 之前部分当 book，得到该书的 `has_prefix` / `has_queries` 布尔。没有 expand 行时两个都 False。没有行不能当零分。

genre 口径与 `book_rank_bench.py` 现有 `genre()` 完全一致：subject2 属 `("网络文学","类型小说")` → `网文/类型`；subject1 == `人文社科` → `社科`；subject1 == `文学` → `文学`；否则 subject1；书表里没有 → `?`。这个函数放 `book_score.py`，bench 改成 import 并删掉重复定义。

方案注册表 `SCHEMES`，键名精确为 `sum, mean, best, mix, best_support, best_top3_support, rrf5, best_support_length`，值是从 BookScore 原料算分数的函数：
- `sum` = `sum(scores)`
- `mean` = `mean`
- `best` = `best`
- `mix` = `0.7*best + 0.3*mean`
- `best_support` = 上面默认公式
- `best_top3_support` = 同默认公式，但 topk 用最好的 `min(3, len(scores))` 个 score 的均值（不受 support 封顶）
- `rrf5` = 本书前 5 段各算 `1/(60+i)`，i 从 1 起
- `best_support_length` = 默认公式 `- 0.02*log1p(chapters)`

`rank(hits, groups, scheme, exclude=(), meta=None, expand=None, total_groups=None)` 返回按该方案降序排好的 BookScore 列表。`BookScore.score` 始终存默认公式的值；`SCHEMES[scheme](b)` 是该方案的分。

CLI：`book_score.py 查询词 -n 10`，或 `--concept 自由`。复用 `qsearch.search`（pool 默认 2000，limit 传 `max(n, 2000)`）与 `qsearch.load_concept` / qsearch 的查询分词口径 `re.split(r"[\s,]+", a.query)`。开关：`--book-score`（默认 `best_support`，可选 SCHEMES 键）、`--json`、`--explain`、`-n`、`--pool`、`--min-chars`、`--db`、`--libdb`。`--explain` 每本书打一行分项：名次、书、chapters、best、topk、support、coverage、groups、has_prefix、has_queries、score，再打最佳段路径:行。无命中时打印空列表并以 0 退出。`--json` 输出全部字段的列表。

## test_book_score.py 规格

纯标准库脚本，不用 pytest。默认模式跑六个单元用例，每条打印 `PASS <name>`，失败打印 `FAIL <name>: <why>` 并以退出码 1 结束；全过时最后一行 `PASS 6 cases`。用例：

1. 单章书：chapters=1，一段 score=1.0，其余段 0.5（低于 0.75）→ support=1、topk=1.0、chapters=1。
2. 长书单强章：chapters=1000，一段 1.0 + 若干 0.1 → support=1，best=1.0，在 coverage/chapters 相同时默认分与第 1 例相同（长度项不动默认分）。
3. 长书多强章：chapters=1000 与 2000 两份相同 hits（10 段 1.0）→ support 都是 5，topk=1.0，两份分数相同，不随章数线性涨。
4. 无命中：hits=[] → 返回 []。
5. 并列：两本书同分 → 按 book 路径、再 best_path、再 line 排序，连跑两次逐项相同。
6. 缺少 derived：`tempfile` 造一个假 ROOT，`库/文学/x/md/` 下放两个 md 文件，meta 里没有这本书 → chapters=2。

构造 hits 用与 `qsearch.search` 同形的 dict。前五例不连真库，第六例用临时目录。

`--perf` 模式：从 `目录/概念表.tsv` 顺序取前 60 个键，逐题交错跑两条端到端路径，顺序按题号奇偶交替：
- 基线 = `qsearch.search(pool=2000, limit=max(20,2000))` + `qsearch.rollup_by_book(hits, con, 20, "mix")`
- 本轮 = 同一次搜索 + `book_score.rank(..., "best_support")`

分别记每题毫秒，打印两边 p50、p95，再打一行规则判定：本轮 p95 <= 基线 p95 + 100 且 本轮 p95 <= 500 才算 PASS，否则 FAIL 并以退出码 1 结束。另加一项「2000 段聚合」：取一道题 2000 条 hits，两个聚合函数各跑 10 次取中位数，打印两个数。
