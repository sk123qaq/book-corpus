# Book query plan

## 何时用

- 用户问「为什么……」「书里怎么说……」「哪本书讲过……」。
- 用户用的是大白话，原文里大概率没有这些词。
- 需要先找到书和章，再回原文取逐字引文。

不用于：已知书名/作者的精确查书（用 `lq.py`）；只要一段已知原文（用 `grep -nF`）。

## 核心规则

**只写两类词。** `literal` 是问题里有区分度的原词。`concepts` 是 `目录/概念表.tsv`
里的概念键。不要写自由发挥的「学术词」组。实测自由发挥的 bridge 组把 recall 从
0.350 拉到 0.067，无原词档从 0.300 拉到 0.050。

**概念必须来自表。** 不让模型自由发明概念。不给概念表时，无原词档从 0.300 掉到
0.000。表是检索的锚，不是装饰。

**先看书写计划，再看书目选章。** 计划只负责把候选书捞出来。真正的定位靠书的
`md/README.md` 章节目录。第一轮 top10 里没有像样的书时，停下来问用户要一个书名、
作者或年代提示，不要继续瞎猜。

## 计划格式

```json
{
  "question": "为什么打工的人觉得自己随时可以被换掉",
  "literal": ["打工的人", "随时", "被换掉"],
  "concepts": ["铁笼", "异化", "工具理性"],
  "groups": [
    {"name": "literal", "terms": ["打工的人", "随时", "被换掉"], "weight": 1.0}
  ],
  "concept_weight": 1.2,
  "book_hint": "",
  "exclude": []
}
```

- `literal` 2 到 4 个，每个不超过 12 字。不要放「人」「事」「为什么」这类泛词。
- `concepts` 1 到 3 个，必须是概念表键。选不出就空着。
- `groups` 只放 literal 一组。概念组由 runner 按表展开，不用手写。
- `concept_weight` 用 1.2。实测 literal 1.0 / concept 1.2 比 1.0 / 1.0 的 MRR 高。
- `book_hint` 只在用户点名书名或第二轮选书时填，必须是库里的目录路径或唯一书名。
- `exclude` 放已知的歧义专名，例如「铁笼山」。

## 怎么选概念

问自己一句：**如果这本书有一章回答这个问题，章名最可能用哪个概念？**

- 先读 `目录/概念表.tsv` 的 `key`、`aliases`、`note` 三列。
- 优先选 note 与问题机制对得上的键。不要选只沾一个字的键。
- 1 到 3 个就够。多选会把噪声带进来。
- 例：
  - 「打工的人随时被换掉」→ 铁笼、异化、工具理性。
  - 「官僚制把人变成机器零件」→ 铁笼、科层制、异化。
  - 「陌生人为什么听同一个指挥」→ 虚构故事、想象的共同体。
  - 「人怎么会变成只会执行的机器」→ 独立判断、工具理性。

## 流程

1. 写计划，存 `/tmp/query-plan.json`。
2. 跑：

   ```bash
   python3 工作区/脚本/qsearch_plan.py --plan /tmp/query-plan.json -n 20
   ```

3. 看 top10 的**书名和章名**，不只看段落。
   - 有像样的书：用 `lq.py` 拿 `md` 路径，读 `md/README.md`，按章名挑 1 到 3 章。
   - 没有像样的书：问用户要书名、作者或年代提示。不要编。
4. 在选中的书/章里再搜一次：

   ```bash
   grep -nF "关键词" "库/<书>/md/"*.md
   # 或把 book_hint 设成书的目录，再跑一次 qsearch_plan.py
   ```

5. 读到答案后，用 `grep -nF` 把引文逐字回查，返回 `路径:行号` 和原文。
6. 最多两轮检索加一次读章。第二轮仍没有像样的书，停下来问。

## 书内定位

第一轮计划只保证「书对了」，不保证「章对了」。读到书名后，先看目录：

```bash
sed -n '1,120p' "库/<书>/md/README.md"
```

章名里出现问题里的核心词，或出现你选的概念键，就优先读那一章。例：

- 问「人怎么会变成只会执行的机器」，候选书《刘擎西方现代思想讲义》的目录里有
  「思考的含义：独立判断」，直接读 `072_思考的含义：独立判断.md`。
- 问「陌生人为什么听同一个指挥」，候选书《人类简史》的目录里有
  「由想象所建构的秩序」，直接读 `025_由想象所建构的秩序.md`。

## 反模式

- 不要写 4 条完整问句再融合。实测 K 档与基线逐位相同，因为基底权重把扩展压死。
- 不要写自由发挥的学术词组。实测 bridge 组 0.067/0.100，比只跑原词还差。
- 不要把概念表外的词硬塞进 `concepts`。runner 会跳过，计划等于少一条腿。
- 不要把 `expand/` 里的前缀或伪查询当原文引文。引文一律回 `库/…/章.md`。
- 不要在 top10 没有像样的书时继续换词硬搜。停下来问提示，比编一个答案便宜。

## 已验证的读数

60 题 gold，计划由 opencode 只读问题生成，不给 gold 的 terms 与 concept：

| 做法 | recall@10 | recall@20 | MRR | 无原词 top20 | 原词 r@10 |
|---|---|---|---|---|---|
| 只跑 literal | 0.283 | 0.333 | 0.134 | 0.000 | 0.800 |
| 只跑 concept | 0.267 | 0.350 | 0.121 | 0.250 | 0.300 |
| literal + concept（本技能） | **0.350** | **0.383** | **0.146** | **0.300** | 0.500 |
| literal + concept + 自由 bridge | 0.200 | 0.317 | 0.126 | 0.200 | 0.250 |
| 无概念表，只跑 literal | 0.283 | 0.333 | 0.131 | 0.000 | 0.800 |
| 无概念表，自由 bridge | 0.067 | 0.100 | 0.017 | 0.050 | 0.000 |

参考：E 段落档 0.267/0.333，L 概念路由 0.333/0.383，M E+L 0.383/0.467。
本技能的无原词档 0.300 与 L 持平，MRR 0.146 高于 L 的 0.120，且计划只读问题生成。

## 失败边界

20 道无原词题里，14 道第一轮失败。只有 2 道的目标书出现在第一轮 top10，其余 12 道
目标书根本没被捞出来。查询侧扩展救不了「书都没出现」的题。这时应该问用户要提示，
或者退回全量伪查询/`rg` 全文，而不是继续换词。

