## 自动分类（scan 默认开）

`scan` 对 `add` 条目用 `pi -p --no-tools` 调 `opencode-go/deepseek-v4.1-flash`，一次 JSON 数组回全部新文件，一级二级按 `classify_books.TAXONOMY` 校验。

- 一级置信 ≥0.45 才写 `subjects`；二级同样过线才写第二级，否则只写一级并标「二级待定」。
- 一级「拿不准」或低于 0.45 时 `subjects` 留空，note 写「低置信 x.xx，需人工确认」，apply 会拒绝直到补上。
- 结果按 sha256 缓存在 `工作区/批次/ingest/classify.json`，重复 scan 不再调模型。
- `--no-classify` 跳过；模型可用 `INGEST_CLASSIFY_MODEL` 覆盖。
- 原来的 TypeSafe 路径在本机被 HTTP 451（区域限制）挡住，已换成这条。

## 拆章失败自动叫 agent

`split_md_batch.py` 在 verify 或 audit 不过时，自动用 `pi -p --approve` 叫一个 agent 修，修完重跑两项检查，过了就落地。

- 每本最多 1 次（`--agent-fix-cap`），整批最多 3 次（`--agent-fix-total`），单次 900 秒（`--agent-fix-timeout`），模型 `--agent-model`，`--no-agent-fix` 关闭。
- agent 只许改批次暂存区与 `overrides/`，不许碰 `库/`、不许改脚本、不许用重复段落或编造文本凑字数。过程写 `logs/<uid>.fix.md`。
- 第一次实战 B0571：诊断出 calibre 定长文档与 NCX 锚点错位，写了 `fixups/span_units.py`，按卷重切 14 篇，audit 75.1% → 100%，697 秒后由驱动自动落地。

## 规则

- **只读先行。** `scan` 不写任何文件；加 `--apply` 才动盘。加锁 `目录/.ingest.lock`，同一时刻只允许一个 ingest。
- **幂等。** 按 sha256 判重，既查库里的所有 source，也查收件箱内部。已在库的文件一律 skip，重复执行 `apply` 不会多出人账行。
- **换源不删旧件。** 新副本排到 `sources` 首位（成为 primary），旧源保留为次源。`md` 仍是旧源产物，DB 的 `derived.source_sha256` 记录的是 manifest 里的源，需重拆才算换完。
- **新书要显式给分类。** `add` 缺 `subjects` 时 apply 直接拒绝并列出条目，不会猜。人账新行的备注写 `ingest:日期；待复核`。
- **写者。** 已有行只由人改；新行由 `ingest.py` 或 `classify_books.py --merge --add-new` 追加。
