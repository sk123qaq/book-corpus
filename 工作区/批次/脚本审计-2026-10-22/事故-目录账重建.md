# 事故：scan_library.py 清空目录/ 六份过程账（2026-10-22 13:41）

## 发生了什么

给 `scan_library.py` 加「扫到 0 个源文件就不写盘」的保护时，第一次 edit 调用里同时改
docstring 和 `main`，两段里有一段没匹配上，整次调用回滚，只落了 docstring。我随后直接
运行脚本验收，旧池目录已不存在，`sources=[]`，脚本照旧无条件写盘，把下面六份 CSV
覆盖成只剩表头：

- `目录/源文件清单.csv`（原 1392 行）
- `目录/书目录清单.csv`（原 1694 行）
- `目录/分类预填.csv`（原 1694 行）
- `目录/重复.csv`（原 6 行）
- `目录/损坏.csv`
- `目录/路径冲突.csv`（原 15 行人工结论）

`目录/分类表.csv`（人账）与 `目录/library.db` 未受影响。快照
`../books.snapshot-2026-10-18` 不含 `目录/`，文件系统是 ext4，没有快照可回滚。

## 恢复

`恢复/重建目录账.py` 以人账与 `library.db` 为源重建，B1359 从冷宫的
`book.json.归档` 补回。结果：

| 文件 | 重建后 |
|---|---|
| 书目录清单.csv | 1694 行（1693 本加 B1359） |
| 源文件清单.csv | 1693 行（对应 DB 的 1693 条 source，比事故前的 1392 行新） |
| 分类预填.csv | 1693 行 |
| 重复.csv | 21 组（按 DB sha256 重算） |
| 损坏.csv | 0 行（当前库无损坏文件） |
| 路径冲突.csv | 0 行 |

## 不可恢复

- `预填依据` 列改为「重建-2026-10-22」，L1 当时的判定理由文本丢了。
- `额外源` JSON、`卷数`、`路径冲突.csv` 的 15 条处置结论（含「加限定词」的原始记录）。
- `重复.csv` 的分组与事故前不同（6 组变 21 组），因为源集合从 1392 涨到 1693。

## 教训

改脚本与验收之间必须先看 diff 是否真的落了。`edit` 多段替换是整体成功或整体失败，
失败后不能假定前一段已生效。保护性分支写完，先用 grep 确认落盘再运行脚本。
