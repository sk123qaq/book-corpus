# 回答阶段设计说明（2026-10-25）

在现有演示页上加两件事。

1. 结果原文带 600 到 800 字前置上下文，命中段整段高亮。
2. 结果区接 `pi` agent 与 `book-corpus-qa` 技能，给出多段依据的回答。

现有代码在 `工作区/演示-检索流程/`。先读 `BRIEF.md` 的五阶段契约，再读本文件。不要改 `工作区/脚本/` 下任何文件，只在演示目录里改。

## 为什么这么接

三体那次失败已经查清：书选对，章选对，最佳段第 1180 行，答案在第 1166 到 1172 行，正好在命中行上方 456 字。所以先修窗口，再让 agent 读多段原文回答。

回答不靠模型记忆，靠项目已有的三样东西。

- `qsearch.search` 取同书前 100 段，按章聚类成 30 章候选地图，带 path、line、text、coverage、score。
- `defpass.score` 在这 100 个候选段上做组覆盖二遍，取前 4 段；只在前 100 候选上跑，不扫全库。
- `book_expand.make_packet` 按行号取有界窗口，长章不整篇读。`window_for` 会带最近标题，`max_chars` 封顶。
- `book_readme.readme_toc` 把 path 映射成 README 里的章名。
- 只读 `book_grep` 扩展 + 内置 `read`，让 agent 在候选不够时继续搜同义说法、读命中章；没有 bash/edit/write。

检索层给候选地图与窗口，agent 做归纳、补搜与引文组织。首跑 11 到 50 秒，引文可回查，长章只加载窗口。

## 数据形状

`trace.py` 的 `read_chapter` 增加前置上下文。返回：

```json
{
  "ok": true,
  "path": "库/.../03_第二部....md",
  "title": "第二部威慑纪元12年，“青铜世纪”号",
  "text": "……前置 700 字 + 命中段 + 后置……",
  "hit_start": 701,
  "hit_end": 760,
  "hit_line": 1180,
  "hit_text": "这支舰队应该是五年前派出的……",
  "before": 700,
  "total_lines": 2220,
  "window_chars": 1600
}
```

`hit_start`、`hit_end` 是 `text` 里的字符偏移，必须满足 `text[hit_start:hit_end] == hit_text`。前置按字符数从命中行往上吃整行，吃到 600 到 800 字为止；后置照旧到 900 字左右。YAML 前置块跳过（前置窗口也不能回退到 YAML），命中行本身不能跳。

`answer.py` 新增 `Answer` 形状。

```json
{
  "ok": true,
  "cached": false,
  "ms": 14135,
  "model": "opencode-go/deepseek-v4.1-flash",
  "answer": "……",
  "lead": "",
  "sections": [],
  "dissent": "",
  "gap": "",
  "citations": [
    {"path": "库/.../03_第二部....md", "line": 1172, "quote": "你的威慑度在百分之十上下波动", "chapter": "第二部……", "verified": true}
  ],
  "passages": [
    {"path": "库/.../03_第二部....md", "start": 1141, "end": 1205, "chars": 3000, "title": "第二部……"}
  ],
  "confidence": "high",
  "not_found": false,
  "error": "",
  "mode": "single",
  "sources": []
}
```

`citations` 只放回查通过的引文。行号以文件实际行号为准，不信模型报的行号。

多书回答把结构放在 `lead`、`sections`、`dissent`、`gap` 四个字段里。`sections` 每项是 `{heading, body}`，最多 4 节，空的整节丢掉。`answer` 由服务端把四段拼成纯文本，缓存、日志与验收脚本继续读它。单书这四项为空。

`mode` 只有 `single` 与 `multi`。单书 `sources` 为空；多书时 `mode="multi"`，`sources` 是书单，
每条多一个 `citations`（这本书回查通过几条），每条 citation 多带 `book` 与 `book_title`。
旧缓存里的 Answer 没有这两个字段，前端按 `single` 处理，服务端读缓存时也补上默认值。

## 服务端

### read_chapter

`trace.py` 的 `read_chapter(path, line=1, chars=900, before=700)`。

- 从 `line` 往上收整行，直到再加一行就超过 `before`。
- 命中段是 `line` 这一行整行。行可能很长，`hit_text` 直接取整行。
- 后置从 `line` 下一行开始，收到 `chars`。
- 返回偏移。前端据此把命中段包成块。

### /api/answer

请求：

```json
{"question": "...", "book": "文学/类型小说/刘慈欣/三体/死神永生",
 "path": "库/.../03_第二部....md", "line": 1180,
 "terms": ["程心","执剑人","三体","威慑","黑暗森林","威慑度"],
 "groups": [{"name":"冰封封印","variants":["冰封","冰壁","封印","封魂咒"]}]}
```

步骤。

1. 读 `book_readme.readme_toc(book)`，得到 path 到章名的映射。
2. 用 `lib_fts_cjk.query_expr` 拼表达式，`qsearch.search(con, expr, terms, [], 100, 40, False, 2000)` 取候选段。只留 `hit["book"] == book` 的段。
3. 按章聚类，取每章最好的一段，排出前 30 章候选地图。
4. 组覆盖二遍：在这 100 个同书候选段上，用 `defpass.score` 按 `groups` 打分，取前 4 段（覆盖 ≥ 2 组）。
5. 当前命中 + 组覆盖 + 章聚类 → `book_expand.make_packet(..., level=2, max_chars=3500)`；重叠合并，最多 6 个窗口、合计 14000 字。
6. 组装提示词，带候选章地图、窗口和只读工具，调 `pi`：

```bash
pi -p --no-session --no-context-files \
  --skill /home/shike/.agents/skills/book-corpus-qa/SKILL.md \
  -e 工作区/演示-检索流程/readonly_tools.ts --tools book_grep,read \
  --model opencode-go/deepseek-v4.1-flash --thinking low "<prompt>"
```

超时 240 秒。`BOOK_MD` 指到本书 md 目录（兼容旧只给一个变量的调用），`BOOK_MDS` 是 md 目录的 JSON 数组；
`book_grep` 只在这些目录里搜。提示词见下。

7. 解析第一个 JSON 对象，去掉代码块围栏。`answer` 为空就返回 `not_found=true`。
8. 回查引文。对每条 citation，取 `quote` 去空白后的前 20 字，在对应章文件的每一行里找去空白后的子串。找到就把 `line` 改成实际行号；找不到再试整章全文；仍找不到就丢掉这条，不放进 `citations`。`path` 必须 realpath 在 `库/` 下且 `.md` 结尾。引文通过后 `verified=true`。
9. 至少 2 条通过就 `confidence` 保持模型给的值；0 到 1 条降到 `low`，并在 `error` 里写「引文回查不足」。
10. 缓存到 `缓存/answers/<sha1>.json`，键含 question、book、path、line、terms、groups、`PROMPT_VERSION`。原子写。
11. 返回。

失败路径：`pi` 非 0、超时、JSON 解析失败都返回 `ok:false` 和可读的 `error`。前端照常显示原文。

### 提示词

```text
你是书库问答的回答阶段。用自然、通顺的中文直接回答，2 到 4 句。

问题：{question}
书：{book}
本书 md 目录：{md}

你可以用两个只读工具：
- book_grep(pattern, path?, max?)：在本书 md 目录里搜正则，返回 file:line。
- read：读命中的章节文件。

先看候选章与候选窗口。候选章是按检索分排的前 30 章，窗口是其中最相关的几段。若窗口不够，或要确认「是谁」「结局」「身份」，用 book_grep 搜人物、事件、同义说法，再 read 命中的章。不要写文件。
注意：原文里的「应该」「十有八九」「猜测」是推测，不是结论。涉及「是谁」「结局」，必须找到身份或结果被确认的段落（令牌、名号、旁白、后文），并往后多读一到两章；推测不能写进答案。
回答里不要写「原文写明」「根据原文」，也不要写路径行号；依据放在 citations，quote 必须逐字来自原文。
证据不足才写「书里没有直接回答」。
输出一行 JSON，不要代码块，不要解释：
{"answer":"...","citations":[{"path":"库/...md","line":1166,"quote":"逐字引文"}],"confidence":"high|medium|low","not_found":false}

候选章（前 {n} 章）：
{chapters}

候选窗口：
{evidence}
```

证据块之间空一行，每条带完整 path 与行号范围。候选章最多 30 行。总提示词控制在 26000 字以内。

## 多书回答（全选）

书卡阶段点「全选 N 本」时，第 5 阶段的回答一次盖住所有书，不做事后合并。
每本书各答一遍再拼会有 N+1 次调用，而且「哪句属于哪本书」只能靠模型自述，不可信。

### 请求与数据形状

请求在原来的字段上多一个可选的 `sources`：

```json
{"question": "...", "book": "...", "path": "库/...md", "line": 1180,
 "terms": [], "groups": [],
 "sources": [{"book": "人文社科/教育/...", "title": "...", "path": "库/.../md/02_x.md", "line": 31}]}
```

Source 就是 `{book, title, path, line}`，`book` 由 `path` 推（`库/.../md/` 前面那段），最多 8 本。
服务端只验形状：每项是对象，`path` 非空字符串，`line` 是整数，`title` 可选字符串，否则 400。
`answer.py` 再做入库校验：`path` realpath 在 `库/` 下且 `.md`，推不出书名就丢掉，同 path 去重，保序。

### 步骤与预算

1. 每本书单独调 `pick_passages(..., limit=60)`（单书仍是 100），候选章地图每本取 4 章。
2. 每本选三段：`line > 1` 时命中段优先，否则跳过命中段直接取替代段；不足三段就有几段给几段。
3. 每本书的预算 `quota = clamp(18000 // n, 2200, 3400)`，三扇窗各 `quota // 3`。先把每本的
   第一窗铺完，再铺第二窗、第三窗，所以任何一本书都不会因为预算被挤掉唯一窗口。真正取不到窗口的书
   （没有候选段、或文件读不出来）会被列到提示词末行的「无相关原文窗口的书」里。
4. 一次提示词装下所有书：每本一行书名与 md 目录、每本 4 章候选、按书分组的窗口。上限 30000 字，
   超了从排名最后的书开始删它的最后一窗，从不删一本书的唯一窗口。

### 多书提示词

比单书多四段：要用的书清单、库级覆盖、回答的组织方式、窗口归到书下。组织方式按问题本身的结构走，不按书排。

1. 开头 1 到 3 句给判断，放在第一个小标题之前，不加标题。库里的说法和问题里的说法不一样，
   或者只有一两本书真的讨论这个说法，先说这件事，并点名是哪几本，不写「只有两三本」「一本讲……的著作」。
2. 中间 2 到 4 个 `## 小标题`。标题是判断句，不用书名、不用「首先/其次」、不编号。
   每段 3 到 5 句，按「是什么、为什么、后果」展开，不按来源排。正文默认不出现作者名和书名，
   不写「甲说」「乙认为」「丙指出」。同一个概念有几本书给了不同定义或口径，先合并成一个定义，
   再把口径差异并列写清，不写谁提的。同一件事有几本书说，合并成一句。
3. 前提不一致时用 `## 分歧` 单独一段，写清不一致的是哪一步：先做什么、谁是主体、外部条件算不算。
   分歧按观点写，需要说明哪本书持哪一方时直接写《书名》。`## 缺口` 点名到书，不写「一本文学研究」这种指代。
4. 模型只输出一个 `answer` 字符串，里面用 `##` 分节。服务端按 `##` 拆成 `lead`、`sections`、
   `dissent`、`gap`，外层 JSON 不再嵌数组，长回答不会因为括号写错整段丢掉。
5. 不要写成文献综述。不写「甲把它界定为……；乙把口径放得更宽……；丙则从……入手」。
6. 不写「原文写明」「根据原文」，不写路径行号；每本书至少用 `book_grep` 确认一次机制章。
   citation 只给 `{path, line, quote}`，quote 逐字；尽量引到至少 2 个不同书的原文。

`库级覆盖` 由服务端用 `para_fts` 算。扫问题词表，跳过命中段数超过 200 的太常见词，按词长从长到短
保留最多三个，报全库命中段数、书数与稀疏词的前两本书名，明确写「不是答案证据」。
这一段让模型能说出「库里不是这个用词」。
没有窗口的书列在末行「无相关原文窗口的书」并要求在回答里写明没有相关原文。

### 回查与排序

- citation 的 `path` 必须 realpath 在 `库/` 下，而且推出来的书必须在本次书单里；
  单书的「同名文件兑底」在多书里关掉，不允许一本书的引文落到另一本书上。
- `book`、`book_title` 由服务端从书单推，不信模型。
- 排序：当前选中的那本（sources 第一项）在前，其余按书卡名次；每本内按离该书命中行的距离；
  先每本一条，再第二轮，封顶 8 条（`MAX_CITATIONS_MULTI`）。单书仍是「离命中行距离 + 4 条」。
- 通过 ≥ 2 条但只盖住 1 本书时，`error` 写「引文只覆盖 1 本书」，`confidence` 不降；
  不到 2 条仍按原规则降到 `low` 并写「引文回查不足」。

### 缓存与工具

- 单书用 `PROMPT_VERSION = "answer-v8"`，多书用 `PROMPT_VERSION_MULTI = "answer-v17-multi"`。
  这一轮改了回答形状，v6 与 v7 的旧缓存不再命中，不做数据迁移。
- 多书键含 question、有序书单的 `(book, path, line)`、terms、groups、model。换掉一本书就不再命中。
- `call_pi` 把 `BOOK_MDS`（md 目录 JSON 数组）给出去，`BOOK_MD` 仍是第一个目录。
  `readonly_tools.ts` 给了 `path` 时要求落在一个根内；没给时每个根跑一次 rg，
  每根配额 `max(5, floor(limit / 根数))`，拼起来截 16000 字。不加新工具、不加新参数。

## 前端

结果阶段，从上到下。

1. 回答卡。加载时显示「正在读原文并组织回答」与脉冲点；全选时换成带真实本数的文案和「最长约 2 分钟」。失败显示错误和「重试」；成功时按 `sections` 渲染小节标题与正文，领句、分歧、缺口各一段；没有 `sections` 时按 `answer` 换行分段。
2. 依据列表。单书 2 到 4 条，多书最多 8 条；每条一行章名与行号，下面是引文，最多两行；多书时上方多一行书名。整条可点，点了用 `/api/chapter` 载入那段，刷新下面的原文窗口与高亮。顶部小字「由模型根据原文归纳，引文已回查」。
3. 原文区。命中段整段用浅朱红底加左侧竖线包成块，块内的检索词仍有 `<mark>`。前置 600 到 800 字要能看到，这是这次修复的核心。原文脚注写「本章 2220 行 · 载入 1600 字 · 命中第 1180 行」。
   回答完成后自动把原文窗口切到第一条 verified 依据，并给该依据加 active 高亮；点其它依据仍可切换，回答卡保留。
4. 回答请求在结果阶段变为 active 时发起，带 AbortController 与序号，换卡或返回时取消旧请求。`instant=1` 立即发起。缓存命中直接渲染。
5. 全选：第 4 阶段触发行右侧一个按钮（`已全选 N 本 · 取消` / `全选 N 本`，`aria-pressed`），只在弹卡且 N>1 时出现。
   开着的时候每张卡都显示已选，下面一行小字说明第 5 阶段会用这 N 本书一起回答；第 5 阶段的加载文案带真实本数
   与「最长约 2 分钟」，回答卡小字报「N 本书」与「覆盖 M 本」，依据小字报「覆盖 M 本书」，每条依据上方多一行书名。
   点其它卡、换一本、重播、返回首屏都退出全选。`&all=1` 可复现。

不要用嵌套 `<mark>`。命中块用 `<span class="hit-para">` 加 `display:block`，里面的词高亮仍是 `<mark>`。

## 验收

固定用这一题。

```bash
curl -s -X POST localhost:8765/api/run -H 'content-type: application/json' \
  -d '{"question":"《三体》里为什么程心刚成为执剑人没多久三体就入侵了地球"}'
```

- 结果 path 是 `库/文学/类型小说/刘慈欣/三体/死神永生/md/03_第二部威慑纪元12年，“青铜世纪”号.md`；命中行随当前索引可能是 1000 或 1180，不写死。
- `/api/chapter` 显式用 line 1180 加 `before=700`，`text` 的前置部分必须包含「你的威慑度在百分之十上下波动」，`hit_text` 必须包含「这支舰队应该是五年前派出的」。
- `/api/answer` 的 answer 必须同时出现「威慑度」与「百分之十」，`citations` 至少一条 verified 行号是 1166 或 1172。第一跑约 11 到 50 秒（实测 11 到 49 秒），第二跑缓存小于 1 秒。
- 不弹卡的问题（「乡土中国 差序格局」）也要能回答，至少 2 条引文。
- 凡人题：answer 必须含「长老」或「阴罗宗」，且区分「受伤是黑袍长老下的手，冰封是南宫婉自封」；citations 落到 0783 与 0790/0791。
- 全选：用「内卷和教育」那题的书卡拼 `sources` 再问一次，`mode=multi`、answer 非空、`sections` ≥ 2 节、
  `lead` 非空、以「《」开头的行 ≤ 2 行、verified 引文 ≥ 4 条且盖住 ≥ 3 本书、全部在书单内，
  冷跑 ≤ 90 秒，第二跑缓存小于 1.5 秒。
- 库里没有的问题要 `not_found=true` 或 answer 含「未找到原文依据」，不能崩。
- `验收/check_demo.py` 增加上面几条，末行 `ALL PASS`。
- 截图：三体题的回答卡与依据、原文命中块，桌面 1440×900；手机 390×844。控制台 0 报错。
