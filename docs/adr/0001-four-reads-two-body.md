# 四读共用一份逐字正文，只有速览编译

状态：proposed · 2026-11-08

## 背景

四读现在按块覆盖率分档：`skim / standard / deep / research` 各自投影同一批块，覆盖带写在 `src/bookcorpus/reading/tiers.py:11-53`，投影在 `tiers.py:459`。`src/bookcorpus/reading/render.py:398` 只渲染投影内的块，没被选中的块直接消失。结果是四档只是同一篇原文的四种长度，不是四种信息深度。标准档的覆盖带是 60–75%，与“标准档基本不变”的要求冲突。

## 决策

- 只有速览使用编译正文；标准、深读、研究共用同一份 100% 逐字正文。
- 档位差异由注解、图表、研究档案的密度承担，不再由块投影承担。
- 新增 `chapter_model.json`：把章拆成信息单元，记录 core/hard、引文锚点、关系、章节归属。
- 处置由纯函数按档位计算：`verbatim / condensed / indexed / omitted`。硬信息在任何档位都必须是 `verbatim` 或 `condensed`；`omitted` 只允许重复表达。
- 研究档检索采用“提示词定标准、模型提请求、代码裁决并执行、verifier 打标”，模型不直接决定搜不搜。

## 后果

- 标准/深读/研究共享正文和块锚点，切换档位不重载正文；“标准不变”成为结构保证。
- 需要新的信息守恒账和 G10–G14 门禁；旧的字符覆盖率降为诊断指标。
- 模型调用从“一次标注”变成“一次结构模型 + 按需分层”，但每层独立缓存，重跑一档只付该层的钱。
- 旧 `tiers.project` 保留为无模型 fallback；新路径通过 feature flag 启用，旧包不受影响。
- 深度产物放在包内 `depth/`，`Store.save()` 在旧路径模式原样复制已有 `depth/`，在深度路径模式整体替换 `depth/`；不把深度文件平铺到包根。
- `chapter()` 用 `depth/state.json` 的哈希判断 `missing/stale/ready`；`annotation.json` 缺失只表示旧路径草稿，不把深度包误判成草稿。flag 关闭时返回的键与现在完全一致。
- 速览页需要“未展开细节”索引和“看原文”跳转，否则压缩不可见。
- 图表从“每种图一个渲染函数”改为七类语法；数字必须可追溯，否则降级。
- 视觉读本 `edition` 继续独立，不并入四读。

## 备选方案

- **继续调覆盖率**：拒绝。覆盖率测长度，不测完整度；调到 95% 只是让标准档接近全文，速览仍可能漏前提。
- **四档都写编译正文**：拒绝。标准档要求逐字基准；四套正文会让成本、门禁、锚点全部翻倍。
- **让模型直接写四档 HTML**：拒绝。`agent_standard.py` 的 `validate_fragment` 只能查原文是否出现，查不了该出现的命题是否出现。
- **让模型自行决定是否联网**：拒绝。模型无法可靠判断自己不知道什么；网络、费用、来源白名单是系统决策。改为模型提交核验请求，代码裁决。
