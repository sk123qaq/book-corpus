# 分层读：三档阅读与书型读法方案

状态：accepted · 2026-11-11（阶段 1、2a、2b 已落地）
取代：`docs/design/四读信息深度-方案-2026-11-08.md` 中 research 档的部分；`docs/adr/0001-four-reads-two-body.md` 的“标准/深读共用逐字正文”由 ADR 0002 承接，0001 不再作为活决策。
不包含：视觉读本（独立第五产物，不并入本方案）。

## Problem Statement

现在的阅读页有四个档位，但第四个“研究档”没有回答一个独立的阅读问题。它按固定配额产出 5–10 行判断矩阵、3–10 条笔记、3–6 个问题，对一章 1,900 字的正文可以写出 2,300 字的元文本，并且渲染在正文之前。它的内容不是外部研究，而是编辑部的核查清单；在小说上甚至退化成“S01-U01 与 S10-U01 应视为首尾回指”这类文本内部校对。它既不能回答“今天还成立吗”，也不构成第四种读法。

citations 层与 research 绑定：research 的矩阵行被拿去生成查询。B0042/07 的 5 条查询全部因 Firecrawl `HTTP 402 insufficient_credits` 失败，`searched:true` 仍然被写入，8 条 claim 里 5 条落 `not_found`、3 条 `not_searched`，页面却显示“已检索”。这是“额度失败被记成已查”，不是“从未查过却标已查”；B0017/03 是 `searched:false`、provider none、徽标“未检索”，本来是对的。

书型差异也没有被建模。书库 1,955 本书里 1,417 本是文学（72.5%），但读本结构是论证本位的：标准/深读共用逐字正文，深读注的类型是 assumption/boundary/evidence/counter/intertext；标准档本该写节导语和背景注，实测两本样本都是 0 节导语、0 条标准注。读者打开一本小说、一本方法书和一本图册，看到的是同一套论证脚手架。

## Solution

把“四读”改成“分层读”，口号“按需求读”。读者只看到三个档位：

1. **速览**：编译正文，5–8 分钟；论证书给命题链，叙事书给场景节拍。
2. **标准**：逐字正文 + 节导语、术语、必要背景注。
3. **深读**：逐字正文 + 按读法模式变化的注解、引文、面板、章末问题。

“研究档”从 reader、生成链、工单、测试和文档中退役；citations 一起退役，reader 不再出现来源面板。外部核验如果以后要做，是独立产物，不是第四个档位；本轮不做，但不写成永久否决。

书型差异放在**读法模式（mode）**里，不放在档位里。一本书一个默认模式，一章可以覆写；**模式不携带默认档位**。档位由读者按当次精力和兴趣选择，不写进模式账。

| 模式 | UI 名 | 深读注解类型 | 默认面板 |
|---|---|---|---|
| narrative | 叙事 | scene / character / motif / turn / setup_payoff | 时间线、人物/称谓、场景节拍、意象/母题 |
| argument | 论证 | assumption / boundary / evidence / counter / intertext | 论证图、关键定义、证据表、反例/边界、适用范围 |
| practical | 实用 | step / check / failure / decision / example | 步骤、清单、决策树、失败模式、例子 |
| reference | 资料·图册 | plate / term / version / caption / provenance | 图版、术语、版本/谱系、图注索引 |

模式只改注解类型和面板；不改正文覆盖率、块 ID、锚点，也不新增第四档。没有足够结构数据时显示“本章没有足够的结构信息”，不编内容。图册/单文件书可以只有书级模式，不设章级覆写。

分三阶段落地：

- **阶段 1（删档）**：research + citations 从 reader 和生成链退役；三档跑稳；只删 legacy 的 research 导出，保留 legacy skim/standard/deep；depth 的 research/citations 与 legacy research.html 先 tar 再删；standard 层保持现状并如实标注。
- **阶段 2a（读法账）**：人账 `读法` 表、派生的 `books/<uid>/reading.json`、自动建议、工单里的四模式选择器；先不改面板和注解。
- **阶段 2b（书型内容）**：一次面板抽取、模式化深读注解、叙事速览、standard 节导语修复、四本书验收。

## User Stories

### 读者

1. 作为读者，我只看到速览、标准、深读三个档位，不再在一个不回答阅读问题的“研究档”上做选择。
2. 作为读者，我按当次精力和兴趣选档位；没有哪一种书型替我预设“应该读多深”。
3. 作为读者，我打开章节时正文先出现，不再先读 2,000 多字的判断矩阵。
4. 作为读者，我在深读页尾最多看到 3 个“这一章没有回答的问题”，而不是 3–10 条编辑核查笔记。
5. 作为读者，我在任何档位都看不到“已检索”徽标，除非真的有一份可核对的外部来源；本轮没有来源面板。
6. 作为读者，我看不到“未找到来源”标在检索失败的判断上；失败就是失败，不是查无结果。
7. 作为读者，产品名和导航写“分层读 / 按需求读”，不再暗示有四个档位。
8. 作为小说读者，我看到时间线、人物/称谓、场景节拍、意象/母题，而不是论证矩阵；速览也是场景速览，不是硬造的命题链。
9. 作为论证书读者，我看到论证图、定义、证据表、反例和适用范围。
10. 作为实用书读者，我看到步骤、清单、决策树和失败模式。
11. 作为图册/资料书读者，我看到图版、术语、版本/谱系和图注，不被硬套成论证。
12. 作为读者，本书默认读法跟随整本书，但某一章可以覆写，不会因为一个特殊章节改掉整本。
13. 作为读者，我能看到系统为什么建议某个读法（例如“5 个主张 / 3 个条件 / 1 个反例”），而不是只看到一个标签。
14. 作为读者，旧 `?tier=research` 链接会落到深读，并看到一行“研究档已退役”，而不是 404 或空白页。
15. 作为操作员，我在读本工单里改过的本章读法会持久化，重新生成不会丢。
16. 作为读者，我恢复“跟随本书”后，本章覆写被清除，读法回到书级默认。
17. 作为操作员，我在窄屏上仍能看清四个模式按钮和当前选择，不需要横向滚动。

### 操作员/编辑

18. 作为操作员，我在读本工单里看到“本书默认”“系统建议”“本章覆写”三个状态，不会把建议当成已生效。
19. 作为操作员，我用四个按钮选本章读法；选择与本书默认相同的模式时，状态回到“跟随本书”，不产生无意义的覆写。
20. 作为操作员，我在没有读法账的新书上先确认一次本书默认读法，之后每章默认跟随，不再重复确认。
21. 作为操作员，我可以把当前选择“设为本书默认”，也可以只对本章覆写。
22. 作为操作员，我在书页工单只看到本书读法的只读摘要和入口，不会在书页和章页维护两份选择器。
23. 作为操作员，我看到的建议来自确定性规则；只有规则低置信度或冲突时才调用模型，结果有缓存和依据。
24. 作为操作员，我确认后的读法写入 `tables/ledger.db` 的 `读法` 表；`books/<uid>/reading.json` 由 `build_library.py --emit-json` 派生，我不手改它。
25. 作为操作员，我在阶段 1 只需处理删档，不需要同时理解书型 schema。
26. 作为操作员，我在阶段 2 用 B0017/03、B0042/07、B1848、B0641 四本书验收四类模式。
27. 作为操作员，我在工单里默认一次生成三档；若某档没生成，读者页把它标成“未生成”，不伪装成可选。

### 维护者

28. 作为维护者，我希望 `TIER_ORDER`、深度层注册、reader tab、工单、测试和文档对“三档”只有一个事实来源。
29. 作为维护者，我希望 research/citations 的删除是可回滚的：tar + manifest 先落 `工作区/归档/`，再删文件；legacy 的 skim/standard/deep 不在删除范围。
30. 作为维护者，我希望旧 `?tier=research` 有明确的重定向，不留下半读的页面；legacy 的 research 导出返回 410，不冒充深读。
31. 作为维护者，我希望 `reading.json` 是 ledger 的纯派生投影，章级覆写、书级默认、建议、兜底四种来源可单测。
32. 作为维护者，我希望面板测试断言“有什么、没有什么”，而不是断言某段模型文案。
33. 作为维护者，我希望 standard 的 0 节导语/0 标准注在阶段 1 被记录为已知状态，阶段 2 用确定性回退修复，不再回归。
34. 作为维护者，我希望 ADR 0002 明确记录“research 退役、三档、书型模式”，GLOSSARY 不再把四读定义为四档。

## Implementation Decisions

### 1. 术语与边界

- **分层读**：产品名。**三档**：速览、标准、深读。**读法模式**：叙事、论证、实用、资料·图册。**本书默认模式**：整本书的默认读法。**本章覆写**：某章偏离本书默认的读法。**档位**：读者当次读多深，和模式正交。
- 中文写“读法模式”或“模式”，不要单写“读法”；“本章读法”只作为 UI 短标签，定义上必须落到“模式”。
- 代码标识、路由、数据库字段继续用 `reading` / `tiers`；只改用户可见文案、导航、文档和页面标题。不改包名、路由前缀、`分类` 表名。
- “研究档”这个词从 reader、工单、导航、测试名和用户文档中消失。内部历史文档可以保留“research 已退役”的说明，但不能继续把 research 定义为档位。
- **模式不携带默认档位**：`reading.json` 没有 `default_tier`；模式表没有“默认入口”列；档位选择只存在于工单生成项和 reader 的档位 tab。

### 2. 三档与层注册

- `TIER_ORDER = ("skim", "standard", "deep")`；`TIER_SPECS` 只保留三项；`OPTIONAL_CLAIM_TIER` 去掉 research。legacy skim/standard/deep 保留原有投影参数，research 项删除。
- `standard` 和 `deep` 仍是 100% 逐字正文；只有 `skim` 编译正文。沿用 ADR 0001 的“共用一份逐字正文，只有速览编译”，由 ADR 0002 承接。
- 阶段 1 深度层注册：`("model", "skim", "standard", "deep")`；阶段 2b 增加 `"panels"`，顺序为 `("model", "panels", "skim", "standard", "deep")`。`citations` 不再是深度层。
- `depth/state.json` 的 ready 判定只看当前阶段的层；缺失 research/citations 不算 stale；阶段 2b 缺 panels 判 stale。
- `disposition` 只保留 `skim` 的 condensed/omitted 规则；`standard` / `deep` 继续 verbatim。
- reader tab、工单 tier 列表、`app.js` 的 tier/depth 名称、`book.html`/`records.html` 的状态列全部改为三档；旧 `research` 键不再出现在 API 响应里。
- 档位生成：工单默认勾选三档；`POST .../generate` 接受 `tiers` 数组，默认 `["skim","standard","deep"]`。如果只生成了部分档，reader 只显示已生成档，其余标“未生成”，不显示空正文。
- `skim.reason` 的语义在阶段 2b 修正：`supported=true` 时 `reason` 必须为空；`supported=false` 才写原因。阶段 1 不改，只在文档里标注。

### 3. 读法账：ledger 表 + 派生 `reading.json`

人账新增 `tables/ledger.db` 表 `读法`。它是唯一写入口；`books/<uid>/reading.json` 是 `build_library.py --emit-json` 生成的派生投影，和 `book.json` 一样可追踪、可重建，但不手改。

```sql
CREATE TABLE 读法 (
  uid TEXT NOT NULL,
  chapter TEXT NOT NULL DEFAULT '*',
  mode TEXT NOT NULL CHECK (mode IN ('narrative','argument','practical','reference')),
  panels TEXT NOT NULL DEFAULT '[]',
  source_sha256 TEXT NOT NULL DEFAULT '',
  updated_at TEXT NOT NULL,
  PRIMARY KEY (uid, chapter)
);
```

- `chapter='*'` 是本书默认模式；`chapter='07'` 是章级覆写。章级行必须有对应的书级行，否则拒绝写入。
- `panels` 是 JSON 数组；空数组表示用模式默认面板。
- `source_sha256` 只对章级行有意义；书级行为空。章节源变化时，覆写视为待确认，不静默沿用。
- 写入走 `lib_common` 的新读写函数（例如 `reading_put` / `reading_get`），受 `.writer.lock` 保护；操作台/工单只写 ledger，不直接写 `reading.json`。
- `build_library.py --emit-json` 读 `读法` 表，写每本书的 `reading.json`；没有书级行的书不生成文件；删行时删除对应派生文件。

派生文件：

```json
{
  "version": 1,
  "generated": true,
  "mode": "argument",
  "panels": [],
  "chapters": {
    "07": {
      "mode": "narrative",
      "panels": [],
      "source_sha256": "<chapter md hash>"
    }
  },
  "updated_at": "2026-11-11T12:00:00+08:00"
}
```

- 没有 `default_tier`，没有 `mode_source`；文件头 `generated: true` 表示不可手改。
- `mode`：`narrative | argument | practical | reference`。
- `panels`：可选；省略时用模式默认面板；`[]` 表示不要面板。
- `chapters`：键是章号字符串（`"07"`），只允许覆写 `mode` 和可选 `panels`；不允许覆写档位。
- 解析顺序：章级覆写（hash 有效）> 书级默认 > 建议 > 分类兜底。解析结果带 `effective_source`：`chapter | book | suggestion | fallback`。
- 分类兜底：文学→叙事；艺术与图像/游戏/影视动画漫画→资料·图册；商业与管理/生活与实用→实用；人文社科/科学技术/建筑与古迹/写作与编剧→论证；其他/拿不准→论证，但标低置信度。
- 没有书级行时 reader 仍可读：使用建议或分类兜底，但工单显示“本书尚未设定读法”；生成前必须由操作员确认一次本书默认，写 ledger 后再生成。

### 4. 建议引擎

- 输入全部是实际可得的数据：
  - ledger `分类` 的 `一级`/`二级`（不是 `subject1/subject2`；后者只在 `build/library.db:book`，作为可选补充）；
  - `mdparse` 的块统计：paragraph/heading/quote/list/table/image/code/footnote 数量；
  - 对话比例：用段落中成对引号（`“”` 或 `「」`）的比例近似，不新增块类型；
  - 图数：md 中的图片标记数；
  - 术语数 / unit 类型计数：只在已有 `chapter_model` 时使用，否则记 0/unknown，不阻塞建议。
- 规则给四种模式打分，输出 `mode`、`confidence`（top1 与 top2 的归一化差）、`evidence`（例如“5 个主张 / 3 个条件 / 1 个反例”）。
- 规则高置信度（top1 ≥ 0.55 且 margin ≥ 0.20）直接用规则；低置信度或 top2 接近时调用一次模型分类器。模型只看结构摘要和首尾各 2 个块，不看全文；返回 `{mode, confidence, evidence}`，不写散文。
- 建议缓存：`build/reading/suggestions/<uid>/<chapter>.json`，键含章节源 hash、prompt version、模型 id；派生、可重建、可删。
- 建议永不自动写 ledger。模型失败时退回规则 top1，`source=rule_fallback`，UI 标“建议待确认”。
- 建议只决定“建议”，不决定生成；生成只用 ledger 的有效模式。

### 5. 工单选择器（B 方案）

- 位置：章页读本工单的“本章读法”块。书页工单只显示“本书读法：论证（人工）”+ 去章页的链接，不放第二个选择器。reader 章头显示一枚只读徽标（`本书读法 · 论证` / `本章覆写 · 叙事`），解释为什么面板不同；reader 不提供编辑控件。
- 布局：全宽“跟随本书（论证）”开关；2×2 四模式按钮；建议模式带“建议”徽标；理由行 `模型建议：论证 · 置信度 0.82`；依据行 `5 个主张 / 3 个条件 / 1 个反例`；覆写行 `本章覆写：叙事（不跟随本书）` + `恢复跟随本书`；主按钮 `按「叙事」生成读本 →` 或 `按本书默认（论证）生成读本 →`。
- **档位不在这个选择器里**。选择器下面是“生成档位”三个复选项，默认全选；它只决定这次生成哪些档，不决定阅读时看哪档。reader 的档位 tab 仍由读者点。
- 状态模型：`{follow: boolean, mode: Mode}`。
  - `follow=true`：有效模式 = 本书默认；没有本书默认时 = 建议；再没有 = 分类兜底。
  - `follow=false`：有效模式 = 选中的 `mode`。
  - 选择与本书默认相同的模式时，`follow` 回到 true，不写覆写。
  - 没有书级行时，显示“本书尚未设定读法”，主按钮 `按「建议」生成读本`；首次确认写书级默认行再生成。
  - `设为本书默认` 是次级动作：改书级默认；已有章级覆写保留，但等于新默认的覆写会被清理。
- 生成：主按钮把 `{follow, mode}` 解析成有效模式，写入 job payload（`mode`, `mode_hash`, `profile_hash`, `tiers`）；job 一旦入队，后续改 profile 不影响这次生成。
- API：`GET /api/chapter/<uid>/<n>` 增加 `reading` 对象（book_mode、chapter_override、effective_mode、effective_source、panels、suggestion）；`PUT /api/chapter/<uid>/<n>/reading` 用 `action=follow|override|book_default` + `mode` 写书级默认、章级覆写或清除覆写；`POST .../generate` 收 `tiers`，服务端解析有效模式；没有书级行且未确认本书默认时返回 409，不隐式写 profile。
- 窄屏：四个按钮保持 2×2；“跟随本书”占满一行；覆写行换行不截断。

### 6. 模式化深读注解

- `deep.py` 的 `NOTE_TYPES` 从固定五类改为 `NOTE_TYPES_BY_MODE`：

| 模式 | 注解类型 | UI 标签 |
|---|---|---|
| argument | assumption / boundary / evidence / counter / intertext | 假设 / 边界 / 证据 / 反例 / 互文 |
| narrative | scene / character / motif / turn / setup_payoff | 场景 / 人物 / 母题 / 转折 / 埋伏与回收 |
| practical | step / check / failure / decision / example | 步骤 / 检查 / 失败 / 决策 / 例证 |
| reference | plate / term / version / caption / provenance | 图版 / 术语 / 版本 / 图注 / 来源 |

- `deep.json` 增加 `mode`；校验类型必须属于该模式的集合；`quote` 仍是逐字子串，`source_scope` 仍是“本章”或“本书 <节或章>”。
- `deep` prompt version 升到 `deep-annotations-v2`。B0042/07 是 argument，旧 deep 注解类型兼容；迁移时给旧 `deep.json` 补写 `mode: argument` 后复用。B0017/03 是 narrative，旧 deep 的 assumption/boundary/... 不兼容，阶段 2b 重跑。B1848/B0641 首次生成。
- 渲染器按模式读标签；未知类型不回退成“假设”，直接报校验错。
- 改类型会改变 `deep.json` 的 `layer_sha`；旧包标 stale，不静默混用。

### 7. 面板：一次抽取，不按面板拆调用

- 阶段 2b 新增 `panels` 层，文件 `depth/panels.json`。它由**每个章一次**面板抽取调用生成（不是每个面板一次），和 `chapter_model` 在同一个 job 里执行；深读注仍是独立调用。
- `panels.json` 结构：

```json
{
  "schema": 1,
  "prompt_version": "reading-panels-v1",
  "mode": "narrative",
  "source_sha256": "<chapter md hash>",
  "panels": [
    {
      "id": "P01",
      "kind": "timeline",
      "title": "时间线",
      "summary": "……",
      "items": [
        {"text": "……", "units": ["U03"], "blocks": ["B21"], "source": "本章"}
      ]
    }
  ],
  "warnings": []
}
```

- 面板类型按模式限定：narrative `timeline/characters/scene_beats/motifs`；argument `argument_map/definitions/evidence_table/counterexamples/scope`；practical `steps/checklist/decision_tree/failure_modes/examples`；reference `plates/terms/versions/captions`。
- 每条 item 必须带块锚点；人名、地名、年份、数字、图注必须在源文/图注中逐字可查，不能编。没有数据的 panel 不写空数组；整章没有可用结构时写 `panels: []`，渲染“本章没有足够的结构信息”。
- 面板渲染在正文之后；速览只显示每个面板的 3 条摘要，标准/深读显示完整面板。
- 模式变化时 `panels` 与 `deep` 一起 stale；重新生成只重跑受影响的层。
- 面板提取的验证：锚点存在、类型合法、quote 逐字、无外部事实、无空话；失败重试一次，仍失败则 `panels: []` + warning，不阻塞正文。

### 8. 深读页尾的“没有回答的问题”

阶段 2b 在深读层增加可选的 `open_questions`，最多 3 条；每条 `{text, why, where, anchor}`。它回答“这一章提出了但没有回答什么”，不写判断、不写矩阵、不写查询、不写“今天还成立吗”。0 条合法；不设最低配额。由深读生成器在同一调用里产出，或由 chapter_model 的未答问题派生；校验锚点存在，不引入外部事实。它属于深读内容，不是新档位。

阶段 1 删除 `research.json` 前，把每本最多 3 条旧 questions 复制进 `deep.json` 的 `open_questions`（加字段，不调用模型）；阶段 2b 只负责渲染和校验。旧 research 的 matrix/notes 不迁移。

### 9. Standard 层修复（阶段 2b）

- **根因**：`model.py` 的 prompt 没有 `sections[].lead`，`schema.py` 允许空；`standard.py` 的 `_notes` 只读 `standard_notes`/`notes`，而 chapter_model 的必填顶层字段没有这两个键。0 lead / 0 notes 是 schema/接线缺口，不是模型偷懒。
- **修法**：不升 chapter_model、不重跑两本。standard 的 lead 优先用 `chapter_model.sections[].lead`；为空时确定性回退到该节第一个 core unit 的首句（没有 core unit 就用第一个 unit），截断 80 字，不改写。`standard_notes` 只从 `standard_notes`/`notes` 读；没有来源就 0 条，不编背景。
- 验收：B0017/03 和 B0042/07 的标准档每节至少 1 条 lead；有源注的节显示标准注；没有源注的节保持 0 条。允许 notes 为 0，不再要求“每节都有背景注”。

### 10. 叙事速览（阶段 2b）

- `skim.json` 增加 `kind: "claims" | "scenes"`，以及 `scenes` 数组；论证模式仍用 `kind="claims"`、`sections`、`detail_index`。
- 叙事速览按场景节拍编译：5–10 个 scene，每个 `{text, units, anchor, turn}`；每个 scene 至少锚定一个块；正文汉字数不超过源文 25%，**不设 15% 下限**，不要求命题链。
- `supported=true` 条件：源文 ≥ 1200 汉字且至少 3 个有效 scene；否则 `supported=false`，`reason` 写人话，`scenes` 空。
- `skim` prompt version 升到 `skim-compiler-v2`；叙事模式优先用 `panels.scene_beats`，没有面板时从块结构确定性分段；不为了凑数造节拍。
- 渲染：档位仍叫“速览”，叙事模式副标题“场景速览”；无 scene 时显示“这一章不适合场景速览”，不显示空列表。

## Further Notes

### 风险与缓解

- **模式误判**：混合书（半叙事半论证）用规则+模型仍可能错。缓解：建议只做建议，人确认；章级覆写；置信度低时显示“建议待确认”。
- **面板抽取成本/编造**：每章多一次抽取调用，可能编人名/年份/图注。缓解：item 必须带块锚点；人名/数字/图注逐字校验；失败重试一次，仍失败给空面板 + warning，不阻塞正文。
- **模式切换 stale**：面板/深读注依赖模式；改模式后旧 `panels.json`/`deep.json` 标 stale，不静默混用。
- **深读注重做**：narrative/practical/reference 是新类型，B0017 旧 deep 要重跑；B0042 argument 可复用。阶段 2b 接受这次重跑。
- **覆写蔓延**：每章都覆写会让书级默认失去意义。缓解：选默认模式自动回到 follow；书页显示覆写章数；阶段 2 不做批量覆写 UI。
- **叙事速览质量**：场景节拍可能碎；没有 3 个有效 scene 就判 unsupported，不硬造。
- **standard 修复暴露模型弱点**：节导语优先用模型 lead，空时确定性回退首句；不编。
- **改名破坏书签/文档**：只改用户可见文案，路由不变；旧 `?tier=research` 302；legacy research 导出 410；导航保留“阅读/读本”入口。
- **删除不可逆**：tar + manifest 先落盘；manifest 记录 sha256；不建 archive 页面，但文件可人工取回。
- **legacy 静态页残留**：重新渲染/删除旧 `chapter.html`；验收 grep `research` tab，不能只删代码。
