# 分层读：三档阅读与书型读法方案

状态：draft for review · 2026-11-11
取代：`docs/design/四读信息深度-方案-2026-11-08.md` 中 research 档的部分；`docs/adr/0001-four-reads-two-body.md` 的“标准/深读共用逐字正文”仍然有效。
不包含：视觉读本（独立第五产物，不并入本方案）。

## Problem Statement

现在的阅读页有四个档位，但第四个“研究档”没有回答一个独立的阅读问题。它按固定配额产出 5–10 行判断矩阵、3–10 条笔记、3–6 个问题，对一章 1,900 字的正文可以写出 2,300 字的元文本，并且渲染在正文之前。它的内容不是外部研究，而是编辑部的核查清单；在小说上甚至退化成“S01-U01 与 S10-U01 应视为首尾回指”这类文本内部校对。它既不能回答“今天还成立吗”，也不构成第四种读法。

citations 层与 research 绑定：research 的矩阵行被拿去生成查询；检索失败时页面仍然显示“已检索”，并把从未查过的判断标成“未找到来源”。这是事实层面的假状态，不是文案问题。

书型差异也没有被建模。书库 1,955 本书里 1,417 本是文学（72.5%），但读本结构是论证本位的：标准/深读共用逐字正文，深读注的类型是 assumption/boundary/evidence/counter/intertext；标准档本该写节导语和背景注，实测两本样本都是 0 节导语、0 条标准注。读者打开一本小说、一本方法书和一本图册，看到的是同一套论证脚手架。

## Solution

把“四读”改成“分层读”，口号“按需求读”。读者只看到三个档位：

1. **速览**：编译正文，15–25%，给“这一章讲什么”。
2. **标准**：逐字正文 + 节导语、术语、必要背景注。
3. **深读**：逐字正文 + 论证/叙事注解、引文、图、章末问题（第二阶段）。

“研究档”从 reader、生成链、工单、测试和文档中退役；citations 一起退役，reader 不再出现来源面板。外部核验如果以后要做，是独立产物，不是第四个档位。

书型差异放在**读法模式**里，不放在档位里。一本书一个默认模式，一章可以覆写：

| 模式 | UI 名 | 默认入口 | 面板 |
|---|---|---|---|
| narrative | 叙事 | 标准 | 时间线、人物/称谓、场景节拍、意象/母题 |
| argument | 论证 | 深读 | 论证图、关键定义、证据表、反例/边界 |
| practical | 实用 | 标准 | 步骤、清单、决策树、失败模式 |
| reference | 资料·图册 | 速览 | 图版、术语、版本/谱系、图注 |

模式只改注解类型、面板和默认入口；不改正文覆盖率、块 ID、锚点，也不新增第四档。没有足够结构数据时显示“本章没有足够的结构信息”，不编内容。

分两阶段落地：

- **阶段 1（删档）**：research + citations 从 reader 和生成链退役；三档跑稳；旧 research/citations 文件和 legacy 四档 export 包 tar 后删除；standard 层保持现状并如实标注。
- **阶段 2（书型）**：`reading.json`、自动建议、工单里的四模式选择器、面板、standard 节导语/标准注修复、四本书验收。

## User Stories

### 读者

1. 作为读者，我只看到速览、标准、深读三个档位，不再在一个不回答阅读问题的“研究档”上做选择。
2. 作为读者，我打开章节时正文先出现，不再先读 2,000 多字的判断矩阵。
3. 作为读者，我在深读页尾最多看到 3 个“这一章没有回答的问题”，而不是 3–10 条编辑核查笔记。
4. 作为读者，我在任何档位都看不到“已检索”徽标，除非真的有一份可核对的外部来源。
5. 作为读者，我看不到“未找到来源”标在从未检索过的判断上。
6. 作为读者，产品名和导航写“分层读 / 按需求读”，不再暗示有四个档位。
7. 作为小说读者，我看到时间线、人物/称谓、场景节拍，而不是论证矩阵。
8. 作为论证书读者，我看到论证图、定义、证据表、反例和适用范围。
9. 作为实用书读者，我看到步骤、清单、决策树和失败模式。
10. 作为图册/资料书读者，我看到图版、术语、版本/谱系和图注，不被硬套成论证。
11. 作为读者，本书默认读法跟随整本书，但某一章可以覆写，不会因为一个特殊章节改掉整本。
12. 作为读者，我能看到系统为什么建议某个读法（例如“5 个主张 / 3 个条件 / 1 个反例”），而不是只看到一个标签。
13. 作为操作员，我在读本工单里改过的本章读法会持久化，重新生成不会丢。
14. 作为读者，我恢复“跟随本书”后，本章覆写被清除，读法回到书级默认。
15. 作为操作员，我在窄屏上仍能看清四个模式按钮和当前选择，不需要横向滚动。
16. 作为读者，我访问旧 research 链接时被带到深读页，并看到一行“研究档已退役”的说明，而不是 404。

### 操作员/编辑

17. 作为操作员，我在读本工单里看到“本书默认”“系统建议”“本章覆写”三个状态，不会把建议当成已生效。
18. 作为操作员，我用四个按钮选本章读法；选择与本书默认相同的模式时，状态回到“跟随本书”，不产生无意义的覆写。
19. 作为操作员，我在没有 `reading.json` 的新书上先确认一次本书默认读法，之后每章默认跟随，不再重复确认。
20. 作为操作员，我可以把当前选择“设为本书默认”，也可以只对本章覆写。
21. 作为操作员，我在书页工单只看到本书读法的只读摘要和入口，不会在书页和章页维护两份选择器。
22. 作为操作员，我看到的建议来自确定性规则；只有规则低置信度或冲突时才调用模型，结果有缓存和依据。
23. 作为操作员，我确认后的读法写入 `books/<uid>/reading.json`，不写进 `book.json`，也不写进 ledger。
24. 作为操作员，我在阶段 1 只需处理删档，不需要同时理解书型 schema。
25. 作为操作员，我在阶段 2 用 B0017/03、B0042/07、B1848、B0641 四本书验收四类模式。

### 维护者

26. 作为维护者，我希望 `TIER_ORDER`、深度层注册、reader tab、工单、测试和文档对“三档”只有一个事实来源。
27. 作为维护者，我希望 research/citations 的删除是可回滚的：tar + manifest 先落 `工作区/归档/`，再删文件。
28. 作为维护者，我希望旧 research URL 有明确的重定向，不留下半读的页面。
29. 作为维护者，我希望 `reading.json` 的解析是纯函数，章级覆写、书级默认、建议、兜底四种来源可单测。
30. 作为维护者，我希望面板测试断言“有什么、没有什么”，而不是断言某段模型文案。
31. 作为维护者，我希望 standard 的 0 节导语/0 标准注在阶段 1 被记录为已知状态，阶段 2 修复后不再回归。
32. 作为维护者，我希望 ADR 明确记录“research 退役、三档、书型模式”，GLOSSARY 不再把四读定义为四档。

## Implementation Decisions

### 1. 术语与边界

- **分层读**：产品名。**三档**：速览、标准、深读。**书型/读法模式**：叙事、论证、实用、资料·图册。**本章读法**：某章生效的模式。**书级默认**：整本书的默认模式。**章级覆写**：某章偏离书级默认的模式。
- 代码标识、路由、数据库字段继续用 `reading` / `tiers`；只改用户可见文案、导航、文档和页面标题。不改包名、路由前缀、ledger 表名。
- “研究档”这个词从 reader、工单、导航、测试名和用户文档中消失。内部历史文档可以保留“research 已退役”的说明，但不能继续把 research 定义为档位。

### 2. 三档与层注册

- `TIER_ORDER = ("skim", "standard", "deep")`；`TIER_SPECS` 只保留三项。`standard` 和 `deep` 仍是 100% 逐字正文；只有 `skim` 编译正文。沿用 ADR 0001 的“共用一份逐字正文，只有速览编译”，只去掉 research。
- 深度层注册改为 `("model", "skim", "standard", "deep")`；`citations` 不再是深度层。`depth/state.json` 的 ready 判定只看这四层；缺失 research/citations 不算 stale。
- `disposition` 只保留 `skim` 的 condensed/omitted 规则；`standard` / `deep` 继续 verbatim。没有“研究档处置”。
- reader tab、工单 tier 列表、`app.js` 的 tier/depth 名称、`book.html`/`records.html` 的状态列全部改为三档；旧 `research` 键不再出现在 API 响应里。
- 旧 URL：`/reader/<uid>/<n>/research` 和 `?tier=research` 302 到 deep，带一行退役提示；不保留 research 页面。
- `skim.reason` 的语义在阶段 2 修正：`supported=true` 时 `reason` 必须为空；`supported=false` 才写原因。阶段 1 不改，只在文档里标注。

### 3. `reading.json`

每本书一个文件：`books/<uid>/reading.json`。它是生成读本的输入，不是派生状态；不进 `build/library.db`，不写 `book.json`，不进 ledger。它随书目录进入数据仓（`.gitignore` 只忽略 `source/`、`md/`、`html/`），因为它是读本输入；建议缓存留在 `build/`，不进仓。

```json
{
  "version": 1,
  "mode": "argument",
  "mode_source": "human",
  "default_tier": "deep",
  "panels": ["argument_map", "definitions", "evidence_table", "counterexamples", "scope"],
  "chapters": {
    "07": {
      "mode": "narrative",
      "mode_source": "human",
      "source_sha256": "<chapter md hash>"
    }
  },
  "updated_at": "2026-11-11T12:00:00+08:00"
}
```

- `mode`：`narrative | argument | practical | reference`。
- `default_tier`：`skim | standard | deep`；省略时用模式默认（叙事=标准，论证=深读，实用=标准，资料=速览）。
- `panels`：可选；省略时用模式默认面板；`[]` 表示不要面板。
- `chapters`：键是章号字符串（`"07"`），只允许覆写 `mode` 和可选 `panels`；不允许覆写 `default_tier`。带 `source_sha256`；章节源变化时覆写视为待确认，不静默沿用。
- `mode_source` 在文件里是 `human`（人确认过的值）；规则/模型建议的 `source` 只存在建议缓存里。
- 没有 `reading.json` 时 reader 仍可读：使用建议或分类兜底，但工单显示“本书尚未设定读法”；生成前必须由操作员确认一次本书默认。
- 解析顺序：章级覆写（hash 有效）> 书级默认 > 建议 > 分类兜底。解析结果带 `effective_source`：`chapter | book | suggestion | fallback`。
- 分类兜底：文学→叙事；艺术与图像/游戏/影视动画漫画→资料·图册；商业与管理/生活与实用→实用；人文社科/科学技术/建筑与古迹/写作与编剧→论证；其他/拿不准→论证，但标低置信度。

### 4. 建议引擎

- 输入：ledger `subject1`/`subject2`、`chapter_model` 的 unit 类型计数、block kind 计数、对话块比例、图数、术语数。
- 规则给四种模式打分，输出 `mode`、`confidence`（top1 与 top2 的归一化差）、`evidence`（例如“5 个主张 / 3 个条件 / 1 个反例”）。
- 规则高置信度（top1 ≥ 0.55 且 margin ≥ 0.20）直接用规则；低置信度或 top2 接近时调用一次模型分类器。模型只看结构摘要和首尾各 2 个块，不看全文；返回 `{mode, confidence, evidence}`，不写散文。
- 建议缓存：`build/reading/suggestions/<uid>/<chapter>.json`，键含章节源 hash、prompt version、模型 id；派生、可重建、可删。
- 建议永不自动写 `reading.json`。模型失败时退回规则 top1，`source=rule_fallback`，UI 标“建议待确认”。
- 建议只决定“建议”，不决定生成；生成只用 `reading.json` 的有效模式。

### 5. 工单选择器（B 方案）

- 位置：章页读本工单的“本章读法”块。书页工单只显示“本书读法：论证（人工）”+ 去章页的链接，不放第二个选择器。reader 章头显示一枚只读徽标（`本书读法 · 论证` / `本章覆写 · 叙事`），解释为什么面板不同；reader 不提供编辑控件。
- 布局：全宽“跟随本书（论证）”开关；2×2 四模式按钮；建议模式带“建议”徽标；理由行 `模型建议：论证 · 置信度 0.82`；依据行 `5 个主张 / 3 个条件 / 1 个反例`；覆写行 `本章覆写：叙事（不跟随本书）` + `恢复跟随本书`；主按钮 `按「叙事」生成读本 →` 或 `按本书默认（论证）生成读本 →`。
- 状态模型：`{follow: boolean, mode: Mode}`。
  - `follow=true`：有效模式 = 书级默认；没有书级默认时 = 建议；再没有 = 分类兜底。
  - `follow=false`：有效模式 = 选中的 `mode`。
  - 选择与书级默认相同的模式时，`follow` 回到 true，不写覆写。
  - 没有 `reading.json` 时，显示“本书尚未设定读法”，主按钮 `按「建议」生成读本`；首次确认写入书级默认（`mode_source=human`）再生成。
  - `设为本书默认` 是次级动作：改书级默认；已有章级覆写保留，但等于新默认的覆写会被清理。
- 生成：主按钮把 `{follow, mode}` 解析成有效模式，写入 job payload（`mode`, `mode_source`, `profile_hash`）；job 一旦入队，后续改 profile 不影响这次生成。
- API：`GET /api/chapter/<uid>/<n>` 增加 `reading` 对象（book_mode、chapter_override、effective_mode、effective_source、default_tier、panels、suggestion）；`PUT /api/chapter/<uid>/<n>/reading` 用 `action=follow|override|book_default` + `mode` 写书级默认、章级覆写或清除覆写；`POST .../generate` 只收 tier，服务端解析有效模式；没有 `reading.json` 且未确认本书默认时返回 409，不隐式写 profile。
- 窄屏：四个按钮保持 2×2；“跟随本书”占满一行；覆写行换行不截断。

### 6. 面板

- 面板渲染在正文之后；速览只显示每个面板的 3 条摘要，标准/深读显示完整面板。没有数据的面板不渲染；一章所有面板都缺数据时显示“本章没有足够的结构信息”，不补空话。
- 数据来源：`chapter_model` 的 unit/关系/术语、图、深读注；阶段 2 不新增“面板生成”模型调用。面板是对已有结构的重排，不是再写一遍。
- 各模式默认面板：
  - 叙事：`timeline`（时间/地点/事件）、`characters`（人物/称谓/关系）、`scene_beats`（场景节拍）、`motifs`（意象/母题）。
  - 论证：`argument_map`（主张/前提/结论/关系）、`definitions`（关键定义）、`evidence_table`（证据/来源/强度）、`counterexamples`（反例/边界）、`scope`（适用范围）。
  - 实用：`steps`（步骤）、`checklist`（检查项）、`decision_tree`（条件分支）、`failure_modes`（失败模式）、`examples`（例子）。
  - 资料·图册：`plates`（图版/图注）、`terms`（术语）、`versions`（版本/谱系）、`captions`（图注索引）。
- 面板只改显示，不改正文、块 ID、锚点；同一章切档不重载正文。

### 7. 深读页尾的“没有回答的问题”

阶段 2 在深读层增加可选的 `open_questions`，最多 3 条；每条 `{text, why, where, anchor}`。它回答“这一章提出了但没有回答什么”，不写判断、不写矩阵、不写查询、不写“今天还成立吗”。0 条合法；不设最低配额。由深读生成器在同一调用里产出，或由 chapter_model 的未答问题派生；校验锚点存在，不引入外部事实。它属于深读内容，不是新档位。

### 8. Standard 层修复（阶段 2）

- `chapter_model.sections[].lead` 作为标准档节导语：模型 prompt 要求每节一句，最多 80 字；模型仍为空时，确定性回退到该节第一个块的首句（截断 80 字），不改写。
- `standard_notes` 只从源注/编辑注生成，最多 120 字；没有来源就 0 条，不编背景。
- 验收：B0017/03 和 B0042/07 的标准档至少有 1 条节导语/节；有源注的节显示标准注；没有源注的节保持 0 条。

### 9. 阶段 1 删除与迁移

- 先打包：`工作区/归档/research-retire-2026-11-11.tar.gz` + `manifest.json`（文件列表、sha256、大小、来源 pack）。tar 只在实例磁盘（`工作区/归档/` 被 `.gitignore` 忽略）；在 `工作区/批次/2026-11-11-分层读删档/说明.md` 记录 manifest 的 sha256、文件数、验收读数，批次账进数据仓。包含：
  - 每个 depth pack 的 `layers/research.json`、`citations.json`；
  - 每个 legacy `export/` 四档包整包（`skim.html`/`standard.html`/`deep.html`/`research.html`）；
  - 修改前的 `README.md`/manifest 副本（其中含 research/citations 行）。
- 再删除上述文件；新 depth pack 的 `skim/standard/deep` 保留。`state.json` 去掉 research/citations 键，ready 只看四层。删除后旧 URL 302 到 deep。

## Further Notes

### 风险与缓解

- **模式误判**：混合书（半叙事半论证）用规则+模型仍可能错。缓解：建议只做建议，人确认；章级覆写；置信度低时显示“建议待确认”。
- **覆写蔓延**：每章都覆写会让书级默认失去意义。缓解：选默认模式自动回到 follow；书页显示覆写章数；阶段 2 不做批量覆写 UI。
- **面板空**：chapter_model 结构不足时四类面板都可能空。缓解：空数据提示，不生成空话；先只做能从现有 unit/术语/图派生的面板。
- **standard 修复暴露模型弱点**：节导语依赖 chapter_model；模型空 lead 时有确定性回退，不编。
- **改名破坏书签/文档**：只改用户可见文案，路由不变；旧 research URL 302；导航保留“阅读/读本”入口。
- **删除不可逆**：tar + manifest 先落盘；manifest 记录 sha256；不建 archive 页面，但文件可人工取回。

### 交付顺序

1. 阶段 1 删档 + 迁移 + 测试 + 文档；B0017/B0042 验收。不做 feature flag：阶段 1 直接切三档，tar + manifest 是回滚手段。
2. 阶段 2 `reading.json` + 解析 + 建议 + 选择器 + API；先不碰面板。
3. 阶段 2 面板 + standard 修复 + 深读问题；四本书验收。
4. 更新 GLOSSARY、ADR 0002、旧设计文档横幅；最后决定是否发 issue（建议一个 umbrella issue，两个 phase checklist）。
