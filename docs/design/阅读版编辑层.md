# 阅读版编辑层

状态：implemented · 2026-11-07
验收：`uv run --frozen pytest tests/test_reading_editorial.py -q`

编辑层是章节旁边的一份 `editorial.json`，管「这一章怎么读」，不管「这一段是什么角色」。
模型仍然只产出 `annotation.json` 里的 role、spine、deps、cards；节拍、图版、预测、
换算器和结论由编辑写。两者分开，模型重跑不会覆盖手工图版，手工图版也不会污染
逐字原文和角色标注。

## 文件位置

```
<阅读根>/<uid>/ch/<nn>/editorial.json
```

`Store.save()` 在重新生成时会保留已有的 `editorial.json`；删除编辑层要从文件或 API 显式删除。
没有编辑层时，渲染器输出和旧版完全一样，`G9` 也不会出现。

## 结构

```json
{
  "schema": 1,
  "uid": "B0003",
  "n": 4,
  "beats": [
    {
      "id": "beat-1",
      "title": "一个离经叛道的题目",
      "question": "为什么一个经济学家，要去给“人命”定价？",
      "before_block": "B01",
      "tiers": ["standard"]
    }
  ],
  "visuals": [
    {
      "id": "ratio-250",
      "kind": "ratio",
      "title": "同一风险，两个价格",
      "after_block": "B20",
      "placement": "after",
      "tiers": ["standard"],
      "data": {
        "left": {"label": "愿意支付", "detail": "WTP · 降低 0.1% 死亡风险", "value": 2000, "display": "$2,000"},
        "right": {"label": "要求补偿", "detail": "WTA · 接受 0.1% 死亡风险", "value": 500000, "display": "$500,000"},
        "ratio": "×250",
        "ratio_note": "同一份风险变化，答案相差 250 倍。"
      },
      "caption": "横轴为线性比例，所以 2,000 美元的条形几乎看不见。这个“看不见”本身就是问题。",
      "claims": [{"block": "B19", "quote": "在第一种情况下我最多出2 000美元"}]
    }
  ],
  "takeaways": [
    {"text": "生命可以被定价，但定价方式取决于我们怎么问。", "sources": ["B12", "B15"]}
  ],
  "takeaways_title": "这一章真正留下的，不是 700 万美元",
  "takeaways_note": "读到这里，问题还在：如果人就是这样决策的，经济学该怎么办？",
  "note_tags": {"B06": "概念 · 两种生命"},
  "note_tiers": {"B06": ["standard"]}
}
```

`beats[].before_block` 和 `visuals[].after_block` 必须是当前章节真实存在的块 ID。
`placement` 取 `after` 或 `inside`；`inside` 把图放进该块的正文列，适合方法条和换算器，
`after` 另起一行，适合整幅图版。`tiers` 缺省为 `standard`、`deep`、`research`。
`claims` 是图版数字的出处，`quote` 必须是该块原文的逐字子串；`G9` 只验证出处存在，
数字和文案的语义一致性仍要编辑复核。

## 六种图版

| kind | 回答的问题 | 关键数据 |
|---|---|---|
| `two_lives` | 两种「生命」差在哪 | `statistical` 点数、`identified` 点数、两边标签和说明 |
| `ratio` | 同一份风险，两个价格差多少 | 左右数值、显示文本、倍数、倍数说明 |
| `ledger` | 每个选择的现金和机会成本 | `rows[]`，每行 `label`、`cash`、`opportunity`、`choice`、`chosen` |
| `steps` | 一个估算方法分几步 | 1–4 个 `steps[]` 和 `result` |
| `framing` | 同一笔钱换个叫法为什么变 | `base`、`credit`、`cash`、`delta` 和两段说明 |
| `prediction` | 读之前先猜什么 | `question`、2–5 个 `options`、`reveal` |

图版不是每章必配。没有合适的问题就不写 `visuals`，空数组合法；不要为了凑「每章三张图」
把正文改写成图注。

## 作者流程

1. 先让章节正常生成，确认 `annotation.json` 和原文块 ID。
2. 写 `editorial.json`，用 API 保存：

   ```bash
   curl -sS -X POST http://127.0.0.1:8771/api/editorial/B0003/4 \
     -H 'Content-Type: application/json' \
     --data-binary @editorial.json
   ```

   保存时会跑 `validate_editorial`，块不存在、引文不逐字、档位写错都会返回 400 和字段路径。
3. 重新生成同一章，`G9 编辑层` 会检查节拍顺序、图版锚点、档位成员和结论出处。
4. 用桌面、390px、夜间、只看原文四种视图验收。`只看原文` 会隐藏所有
   `data-origin="added"` 的元素，并把正文栏收窄到 680px。

## 设计约束

- 节拍是编辑判断，不是模型摘要。五拍是这一章的论证转折，不是固定模板。
- 每张图必须回答正文提出的一个问题；图注先给结论，再给依据。
- 图上的数字必须有 `claims` 出处。`G9` 能查引文存在，查不了「2,000 是否真的对应 0.1%」，
  所以数字仍要人工对源文。
- `only-source` 保留编辑层加的段距，但隐藏节拍、图版、边注和结论。这是有意的可读性取舍，
  不是原文缺失；原文块本身逐字未动。
- 夜间模式是阅读器的低对比纸色，不是纯黑主题；图版用同一组 CSS 变量，不另做一套暗色图。

## 验收

- `G9` 通过，且 `G1` 到 `G8` 不退化。
- 桌面 1400px、移动 390px、夜间、只看原文四种视图都无横向溢出。
- 图版在 390px 不靠缩小字号硬塞；表格类图版在窄屏改为堆叠卡片。
- `editorial.json` 缺失或为空时，页面和旧版一致。
