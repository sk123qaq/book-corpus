# 四读信息深度方案

状态：待评审 · 2026-11-08  
范围：`skim / standard / deep / research` 四档的正文、注解、图表与研究扩展  
不包含：视觉读本（`edition`）的改版；代码实现

## 0. 一句话

四读不再按“保留多少块”分档，而按“每个信息单元怎么呈现”分档：

- **速览**是唯一使用编译正文的档位；
- **标准 / 深读 / 研究**共用同一份 100% 逐字正文；
- 三档的差别是注解、图表、研究档案的密度；
- 所有压缩都记在一本可检查的“信息守恒账”上，不再用字符覆盖率当档位 KPI。

## 1. 问题

### 1.1 现在四读是块投影

`src/bookcorpus/reading/tiers.py:11-53` 用 `c_min/c_max` 定义每档保留多少块，`tiers.py:459` 的 `project()` 按块取舍。`src/bookcorpus/reading/render.py:398` 只渲染投影内的块，没被选中的块直接消失。

这带来三个问题：

1. **覆盖率不等于完整度。** 一章可以刚好落在 55% 的覆盖带里，同时丢掉一个关键前提。`src/bookcorpus/reading/service.py:28-30` 自己也承认，块粒度让覆盖率只能落在离散点上。
2. **标准档并不是“基本不变”。** 现在标准档的覆盖带是 60–75%，已经准备丢掉 25–40% 的块。用户要的标准档是逐字基准，这两件事冲突。
3. **讲解层承担不了正文。** cards 的预算是 `e_max` 的 10–50%，只能在旁边补一句，不能替代被删掉的论证。

### 1.2 为什么调覆盖率解决不了

把 `c_min` 调到 95% 只会让标准档接近全文，速览档仍然可能漏前提。问题不在阈值，在单位：**块是排版单位，不是信息单位。** 一个块里可能有两三个论证动作，一个论证也可能跨三四个块。

### 1.3 两条可复用的管线

- `src/bookcorpus/reading/agent_standard.py:22` 已经让模型直接写标准档 HTML，`validate_fragment` 能检查“原文块是否逐字出现”，但检查不了“该出现的命题是否出现”。所以它只能是实验，不能当正式管线。
- `src/bookcorpus/reading/edition/generate.py:11` 给出了正确模式：模型只写 JSON 内容层，程序逐字插入原文，`edition/gate.py` 再做覆盖校验。新方案沿用这个模式，但把“内容层”拆成信息单元、处置和分档注解。

## 2. 已定决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 只有速览换编译正文；标准、深读、研究共用 100% 逐字正文 | “标准不变”必须是结构保证，不能靠覆盖率碰巧落在 95% |
| D2 | 深读 = 逐字正文 + 论证注，材料限于本章和本书其他章节 | 深读回答“这本书内部怎么成立”，书外材料归研究 |
| D3 | 标准档长清单可折进 `<details>`，展开仍是逐字原文，summary 写清条数 | 页面可以短，原文不能少；折叠是呈现，不是删除 |
| D4 | 研究档检索：提示词定标准，模型提请求，代码裁决并执行，verifier 打标 | 模型不拥有“搜不搜”的最终权力；网络、费用、来源白名单是系统决策 |
| D5 | `已核验` = 抓到支持句 + URL + 访问时间；普通事实一个强来源，争议经验判断两个独立来源 | “有链接”不等于“核验过” |
| D6 | 一页两正文树；源文超过 30K 字把速览拆独立页 | 四档共享正文锚点，切换不重载；避免单页过重 |
| D7 | 图表用七类语法，不让模型为每种图写一个渲染器 | 图是结构表达，不是手工艺品；可校验、可降级 |
| D8 | 保留旧 `tiers.project` 作为无模型 fallback，新路径通过 feature flag 启用 | 旧包不受影响；新管线失败时不静默降级 |

## 3. 术语

这一节是四读上下文自己的术语。现有 `GLOSSARY.md` 明确只覆盖视觉读本，暂不把四读术语塞进去；等方案确认后再决定是否拆 `GLOSSARY-MAP.md`。

**档位（tier）**：`skim / standard / deep / research` 四个阅读契约。  
_Avoid_: 低档、中档、高档。“低中档”不再使用，直接说档位名。

**编译正文（compiled body）**：模型按信息单元重写出的正文，只在速览档使用。  
_Avoid_: 摘要、缩略版。

**逐字正文（verbatim body）**：源文块按原序、原文、原块 ID 呈现的正文，标准、深读、研究共用。  
_Avoid_: 原文版、完整版。

**信息单元（unit）**：一章里一个可独立判断的论证动作，例如一个定义、一个判断、一组条件、一条证据、一个结论。单元可以跨块，块也可以拆成多个单元。  
_Avoid_: 段落、块、句子。

**处置（disposition）**：某一档对某个信息单元的处理方式：`verbatim / condensed / indexed / omitted`。  
_Avoid_: 覆盖、保留率。

**硬信息（hard info）**：定义、判断、条件、风险、例外、结论、数字、图表标题、被引证据。硬信息在任何档位都必须是 `verbatim` 或 `condensed`。  
_Avoid_: 重点、要点。

**折叠（fold）**：把长清单或长表格收进 `<details>`，内容仍在 DOM 中逐字存在，summary 写明“是什么、多少条”。折叠不是处置，不是删除。  
_Avoid_: 收起、省略。

**论证注（argument note）**：深读档对某个单元或小节的假设、边界、证据质量、反例、互文的注释。只使用本章和本书其他章节的材料。  
_Avoid_: 深读摘要、解读。

**研究档案（research dossier）**：研究档对某一组命题的外部语境、后续证据、批评、今日适用和开放问题。每条都带来源与核验状态。  
_Avoid_: 扩展阅读、参考文献。

**已核验（verified）**：抓取到的来源页面里有一段原文，确实支持该命题；同时存下 URL、支持句、访问时间。  
_Avoid_: 有引用、有链接、查过。

## 4. 档位契约

| 档位 | 读者问题 | 正文 | 模型写什么 | 图 | 目标时间 |
|---|---|---|---|---|---|
| 速览 `skim` | 这一章说了什么 | 编译正文，原文的 15–25% | 节导语、每节 2–4 个命题、转折、细节索引 | 1 张章级论证图 + 最多 2 张节级图 | 5–8 分钟 |
| 标准 `standard` | 这一章怎么说的 | 逐字 100% | 术语、概念背景、节导语、图注 | 1 张结构图 + 最多 3 张节级图 | 10–15 分钟 |
| 深读 `deep` | 为什么这样说，靠什么成立 | 逐字 100% | 论证注：假设、边界、证据、反例、互文 | 标准图 + 每 H2 最多 1 张论证链 | 20–30 分钟 |
| 研究 `research` | 今天还成立吗 | 逐字 100% | 研究档案、命题矩阵、检索请求 | 命题矩阵 + 时间线/关系图 | 30–45 分钟 |

### 4.1 速览

速览是唯一换正文的档位。它不是“抽几段”，而是按节重写：

- 每个 H2 一段导语，回答“这一节在推进什么”；
- 每节 2–4 个命题，每个命题带单元锚点；
- 一个转折或收束句，指出这一节改变了什么；
- 关键定义可以保留一句逐字引用，不必强行改写；
- 所有没有进入正文的细节，进“未展开细节”索引，每条带锚点，可跳回标准档原文。

速览的正文长度按汉字数计，控制在源文的 15–25%。索引不计入正文比例。

速览不做“作者认为 / 本章指出 / 我们可以看到”这类导读腔。直接写命题。

### 4.2 标准

标准档的正文是 100% 逐字原文：

- 不重写、不合并、不删段、不加省略号；
- 块序、块 ID、标题层级不变；
- 长清单可以折进 `<details>`，展开后仍是逐字原文；
- summary 必须写清里面是什么、多少条，例如 `完整清单 · 23 条`、`表 3–2 · 14 行`；
- 折叠内容在 DOM 中，G1 仍然通过；打印和“只看原文”时自动展开。

标准档的模型产物只有四类：

1. **术语**：首次出现时挂一次，释义优先用原文定义；原文没有定义时，写一句概念背景，标 `origin="editor"`，不超过 60 字。
2. **概念背景**：解释读者可能不知道、但不懂就读不下去的概念。只使用本章和本书其他章节的材料，不引书外历史事实；不超过 120 字。
3. **节导语**：一句话说明这一节回答的问题，不超过 80 字；它是导航，不是摘要替代。
4. **图注**：结论先行的一句话，外加一句读图方式。

标准档的附加文字预算控制在原文的 15% 左右。超了要删注，不是删原文。

### 4.3 深读

深读的正文仍是 100% 逐字原文。模型只写论证注，每条注必须落在具体单元或块上：

- **假设**：这个判断要成立，必须先成立什么；
- **边界**：什么条件下不成立，原文有没有交代例外；
- **证据**：样本、基数、选择效应、测量方式；原文没交代就写“原文未交代”；
- **反例/张力**：原文内部矛盾，或作者自己承认的反驳；
- **互文**：与本书其他章节的呼应、重复、修订。

深读的材料边界：本章 + 本书其他章节。可以引用其他章节的原文，但不能引入书外新事实、作者生平、成书后的研究。那些归研究档。

每 H2 最多 3 条注，全章最多 12 条。每条 80–200 字。没有可说的就不写，不凑数。

### 4.4 研究

研究档的正文仍是 100% 逐字原文，另加两块：

1. **研究档案**：按节或按命题组织，条目类型为 `context`（思想/历史语境）、`later`（后续证据）、`critique`（批评/争议）、`application`（今日适用）、`open`（开放问题）。每条带 `origin`、`certainty`、`citations`、`related_units`。
2. **命题矩阵**：5–10 条最值得校验的命题，四列：命题｜当前判断｜变化来源｜需要什么证据。当前判断用四态：仍成立 / 条件改变 / 需谨慎 / 需核验。

研究档是唯一允许书外材料的档位。每条书外事实必须有引用；没有引用的，只能写成“待核验的推断”，并标 `未核验`。

没有配置检索 provider 时，研究档退化为“研究议程”：只列命题、为什么需要外部证据、建议查询，不写当前事实。这样不会把模型记忆冒充成研究结论。

### 4.5 跨档规则

- 标准、深读、研究共用同一份逐字正文和同一套折叠；切换档位不重载正文。
- 速览的每个命题、每条索引都必须能跳到标准档的对应块。
- 任何档位都不静默丢块。被压掉的单元至少有一行索引；重复表达必须有 `duplicate_of` 指向 canonical 单元。
- 任何新增文字都要带 `origin`：`source`（原文）、`editor`（编注/论证注）、`model`（推断）、`external`（书外来源）。研究档还要带 `certainty` 和 `citations`。

## 5. 信息模型

### 5.1 信息单元

```json
{
  "id": "S02-U03",
  "kind": "claim",
  "section": "S02",
  "source_blocks": ["B19", "B20"],
  "quotes": [
    {"block": "B19", "text": "在第一种情况下我最多出2 000美元"}
  ],
  "summary": "同一风险变化，支付意愿约 2,000 美元，接受意愿约 500,000 美元。",
  "importance": "core",
  "hard_info": true,
  "relations": [
    {"type": "supports", "to": "S02-U05"}
  ]
}
```

字段：

- `kind`：`definition / claim / conclusion / condition / risk / example / evidence / context / transition`。
- `source_blocks`：该单元覆盖的块；一个单元可以跨块。
- `quotes`：逐字锚点，每项必须来自一个具体块，不能拼接、不能改写。
- `summary`：一到两句，不能引入原文没有的事实。
- `importance`：`core`（删掉会断主论证）、`support`（支撑核心）、`detail`（细节/例证）。
- `hard_info`：定义、判断、条件、风险、例外、结论、数字、图表标题、被引证据为 `true`。
- `relations`：只记原文明确表达的关系：`supports / contrasts / causes / exemplifies / qualifies`。
- `duplicate_of`：可选；只用于重复表达，指向 canonical 单元。

目标密度是每 1000 字 6–12 个单元。论证密集的章可以到 15，叙事章可以低到 4。单元按论证动作切，不按句子切；一段最多 3 个单元。

### 5.2 处置

每个档位给每个单元一个处置：

| 处置 | 含义 | 页面表现 |
|---|---|---|
| `verbatim` | 原文逐字出现 | 正文块，或速览里的逐字引用 |
| `condensed` | 摘要句出现，带原文锚点 | 速览正文的一句命题 |
| `indexed` | 只在细节索引里留一行，带锚点 | “未展开细节”条目，可跳原文 |
| `omitted` | 不出现 | 只允许重复表达，且必须有 `duplicate_of` |

硬规则：

1. 所有 `hard_info` 单元在任何档位都必须是 `verbatim` 或 `condensed`。
2. 所有非硬信息单元至少是 `indexed`。
3. `omitted` 只允许用于 `duplicate_of` 指向 canonical 单元的重复表达。
4. 每个正文块必须被至少一个单元覆盖，或列入 `non_semantic` 并写明理由。`unmapped_blocks` 必须为 0。

表格按行拆单元；同类数据行可以合并成一个单元，但必须保留表头和关键行。如果整张表是核心证据，速览至少保留表头、结论行和一句读表说明；其余行进索引。如果表只是细节，速览可以把整表标为 `indexed`，但不能丢表题。

图片分两类：

- **语义图**：参与论证、提供数据或结构。必须进单元或 `figures`，标准/深读/研究保留原图，速览保留图注和锚点。
- **装饰图**：章题图、版式图、重复扫描件。列入 `non_semantic`，写理由，可以省略。

### 5.3 守恒账

每一档渲染前计算：

```json
{
  "core_total": 42,
  "core_covered": 42,
  "hard_total": 57,
  "hard_covered": 57,
  "detail_total": 31,
  "detail_in_body": 18,
  "detail_indexed": 31,
  "omitted_duplicates": 4,
  "unmapped_blocks": 0
}
```

- `core_covered`：`verbatim` 或 `condensed` 的核心单元数。
- `detail_in_body`：进入正文的细节单元数；其余细节在索引里。
- `detail_indexed`：至少有索引行的细节单元数。
- `omitted_duplicates`：因重复而省略的单元数。
- `unmapped_blocks`：既没有进单元、也没有进 `non_semantic` 的正文块数。

页面徽标用这本账，不用字符覆盖率：

`编译版 · 核心 42/42 · 细节 18/31 · 其余 13 条在索引 · 6 分钟`

### 5.4 `chapter_model.json`

与 `annotation.json`、`editorial.json` 同目录，原子写，manifest 最后落。

```json
{
  "schema": 1,
  "uid": "B0003",
  "n": 6,
  "source_sha256": "...",
  "prompt_version": "chapter-model-v1",
  "units": [
    {
      "id": "S02-U03",
      "kind": "claim",
      "section": "S02",
      "source_blocks": ["B19", "B20"],
      "quotes": [{"block": "B19", "text": "在第一种情况下我最多出2 000美元"}],
      "summary": "同一风险变化，支付意愿约 2,000 美元，接受意愿约 500,000 美元。",
      "importance": "core",
      "hard_info": true,
      "relations": [{"type": "supports", "to": "S02-U05"}]
    }
  ],
  "sections": [
    {"id": "S02", "block": "B12", "title": "给生命定价", "units": ["S02-U03", "S02-U04"]}
  ],
  "terms": [
    {"name": "支付意愿", "definition": "为降低一点风险最多愿意付多少钱。", "source_block": "B19", "origin": "source"}
  ],
  "figures": [
    {
      "id": "F01",
      "family": "argument",
      "question": "这一章的论证靠哪几步成立",
      "units": ["S01-U01", "S02-U03", "S03-U01"],
      "origin": "source",
      "caption": "先制造一个不可接受的数字，再拆掉它的前提。",
      "reading_note": "看每条边是支持还是限定，不要只看节点。",
      "data": null
    }
  ],
  "non_semantic": [
    {"block": "B01", "reason": "章题页"}
  ],
  "tiers": {
    "skim": {
      "body": "compiled",
      "disposition": {"S02-U03": "condensed", "S02-U04": "indexed"}
    },
    "standard": {
      "body": "source",
      "disposition": {"S02-U03": "verbatim"}
    },
    "deep": {
      "body": "source",
      "disposition": {"S02-U03": "verbatim"}
    },
    "research": {
      "body": "source",
      "disposition": {"S02-U03": "verbatim"}
    }
  },
  "folds": [
    {"block": "B31", "summary": "完整清单 · 23 条", "reason": "长清单超过 8 项"}
  ]
}
```

`figures` 在结构模型阶段只给候选：`family / question / units / origin / caption / reading_note`。具体 `data` 由标准档图表层填，避免结构模型一次写太多。

### 5.5 与 `annotation.json` 的关系

- `annotation.json` 继续服务旧渲染路径：role、spine、deps、cards 不变。
- `chapter_model.json` 是新路径的唯一结构来源；它不复用 `annotation.json` 的 `tier_blocks`，因为档位不再由块投影决定。
- 旧包没有 `chapter_model.json` 时，渲染器走旧路径，不报错。
- 新包生成后，旧 `annotation.json` 仍保留，作为回退和对比，不删。

## 6. 生成流水线

### 6.1 总览

```
解析块（沿用 mdparse）
  → chapter_model（一次，按 H2 分块）
  → disposition planner（纯函数，算出四档处置 + 折叠）
  → 按需生成层：skim / standard / deep / research
  → 研究档：检索请求 → 代码裁决 → 搜索/抓取 → verifier
  → 渲染一页两正文树
  → 门禁 G1–G14
  → depth/state.json 最后写
  → 根 manifest 最后落
```

### 6.2 `chapter_model`

- 输入：章节标题、H2 结构、带块 ID 的原文、书名、相邻章节标题。
- 输出：`units / sections / terms / figures / non_semantic`。
- 源文总字符 ≤ 18000：一次调用，即使有多个 H2。
- 源文总字符 > 18000：按 H2 分块调用；每块带上前后 H2 标题和代码给出的已确定单元 ID 前缀（如 `C01-`），合并后整体校验。分块只在超过 18000 时发生。
- 单元 ID 用 `S%02d-U%02d`，全局唯一，避免分块重号。
- 输出上限按块控制在 12K tokens 以内；不抬高全局 `MAX_TOKENS`。
- 缓存键：`sha256(source_sha256 + prompt_sha256 + model + effort)`；缓存落 `depth/cache/<key>.json`，`state.json` 记录 `cache_key`。

校验失败时，把错误列表附回给模型重试一次（总共两次调用）；仍失败就抛错，不写半成品，也不用合成模型兜底。只有模型提供方传输失败时，按 provider fallback 重试一次。

### 6.3 处置规划

`plan_dispositions(chapter_model, tier)` 是纯函数，输入结构模型和档位，输出：

- 每个单元的处置；
- 每个块的呈现方式（正文 / 折叠 / 索引 / 省略）；
- 折叠列表；
- 守恒账。

它不调用模型，结果可重放。这样“为什么这一档删了这条”永远能追溯到规则，而不是模型的自由裁量。

### 6.4 分层生成

四层独立生成、独立缓存、独立重跑：

| 层 | 输入 | 输出 | 失败时 |
|---|---|---|---|
| `skim` | 结构模型 + 分节原文 | 节导语、命题、转折、细节索引 | 速览显示“编译未完成”，其余档正常 |
| `standard` | 结构模型 + 原文 + 书内上下文 | 术语、概念背景、节导语、图表 spec | 标准档显示逐字正文，注为空 |
| `deep` | 结构模型 + 原文 + 本书其他章节摘要 | 论证注、论证链 spec | 深读显示逐字正文，注为空 |
| `research` | 结构模型 + 原文 + 引用 | 研究档案、命题矩阵、检索请求 | 研究档显示“研究未完成”，不编造 |

层缓存键：`sha256(chapter_model_sha + layer_prompt_sha + model + effort + citations_sha)`。`citations_sha` 只对研究层生效。

### 6.5 渲染

新增 `render_depth_chapter()`，不改造旧 `render_chapter()`：

- 两棵正文树：`[data-body="compiled"]` 和 `[data-body="source"]`。
- 速览 tab 显示编译树；标准/深读/研究显示逐字树，只切换 `[data-tiers]` 注解层。
- 逐字树复用现有 `_render_block` 和块锚点 `#B12`；不复制一套块渲染。
- 速览的“看原文”链接切到标准 tab 并滚到对应 `#B12`。
- `only-source` 隐藏 `[data-origin="added"]`，并展开所有 `<details>`。
- 无 JS 时四档顺序展开，tab 只是渐进增强；打印时按当前档输出。

### 6.6 缓存与失效

- `source_sha` 变：`chapter_model`、四层、引用全部失效。
- `chapter_model` 变：四层全部失效。
- 单层 prompt 变：只失效该层。
- 引用变：只失效研究层和研究渲染。
- 引用超过 180 天：渲染标“引用较旧”，不自动重抓；下次手动重跑研究层时更新。

## 7. 模型契约

所有模型只输出 JSON，不输出 HTML。渲染由程序完成。这样 G10/G11/G12/G13 才能查 JSON，而不是猜 HTML。

### 7.1 `chapter-model-v1`

角色：中文书稿的结构编辑，不是摘要器。

规则：

- 单元按论证动作切，不按句切；一段最多 3 个单元。
- 每个单元至少一个 `quote`，必须逐字来自 `source_blocks` 中的块；不能拼接、不能改写。
- `summary` 不能引入原文没有的事实；数字、专名、年份必须与原文一致。
- `hard_info` 不能漏标：定义、判断、条件、风险、例外、结论、数字、图表标题、被引证据。
- 每个正文块必须被至少一个单元覆盖，或进 `non_semantic` 并写理由。
- `relations` 只记原文明确表达的关系；不要把所有单元串成一条链。
- `terms` 只收“不懂就读不下去”的术语；能用原文定义就用原文。
- `figures` 只收有结构关系的候选：论证链、对照矩阵、分类树、流程、时间线、关系网、数量对比。没有结构就不提。
- 不要输出 `tier_blocks`；处置由代码算。

校验：

- JSON 可解析，schema 正确；
- 所有块 ID 存在；所有 quote 逐字；所有单元有 summary；
- `unmapped_blocks=0`；`non_semantic` 有理由；
- 关系目标存在；图候选有 units；
- 单元密度在 4–20 个/千字之间（超出只警告，不阻断）。

### 7.2 `skim-compiler-v1`

输入：结构模型 + 分节原文。输出：

```json
{
  "sections": [
    {
      "id": "S02",
      "lead": "这一节把“生命值多少钱”拆成两个问题。",
      "claims": [
        {"text": "同一风险变化，支付意愿与接受意愿相差约 250 倍。", "units": ["S02-U03"], "anchor": "B19"}
      ],
      "turn": "但这两个数字都不是市场价，而是两种提问方式。"
    }
  ],
  "detail_index": [
    {"label": "WTP/WTA 的实验设置", "unit": "S02-U04", "anchor": "B20", "quote": "……"}
  ]
}
```

规则：

- 每节 1 段导语、2–4 个命题、可选 1 个转折；
- 每个命题至少引用一个单元；核心单元必须至少出现一次；
- 关键定义可以带一句逐字引用，算 `verbatim`；
- 不写“作者认为 / 本章指出 / 我们可以看到”；
- 数字、专名、年份与原文一致；
- 正文汉字数在源文的 15–25%。

### 7.3 `standard-annotator-v1`

输出：

```json
{
  "section_leads": {"S02": {"text": "这一节回答：一条命的价格从哪里来。", "anchor": "B12"}},
  "terms": [
    {"name": "支付意愿", "definition": "为降低一点风险最多愿意付多少钱。", "anchor": "B19", "origin": "source"}

  ],
  "figures": [
    {
      "id": "F02",
      "family": "quantity",
      "question": "同一风险，两种问法的答案差多少",
      "units": ["S02-U03"],
      "origin": "source",
      "caption": "同一份风险变化，两个答案相差 250 倍。",
      "reading_note": "看条形长度的比例，不要只看数字。",

        "right": {"label": "接受意愿", "value": 500000, "display": "$500,000"},

```

规则：

- 术语首次出现才挂；同一术语不重复解释；
- 概念背景只用本章/本书材料；书外历史事实不写；
- 节导语是导航，不是摘要替代；
- 注不超过 120 字；全章注数不超过 12 条；
- 图必须有 `question / units / origin / caption`；数字必须能在原文找到。

### 7.4 `deep-annotator-v1`

输出：

```json
{
  "notes": [
    {
      "id": "D01",
      "anchor": "B20",
      "kind": "assumption",
      "text": "这个 250 倍的对比要成立，前提是两种问法面对的是同一概率变化；原文用 0.1% 的死亡风险固定了这一点。",
      "units": ["S02-U03"],
      "sources": ["B19", "B20"],
      "origin": "book"
    }
  ],
  "figures": [
    {
      "id": "F03",
      "family": "argument",
      "question": "250 倍这个结论依赖哪几步",
      "units": ["S02-U03", "S02-U05"],
      "origin": "derived",
      "caption": "倍数不是结论本身，结论是“提问方式改变了价格”。",
      "reading_note": "看哪一步是假设，哪一步是测量。",
      "data": null
    }
  ]
}
```

规则：

- `kind`：`assumption / boundary / evidence / counterpoint / crossref`；
- 每条注至少引用一个单元或块；
- 只能使用本章和本书其他章节；引用其他章节要写章节名；
- 原文没交代的证据细节，写“原文未交代”，不补；
- 全章最多 12 条，每 H2 最多 3 条；
- 不写泛泛的“这很重要”“值得深思”。

### 7.5 `research-dossier-v1`

输出：

```json
{
  "dossier": [
    {
      "id": "R01",
      "kind": "later",
      "title": "后续研究对 WTP/WTA 差距的解释",
      "text": "后续研究把差距拆成收入效应、替代性和不确定性等来源。",
      "origin": "external",
      "certainty": "verified",
      "citations": ["C01"],
      "units": ["S02-U03"]
    }
  ],
  "claim_matrix": [
    {
      "claim": "WTP/WTA 差距有 250 倍",
      "unit": "S02-U03",
      "judgment": "caution",
      "reason": "实验设置和样本会影响倍数，不能当成普遍常数。",
      "citations": ["C01"],
      "certainty": "verified"
    }
  ],
  "verification_requests": [
    {
      "claim": "S02-U03",
      "need": "external",
      "query": "WTP WTA disparity meta-analysis",
      "reason": "经验倍数是否稳定，需要后续研究",
      "claim_quote": "在第一种情况下我最多出2 000美元"
    }
  ]
}
```

规则：

- `kind`：`context / later / critique / application / open`；
- 每条 `external` 必须有 `citations`；没有引用就只能写 `open` 或 `model`，并标 `未核验`；
- `judgment` 四态：`still / changed / caution / verify`；
- `certainty` 三态：`verified / partial / unverified`；
- 不编造 URL、作者、年份、期刊；
- 没有 provider 时，只输出 `open` 条目和 `verification_requests`，不输出当前事实。

### 7.6 `citation-verifier-v1`

输入：一条命题 + 抓取到的候选段落。输出：

```json
{
  "status": "verified",
  "quote": "……",
  "reason": "该段明确报告了同一实验中的 WTP/WTA 倍数。",
  "confidence": "high"
}
```

`status` 只能是 `verified / partial / unsupported / not_found`。只有 `verified` 才能在页面标“已核验”。

## 8. 研究档检索

### 8.1 裁决链

```
提示词定标准
  → 模型对每条命题输出 need/query/reason
  → 代码按策略筛选、排序、限量
  → SearchProvider 搜索
  → fetch + 正文提取
  → verifier 判断支持关系
  → citations.json + 页面状态
```

模型不直接调用搜索，也不决定最终搜几条。它只提交“候选核验请求”。

### 8.2 什么算 `need=external`

提示词里的标准：

- 依赖发布后的事实：当前政策、机构、价格、统计、技术状态；
- 具体经验数字、年份、研究结论，读者可能想查证；
- 有争议的判断，或不同来源可能给出不同答案；
- 如果为假，会改变读者决策的命题。

不算 `external`：

- 定义、逻辑推导、文本解释；
- 作者明确表达的观点；
- 原文已经引用并给出处的事实；
- 思想实验、假设场景。

### 8.3 代码策略

- 只对 `research` 档执行；
- 只处理 `need=external`；
- 每章最多 5 次查询，去重后按优先级排序：
  1. 核心命题 + 时效性；
  2. 核心命题 + 经验数字；
  3. 支撑命题 + 时效性；
  4. 其他。
- 每次查询最多取 3 个结果，抓取前 2 个；全章最多抓 10 页；
- 没有配置 provider：全部 `not_searched`，研究档显示“未接检索”；
- 抓取失败：`fetch_failed`；搜到但没支持句：`not_found`；
- 只有 verifier 返回 `verified` 才写 `已核验`。

### 8.4 引用存储

`citations.json` 与 `chapter_model.json` 同目录：

```json
{
  "schema": 1,
  "sources": [
    {
      "id": "C01",
      "query": "WTP WTA disparity meta-analysis",
      "url": "https://example.org/paper",
      "title": "……",
      "accessed_at": "2026-11-08T12:00:00Z",
      "provider": "http",
      "content_sha": "..."
    }
  ],
  "links": [
    {
      "claim": "S02-U03",
      "source": "C01",
      "status": "verified",
      "quote": "……",
      "confidence": "high"
    }
  ]
}
```

只存支持句，不存整页正文。`content_sha` 用于发现来源页面变化。

### 8.5 安全与失败

- 只允许 `http/https`；拒绝私网、回环、link-local 地址；
- 页面最大 2MB，超时 15 秒，不执行 JS；
- 提取正文用 `bs4` 去脚本/样式；引用文本转义后渲染；
- 外部链接只出现在研究档，`rel="noopener noreferrer"`；
- G5 的外部资源规则不拦引用 `<a href>`，但仍禁止外部 CSS/JS/图片/字体；
- provider 未配置、超时、限流都不阻断生成；页面标状态，不静默失败。

## 9. 图表

### 9.1 七类语法

| family | 回答什么 | 典型场景 | 数据来源 |
|---|---|---|---|
| `argument` | 论证靠哪几步成立 | 主张—证据—结论、假设—推论 | 单元关系 |
| `matrix` | 两个维度怎么对照 | 命题校验、方案对比、条件矩阵 | 原文/单元 |
| `tree` | 概念怎么分类 | 章节层级、分类树、决策树 | 原文结构 |
| `flow` | 过程怎么走 | 流程、因果链、分支 | 原文步骤 |
| `timeline` | 时间上怎么发生 | 历史、版本、事件序列 | 原文/引用 |
| `network` | 概念怎么相连 | 知识地图、上下游、影响关系 | 单元关系 |
| `quantity` | 数量差多少 | 条形、比例、曲线、账本 | 原文数字 |

`quantity` 复用现有 `visuals.py` 的 `scale / ratio / curve / ledger` 图版；新代码只加 `diagrams.py` 处理前六类。不要为每张图写一个渲染函数。

### 9.2 统一信封

```json
{
  "id": "F01",
  "family": "argument",
  "question": "这一章的论证靠哪几步成立",
  "units": ["S01-U01", "S02-U03", "S03-U01"],
  "origin": "source",
  "caption": "先制造一个不可接受的数字，再拆掉它的前提。",
  "reading_note": "看每条边是支持还是限定，不要只看节点。",
  "data": {
    "nodes": [
      {"id": "n1", "label": "生命可以被定价", "role": "claim"},
      {"id": "n2", "label": "WTP/WTA 相差 250 倍", "role": "evidence"},
      {"id": "n3", "label": "提问方式决定价格", "role": "conclusion"}
    ],
    "edges": [
      {"from": "n2", "to": "n1", "relation": "supports"},
      {"from": "n2", "to": "n3", "relation": "implies"}
    ]
  },
  "fallback": "text"
}
```

- `origin`：`source`（原文直接给出）、`derived`（由单元关系推导）、`external`（研究引用）。
- `caption` 结论先行，不写“图展示了……”。
- `reading_note` 一句话，告诉读者看什么。
- `fallback`：`text` 或 `table`；数据不合法、移动端过窄时降级。
- 每个节点/边必须能追到单元或原文；`derived` 要在 `data.derivation` 写推导。

### 9.3 放置与预算

- 标准：1 张章级结构图（`tree / network / argument`）+ 最多 3 张节级图；不是每节都配图。
- 速览：1 张章级论证图 + 最多 2 张节级图；文字已经压短，图承担更多结构。
- 深读：标准图 + 每 H2 最多 1 张论证链，全章最多 6 张。
- 研究：命题矩阵（5–10 条）+ 需要时的时间线/关系图。
- 图只能放在节首、节尾或块后，不切开原文段落。
- 图不重复：同一结构只画一次；深读可以复用标准图并加注，不另画一张。

### 9.4 渲染与降级

- `argument / tree / flow / timeline / network` 用内联 SVG + HTML 标签；`matrix / quantity` 用 HTML/CSS。
- 移动端：宽图横向滚动或降级为纵向列表；不缩小到不可读。
- 打印：`break-inside: avoid`；图注跟图不分离。
- 无障碍：`role="img"` + `aria-label`，图注可见；颜色不是唯一编码。
- 数据不合法：整图降级为 `table` 或 `text`，页面标“图已降级”，不画空图。
- 数字不在原文：G12 失败，删图，不修改数字。

## 10. 页面

### 10.1 一页两正文树

```html
<body data-tier="standard">
  <main data-body="compiled" hidden>…速览编译正文…</main>
  <main data-body="source">
    …逐字正文 + 标准/深读/研究注解层…
  </main>
</body>
```

- 四个 tab：速览、标准、深读、研究。
- 速览显示编译树；其余三档显示逐字树，只切换 `[data-tiers]`。
- 正文块锚点统一 `#B12`；速览的“看原文”切到标准并滚动到同一锚点。
- `?tier=deep` 可深链；`#B12` 可定位。
- 无 JS 时四档顺序展开，tab 隐藏；内容仍可读。

### 10.2 速览

- 顶部徽标：`编译版 · 核心 42/42 · 细节 18/31 · 6 分钟`。
- 每节：导语 → 2–4 个命题 → 可选转折。
- 每个命题旁有 `看原文`，跳到标准档对应块。
- 关键定义可以有一句逐字引用，样式与命题区分。
- 底部“未展开细节”：按节分组，每条 `label + 首句 + 锚点`，可展开逐字引文。
- 速览没有 `only-source` 开关；它本来就是编译稿，给“看原文”跳转。

### 10.3 标准 / 深读 / 研究

- 共用逐字正文；顶部显示档位说明和“只看原文”开关。
- 标准：首现术语有标记，边注解释概念；长清单折叠；结构图在章首或节首。
- 深读：在标准注解之上加论证注；注按 `assumption / boundary / evidence / counterpoint / crossref` 着色或加标签。
- 研究：在标准注解之上加研究档案和命题矩阵；外部引用用上标 `[C01]`，页尾列来源。
- “只看原文”：隐藏所有 `data-origin="added"`，展开所有 `<details>`，保留原图。
- 切换档位不重新加载正文，只改 `data-tier` 和注解可见性。

### 10.4 工作台

现有 `apps/reading/web/chapter.html` 的档位卡从覆盖率改成契约：

- 速览：`编译正文 · 核心 42/42 · 5–8 分钟`

工作台显示：

- 结构模型状态：未生成 / 已生成 / 过期；
- 四层状态：未生成 / 生成中 / 完成 / 失败；
- 预算估算：结构模型、四层、检索分开；
- 按钮：`生成结构模型`、`生成四档`、`只补速览`、`只补研究`；
- 源文变更时显示“需重建”，不静默复用旧层。

### 10.5 导出与打印

- 导出仍按档位单页。
- 速览导出附一个折叠的“原文全文”，保证离线可核对；正文比例仍按编译正文算。

## 12. 数据与接口

### 12.1 文件

```
<阅读根>/<uid>/ch/<nn>/
  chapter.html              # 旧路径，不改
  export/<tier>.html        # 旧路径，不改
  manifest.json             # 根 manifest，旧键不改
  annotation.json           # 旧路径保留
  editorial.json            # 旧路径保留
  depth/
    state.json              # 提交标记，最后写
    chapter_model.json
    ledger.json
    layers/
      skim.json
      standard.json
      deep.json
      research.json
    citations.json
    chapter.html
    export/<tier>.html
```

`depth/` 是一个原子单位，不把深度产物平铺到包根。`depth/chapter.html` 用 `../assets/` 引用根资源，不复制一份 `assets/`；这样旧包的资源路径不变，也不会因为复制产生两套图片。

### 12.2 包内所有权与 `Store.save()`

`Store.save()` 现在是整包 stage-and-swap，且只把 `edition/` 和 `agent-standard.html` 搬进新包（`src/bookcorpus/reading/store.py:145-183`，白名单在 `:167`）。深度包必须在同一层解决，否则旧路径重生成一次就会把 `depth/` 静默删掉。

给 `Store.save()` 增加可选 `depth` 参数，而不是在 Store 里读 feature flag：

- `depth is None`（annotation / editorial / 旧路径重跑）：若旧包已有 `depth/`，原样复制到新包；不创建、不读取、不校验。旧包没有 `depth/` 时，新包也没有。
- `depth is not None`（只有 `kind="depth"` 任务）：把完整的 `depth/` 写进 staging，校验通过后随整包一起替换；根 `chapter.html`、`export/`、`annotation.json`、`editorial.json`、`audit.json`、`edition/`、`agent-standard.html` 原样保留，根 `manifest.json` 最后写。
- 这样 annotation/editorial 重跑不会带走深度包；深度任务也不会覆盖根旧产物。`save_editorial()` 继续只写根 `editorial.json`，不碰 `depth/`。
- `depth/state.json` 是深度包的提交标记，最后写入；它记录 `source_sha256`、`chapter_model_sha`、`prompt_version`、`schema`、`status`；只有 layers 存在时才加 `layers_sha`。阶段 1 的 `status` 是 `model`，不提前写 `ready`。`chapter_model.json`、`ledger.json`、`layers/*.json` 先写，`state.json` 后写。
- 临时目录或 `state.json` 写失败：不替换旧 `depth/`，不写根 `manifest.json`。旧深度包继续可用，读路径按哈希判断为 `stale`，不把半成品当 `ready`。
- 深度任务不覆盖根 `annotation.json`、`editorial.json`、`chapter.html`、`export/`；这些仍归旧路径。

### 12.3 API 与草稿判定

- `READING_DEPTH` 在 `ReadingService` 初始化时解析一次，并传给 server；不在每个请求里重新读环境变量。
- **关闭时**：`GET /api/chapter/<uid>/<n>` 返回的键与现在完全一致，不出现 `depth`；`POST .../generate` 收到深度请求时返回 400；`_run_job()` 不进深度分支。
- **开启时（阶段 1）**：`chapter()` 先读 `depth/state.json`：缺失 → `depth.state="missing"`；`source_sha256` 不匹配 → `depth.state="stale"`；匹配且 `status="model"` → `depth.state="model"`，只附加 `depth.model` 与 `depth.ledger`。`depth.body/layers/citations` 属于 #3/#5，不在阶段 1 附加；只有 layers 存在时才校验并记录 `layers_sha`。
- `annotation.json` 缺失仍然只表示**旧路径草稿**。深度包有没有 `annotation.json` 与 `depth.state` 无关；不得因为缺 `annotation.json` 就把已有 `depth/` 的章标成草稿，也不得因为 `depth.state="ready"` 就把旧路径草稿改成正式。
- 阶段 1 不接深度生成路由，也不创建 `kind="depth"` 任务；`POST /api/chapter/<uid>/<n>/generate` 的深度分支与 `model → layers → render` 编排留到后续渲染/工作台票。
- 阶段 1 不接深度阅读路由；`GET /reader/<uid>/<n>` 与 `export/<tier>.html` 保持旧行为，深度 HTML 路由留到 #3/#5。
- `Store.tier_states()` 继续只看根 `export/<tier>.html`；深度层状态只走 `depth/state.json`，不混进 `tier_states()`。
- 不破坏旧字段；旧前端仍能读 `tiers` 的覆盖率字段，新前端读 `depth`。

## 15. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单元切得太碎/太粗 | 守恒账失真 | 金标校准；密度只警告；人工可改 |
| 模型把细节标成 core | 速览臃肿 | 金标 + 抽检；core 比例上限 40% 警告 |
| 模型把 core 标成 detail | 漏前提 | G10 核心覆盖 + 人工抽检；core 召回优先 |
| 摘要数字/专名错 | 信任崩塌 | G11 精确匹配；数字必须回原文 |
| LLM judge 误判 | 假通过 | 只做抽样；精确字段机器查；人工复核 |
| 检索来源质量差 | 研究档不可信 | `已核验` 精确率优先；宁少勿滥；provider 白名单 |
| 页面过重 | 阅读体验差 | 30K 拆速览；图预算；注预算；HTML 体积目标 |
| 叙事章不适合编译 | 速览失真 | 短章/文学章跳过速览，保留逐字三档；显示“本章不适合编译” |
| 旧包不兼容 | 回归 | feature flag；旧路径保留；新字段可选 |
| 成本超预算 | 生成失败 | 分层缓存；按需生成；沿用单章 $1 上限；先估后跑 |

## 16. 不做的

- 不让模型直接写四档 HTML。`agent_standard.py` 证明能写，但门禁只能查“原文在不在”，查不了“该在的命题在不在”。
- 不再用字符覆盖率当档位 KPI。它测长度，不测完整度。
- 不做四套视觉系统。四档共用一个阅读器，只换正文来源和注解密度。
- 不为每种图写一个渲染函数。先定七类语法，再让模型填数据。
- 不静默丢段。被压掉的单元至少留一行索引。
- 不把视觉读本并进四读。`edition` 继续独立；四读复用它的 content/gate 思路，不复用整页风格。
- 不做跨书知识库。深读只用本书；研究的外部材料按命题检索，不做全库 RAG。

## 17. 边界与默认

这些不是待问题，是默认选择；评审时可以直接反对：

- **文学/叙事章**：短章（<1200 字）和无 H2 的纯叙事章，速览先跳过，显示“本章不适合编译，建议标准档”。等金标跑通再决定是否做叙事模板。
- **检索 provider**：本期只定义接口 + `NullProvider`；具体 vendor 不在方案里锁定。配置了才启用，默认关闭。
- **引用有效期**：180 天。过期只标“引用较旧”，不自动重抓。
- **速览拆页**：源文 >30K 字，速览独立 `skim.html`；标准/深读/研究仍一页。>60K 字按 H2 分卷，另案处理。
- **术语表位置**：四读术语先放本文档；不塞进现有 `GLOSSARY.md`，因为它明确只覆盖视觉读本。方案确认后再决定是否拆 `GLOSSARY-MAP.md`。
- **旧路径退役**：新路径默认开启后保留一个版本；`tiers.project` 只做 fallback，不再新增功能。
