# 视觉读本决策记录（2026-11-07）

两条影响后续走向的取舍，记下原因与代价，避免后面翻烧饼。

## 决策一：视觉读本是独立第五产物，不变换四读

决定：每章视觉读本走 `/<uid>/<n>/edition` 与 `pack/edition/index.html`，
不进四读的档位体系，不动 `tiers.py` 的投影逻辑，标准档确认面板与
档位勾选框不增加"视觉版"选项。

因为：四读的对象是"读法"（检阅/扫读/深读/精研），投影同一份正文；
视觉读本的对象是"呈现"（版式 + 内容驱动图示），同一份正文的另一种
组织。两者联合有交叉表爆炸风险（4 档 × N 模板），且用户没有要求
替换四读；把视觉读本嵌进档位会让四读任务多一条模板分支，
跟着 api/editorial 的校验与 G9 门禁一起重新审计一遍，收益不抵风险。

代价：章节工作台多一张卡、`jobs` 里多一类任务、门禁 V 系列独立于
G 系列。页面骨架与 CSS 来源仍复用 render.py，不让两套样式漂移。

## 决策二：正文直通——模板只吃锚点，不做原文改写

决定：视觉读本沿用 chaptergen 验证过的做法——正文不改写，
模型只产出补充层。对存在"模板套写变动"风险的场景
（底噪强、块内含 HTML、提取噪声），一律以**原文可见的默认底**：
先把 SourceDocument 渲染成一页原文视图，再由 `content.json`
做渐进增强——结导航、要点卡、图示、回看单。模板不能直接命中
原文段落做删除、改写或重排，只能：（a）在锚点前/后插入新块，
（b）给已有块加装饰类（要点强调、序号徽标），
（c）由 V-gate 校验原文覆盖。

因为：chaptergen 阶段已经验证"正文逐字保留 + 内容 JSON 驱动组件"
能在 3 分钟内生成 B0003 级别的章节；而直接让模板拿走原文改造，
在 B0001（无标题纯叙事）、B0004（30 张表）上失败率高，无法逐章
兜底。原文直通保证任何书的任何章"至少不比纯文本差"，
`content.json` 生成的补充层是可跳过、可重跑、可独立校验的。

代价：图示位置只能出现在"锚点处"，不能像手排 HTML 那样把段落
拆开图文混排；这对大多数章节（段落粒度足够）可接受。

## 决策三：视觉任务在独立排队，不上拍卖系统/不做实时参数定制

决定：视觉读本生成走一条独立的 `JobQueue` 分类（`kind=edition`），
接受 `uid/n/model/effort`，不拍四读队列、不提供 per-chapter 参数
面板、不承诺并发度。

因为：生成一次 60–200 秒的 LLM 调用链，四读任务可能同时跑
（模型标注/编辑层生成更多），独立队列避免互相饿死；参数面板
在 xerox 单一模板上没有自适应空间，先不透露给用户。

代价：如果未来加入第二模板（lab/proof），模板适配的第一版先在
`content` 阶段给候选分数，用户确认，不放进任务参数。
