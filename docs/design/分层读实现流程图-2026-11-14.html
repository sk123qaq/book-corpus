流程 01 · 总览

全链路：一章 md 怎么变成一张深度页

输入books/<uid>/md/ 第 n 章 + 读法 表→输出工作区/阅读/<uid>/ch/<nn>/depth/chapter.html，外加 state.json 与五件层产物

01

章页

apps/reading/server.py:246

页面读 /api/chapter/<uid>/<n>，拿到原文块、当前读法、容量预检与五层状态。没有书级读法时，主按钮禁用并显示「先选一个读法 →」。

决策

先立读法再生成。没有读法就用兜底 argument 批量生成，等于把论证注加到小说上，返工比重选一次贵得多。

读数

读法值 4 个：narrative、argument、practical、reference；新工作区没有任何读法行时，禁用是正确空状态。

uid + n
02

裁决读法

service.py:712 · profile.py:290

章级覆写、书级默认、建议、兜底 argument 依次比较，产出 effective_mode 与 effective_source。章级覆写只在 source_sha256 匹配时生效。

决策

章级覆写绑定源文哈希。正文一改，旧判断先挂起，不把上一版文本的读法套到新版上。

读数

解析来源 4 档：chapter、book、suggestion、fallback；建议不写人账，也不参与过期。

effective_mode
03

提交

server.py:449 · service.py:1051

逐层按钮 POST /api/depth，主按钮 POST /api/jobs。两条路最终都进 submit_depth；后者对新章自动改写成五层任务。

决策

入口不同，队列同一份。主按钮不要求读者先理解五层，深度面板才暴露层选择。

读数

默认请求五层；已生成的层可保留，只补缺层；同章已有任务时返回 409 job_active。

layers + mode
04

容量预检

判定depth/preflight.py:95

用块数、分块数、预计输出 token、预计秒数判四条硬线。命中任一条就 422，不建任务。警告线只显示，不阻断。

决策

48,029 块的 B0041 著者序不可能在一次调用里变成合法 JSON。提交前 50 毫秒拒绝，比花 21 分钟失败便宜。

读数

B0001/01 15 块、1 分块、16,800 token、约 155 秒；5,034 块、51 分块、4,955,040 token、45,460 秒。

ok
05

排队

jobs.py:284 · service.py:519

任务带 kind=depth 与层清单进内存队列，同一 uid/n 只允许一个活跃任务。jobs.json 整表原子落盘。

决策

同章并发会让两份 depth/ 互相覆盖。冲突直接 409，不让读者猜哪份结果是最后的。

读数

max_workers=4；任务 id 形如 r-<10hex>；五步进度：切块、标注、校验、组档、渲染。

job
06

结构模型

depth/model.py:981 · disposition.py:286

按块切分，逐块缓存调用模型，合并后过 schema 与守恒审计，写 chapter_model.json 与 ledger.json。模型只提结构，处置账由纯函数生成。

决策

不让模型决定哪段该删。处置是确定的，同一模型重放结果一致，审计才能复算。

读数

每个分块最多 100 块，每次调用上限 96k token 输出；G10 要求未映射块为 0。

model + ledger
07

四层编译

service.py:1361

面板、速览、标准、深读依次生成。每层过校验就落一次盘并快照 state，中断后续跑只补缺层。

决策

五层不是一次事务。已完成层必须活过一次崩溃，否则一次失败会把前面花掉的调用全作废。

读数

速览一轮约 194 秒；标准层不调模型；深读缺失时页面仍可出，只是带一句「后续生成」。

layers
08

渲染

depth/render.py:624

把编译速览与全部原文块合成一页。标准、深读共用逐字正文，深读只叠加注解。页签为速览、标准、深读。

决策

两棵树共用块 id，速览里的锚点能跳回原文。压缩靠折叠与注解，不靠删块。

读数

渲染版本 v1；没有 JavaScript 时两棵树同时可见，有 JavaScript 按页签切换。

chapter.html

打开

结果server.py:557 · store.py:373

只有 route=depth 且 chapter.html 在盘上才发 200。源文或读法变了，返回 404 并给理由；旧包走 legacy。

决策

不发布过期页。读者不会看到与当前正文不一致的解读，也不会把旧注解当成新结论。

读数

404 理由三种：源文已改、读法已改、尚未生成；旧链接 ?tier=research 先 302 到深读。

流程 02 · 读法账

一本书的读法从哪里来，什么时候过期

输入读法 表 + 章级建议→输出effective_mode、effective_source、stale 理由

01

书级默认

service.py:702

书页「设本书默认」写 读法 表的 chapter='*' 行，同时清掉与新默认同模式的章级覆写。只写账，不提交任务。

决策

设默认不是生成命令。一本书换读法后，哪些章要重生成由章页决定，避免一次点击把全书几百章排队。

读数

一次事务写 1 行书级记录；同模式章级覆写一并删除，不同模式的覆写保留。

chapter='*'
02

章级覆写

service.py:720

三个动作：follow 删章级行，override 写章级行并记 source_sha256，book_default 写书级默认。章级行必须先有书级行。

决策

follow 是删除，不是写一条与书级相同的记录。读法账里只留真正的判断，不留下噪声行。

读数

缺书级行返回 409 reading_profile_required；覆写命中时 effective_source=chapter。

override
03

建议

service.py:712

规则先给建议，模型可用时再补一条；建议存在派生的 reading.json 或内存里，不写 读法 表。

决策

建议可以错，所以不进人账，也不参与过期判定。它只在没有书级默认时进入裁决。

读数

suggestion 来源的优先级低于书级默认，高于兜底 argument。

suggestion
04

裁决

profile.py:290

章级覆写（哈希匹配）> 书级默认 > 建议 > argument。章级哈希不匹配时记 chapter_override_pending，不生效。

决策

正文一改，旧章级判断先挂起，不直接删除。改回同一正文可以恢复，读者不用重选。

读数

返回 effective_mode、effective_source、panels、suggestion；待生效覆写单独列。

mode
05

过期判定

判定service.py:765 · store.py:351

深度页只认账上的 book 或 chapter 来源，不触发模型建议。每层 state.layer_mode 与当前 mode 比对，不一致或缺失都算 stale。

决策

过期按整包算，不按层算。换读法后旧层全部失效，避免一页里混两种注解口径。

读数

旧层没有 layer_mode 也算过期；改回原值且层记录一致时恢复。

stale / fresh
06

章节路由

store.py:373

ready 才走 depth。stale 直接 none 并报「源文已改」或「读法已改」。有旧 manifest 走 legacy，partial 报已生成层数。

决策

一条章只有一个打开路径。深度页和旧读本同时可开，读者不知道看的是哪份，锚点也对不上。

读数

partial 文案「已生成 N/5 层，缺 …」；model 文案「结构模型已建，深度页未出」。

流程 03 · 提交

按钮点下去，先过哪几道闸

输入章页按钮 + layers / tiers→输出202 job，或 409 / 422 / 400，或页面上的阻断卡

01

主按钮

web/chapter.html:168

没有书级读法时显示「先选一个读法 →」并禁用。有读法时显示「按「mode」生成读本 →」，点击 POST /api/jobs。

决策

读者先选读法，再选档位。读法决定注解口径，档位决定长度，两个选择不能混成一个下拉。

读数

按钮文案随 reading.book_mode 变化；无读法时禁用是页面行为，不是服务端 409 的替代。

POST /api/jobs
02

分流

server.py:339

开启深度且本章没有旧包时，新章自动走 submit_depth 五层；有旧 manifest 或现成深读产物时仍走旧 submit。

决策

新章默认深读路径，旧包不强行迁移。迁移失败会把一本能读的书变成不能读。

读数

判断含 depth_state 的 partial / missing 与盘上 depth/ 文件；partial 续跑只补缺层。

depth / legacy
03

读法闸

判定service.py:753

先查书级行。没有就 409 reading_profile_required，错误体带 uid。这个检查在预检之前。

决策

读法缺失是配置问题，源文过大是输入问题。先报配置，读者知道下一步点哪，不会被 422 的拆分建议带偏。

读数

409 在 422 之前；两者都不建任务。

有读法
04

补齐结构层

service.py:1051

submit_depth 按需把 model 插进请求：源文或读法变了而结构层是旧的，或盘上没有结构模型、显式 rebuild_model。

决策

读法换了却拿旧模型编译新层，注解口径会对不上。结构层必须跟读法一起重做。

读数

请求 model 时另查模型配置；缺 key 返回 400 MissingConfigError。

blocks + plans
05

容量闸

判定depth/preflight.py:95

硬线 5,000 块、100 分块、1,000,000 输出 token、7,200 秒。警告线 1,000 块、20 分块、1 小时、单块超过 100 块。警告只显示，不阻断。

决策

阈值取 2 小时预算和 109 token/s 的实测速度。780 块是上限，推荐拆到 500 块，约 1.3 小时，给模型变慢留余量。

读数

估算式 ceil((分块×2,000 + 块×800)×1.2)，秒数再除 109；B0001/01 估 16,800 token、155 秒。

通过
06a

入队

service.py:1077

预检结果写事件 preflight_gate，任务进队列，页面拿到 202 与任务 id。

决策

警告不阻断。1,000 块以上的章会显示「约 N 分钟」，让读者自己决定等不等。

读数

同章冲突 409 job_active；档位已有旧包 409 pack_exists；深度关闭 400。

阻断
06b

422 不建任务

web/chapter.html:433

返回 source_too_large 与 remediation。章页把预检行切到 blocked，显示内联阻断卡，逐层按钮禁用。

决策

主按钮不提前禁用，点了才看到完整的阻断理由。逐层面板提前禁用，避免读者以为选了层就能绕过。

读数

阻断后 GET /api/jobs 仍为空；B0001 追加后第 2 章 5,034 块，预计 45,460 秒。

全选 / 部分选

选择层

web/chapter.html:414

默认「生成全部五层」。部分勾选显示「生成所选层（保留 N 层）」，一层不选显示「没有要生成的层」。另有「只重建结构模型」。

保留已生成层是默认语义。重跑不用全量付费，也不必先删旧页。

流程 04 · 任务

一个深度任务怎么跑，失败后怎么续

输入{uid, n, layers, model, effort}→输出state.json 与五件层文件，或 blocked / failed + 失败现场

01

入队

service.py:1051 · jobs.py:284

冲突检查在同一把提交锁里做。同章已有 queued 或运行中任务时返回 409 与冲突列表。

决策

同一章只允许一个写者，不同章可以并行。写者冲突不能靠重试解决，只能由队列拒绝。

读数

max_workers=4；任务 id r-<10hex>；jobs.json 整表原子写，服务重启后从盘上恢复。

queued
02

起跑

service.py:1361

重新读原文并再跑一次预检。排队期间源文变大到超限，任务在这里转 blocked。mode 取 effective_mode，缺省 argument。

决策

提交时的预检不是最终判据。起跑时以盘上源文为准，事件链里能看到两次 gate。

读数

起跑再评估一次；超限不写失败现场，只发 blocked 与 remediation。

chunking
03

能不能跳过

判定service.py:1428

逐层判断：文件在盘上、layer_model_sha 匹配、layer_mode 匹配、layer_request 的 model 与 effort 匹配、没有 degraded。任一不满足就重做。

决策

续跑只补缺层，不重花已成功的调用。旧层缺 layer_mode 不跳过，因为它不知道自己是按哪种读法生成的。

读数

跳过层发 layers_skipped 事件；任务结果带 skipped 列表。

新鲜
04a

保留

service.py:1435

层文件不重写，state 里原有 sha、usage、mode 一并保留。后续层如果需要这份产物，直接从盘上读。

缺失 / 过期
04b

重做

service.py:1596

按顺序补 panels、skim、standard、deep。每层过校验后立刻快照，不等整个任务结束。

structure rebuilt
05

结构重生成

service.py:1515

结构模型重建后，本次没有请求的其它层 layer_model_sha 置 __stale__，不计入 ready。下一次任务会重做它们。

决策

新结构下的旧面板与旧速览不能冒充新鲜层。__stale__ 是内部哨兵，不写进页面。

读数

本次只重建 model 时，状态回 model；其它层文件还在，但不再算 ready。

层循环
06

失败分类

jobs.py:376

source_too_large 记 blocked，不写失败现场，不给重试按钮。其它异常记 failed，写 工作区/阅读/failures/<job-id>-<layer>.json，带栈、层与原始 payload。

决策

阻断是输入不可执行，失败是实现或模型出错。两种账不能混，否则操作员会把「拆章」和「重跑模型」搞反。

读数

payload 上限 200 KB，超出记 payload_omitted；B0019-08 的账是 r-0b75993eeb-model.json。

done / partial
07

收尾

service.py:1718

决策

只有速览新鲜才渲染，避免页面引用旧速览。partial 也保留已生成层，下次续跑。

读数

渲染步骤记「渲染」，进度 90%；任务返回 {status, pack_id, skipped, layers_ready}。

流程 05 · 结构模型

长章怎么切，模型返回什么，账怎么守恒

输入块列表 B01… + 读法→输出chapter_model.json 与 ledger.json，每块都有处置

01

切块

reading/mdparse.py:105

md 按段落、标题、图片切成块，id 顺序 B01、B02…。同一份源文重复解析得到同一组 id；源文一变，source_sha256 变，缓存和旧层一起失效。

决策

块 id 不随机，缓存才能按块命中。用内容哈希做 id 会让每次改一个错字就全章缓存失效。

读数

块自带汉字数 chars；预检另按文本长度算总量，两个口径不要互换。

blocks
02

要切吗

判定depth/model.py:182

总字符不超过 18,000 且块数不超过 100 时一次调用。否则先按 H2 分组，再按字符与块数切，chunk_id 是 0000-0032 这样的范围。

决策

按块数切，不按字符切。块越多，JSON 的条目与局部 id 越多，输出增长比字符快；18,000 字不一定比 100 块更省。

读数

84.5% 的章总块数不超过 100，一次调用完成；总块数 p90 是 131，切两块。

不超
03a

一次调用

model.py:845

整章一次请求，输出上限 96k token。返回的 uid 必须与本章一致。

超了
03b

逐块调用

model.py:223

每块单独读缓存、单独调用。unit id 带 C<chunk_id>- 前缀，合并后必须回到同一个 uid。

truncated
04

截断兜底

model.py:822

输出截断时只把这一块二分，最多两层。事件记 truncated、chunk_split、chunk_retry。已成功的块留在缓存里。

决策

一块截断不拖累其它块。整章重试会把已经成功的 80% 再付一次钱，还会把稳定输出变成随机输出。

读数

100 块乘 800 token 加 2,000 开销约 82k；乘 1.2 安全系数后 98.4k，96k 仍可能截断，靠二分兜底。

merge
05

合并校验

model.py:validate_chapter_model

合并各块 parts，校验 schema、uid、章节号、块引用。分块时 unit id 带 C<范围>- 前缀，合并后必须回到同一个 uid。

决策

模型返回的 uid 不一致直接判失败，不做猜测修复。猜错会把上一章的结构挂到这一章。

读数

B0019-08 的失败原文「uid 不一致：B0019-C04 != B0019」，连续两次拒收。

model
06

处置账

disposition.py:242 · :286

按三档给每个 unit 定处置：verbatim、condensed、indexed、omitted。omitted 只允许 duplicate_of 指向的重复单元。

决策

处置是纯函数，同一模型重放结果一致。模型不参与决定删哪段，审计才能逐条复算。

读数

G10 查核心覆盖、硬信息覆盖、未映射块为 0、省略项有重复锚点；任一不过就不写结构层。

service.py:1493

决策

结构层先落盘，后续面板、速览都能在失败后复用。结构层审计失败不写文件，旧包保留。

读数

五件产物里结构层最先完成；后续四层都引用同一个 chapter_model_sha。

流程 06 · 四层编译

面板、速览、标准、深读各做什么，哪一层会拦任务

输入model + ledger + blocks + mode→输出panels.json、skim.json、standard.json、deep.json

01

面板 A1

depth/panels.py:326

按 mode 选面板类型，最多 6 个，每个最多 8 条，条目不超 120 字，每条带块锚点。模型调用失败时降级为空面板并记 layer_degraded。

决策

面板不是第二份正文，没有锚点的条目不能进页面。降级后 chapter.html 虽会写出，状态仍是 partial，章节路由不端出，等面板补成才发布。

读数

validate_panels 的 schema 错误会让任务失败；audit_panels 只记录，不单独拦任务。

panels
02

速览 A1′

depth/skim.py:767

按 mode 把模型编译成 scenes 或 claims。原文汉字少于 1,200 时标 supported=false。非叙事档查 15%–25% 比例闸门。

决策

叙事档不查比例，只查场景与上限。用固定比例卡叙事会逼模型删情节，读起来像摘要而不是小说。

读数

JSON 重试 1 次，质量修复 1 次；本轮实测生成约 194 秒；audit_skim 的错误会让任务失败。

skim
03

标准 A2

depth/standard.py:339

从模型与原文确定性投影：章节导语、术语、注释、折叠、图。不调模型。G12 发现坏图先删，再补一张无数字的章级结构图。

决策

标准档必须能在模型不变时复现。图错了删图，不带着错数字上页面，也不因为一张图让整章生成失败。

读数

每章最多 3 张节图；标准层不产生模型费用；审计状态写入层文件，任务不因 G12 失败。

standard
04

深读 A3

depth/deep.py:557

按 mode 生成论证注、叙事注、实用注或资料注。最多 12 条，每节最多 3 条，每条 80–200 字。

决策

注解只加在逐字正文上，不复制原文。没有注解也保留原文，深读层缺失不是页面失败。

读数

深读缺失时页面提示「深读注解将在后续生成。」；audit_deep 错误会让任务失败。

validate + audit
05

哪层会拦任务

判定validate_* · audit_*

每层先 validate 再 audit。速览与深读的 audit errors 直接让任务失败；面板 schema 错误失败，模型失败降级；标准层记录 audit 状态，不因 G12 失败。

决策

不同层的失败代价不同，闸门也不该一刀切。结构错误必须停，图错可以删，面板缺失可以等。

读数

失败不发布半成品；旧 depth/ 保留；每层快照独立，失败前的层仍然可用。

两套「五」
06

五层对页

depth/render.py:624

生成账五件是结构、面板、速览、标准、深读。页面五层是 CH 原文、A1 图文总览、A1′ 速览、A2 标准、A3 深读。结构模型不是阅读层。

决策

两套「五」分开叫，避免把 chapter_model 当成第五个页签。读者只看到三个页签，结构只在生成账里。

读数

页面页签 3 个：速览、标准、深读；面板在速览页签与标准/深读原文树各出现一次，由 CSS 控制可见性。

流程 07 · 页面

01

渲染判据

判定service.py:1718

速览新鲜且 layer_model_sha[skim] 等于 chapter_model_sha，并且本次请求或跳过集合里包含 panels、skim、standard、deep 任一层，才渲染。

决策

只重建结构模型不重渲染。页面里的速览必须来自当前模型，不能拿旧结构拼新页面。

读数

02

两棵树

depth/render.py:639

编译树放速览与面板，原文树放全部块。标准、深读共用原文，标准叠加导语、术语、注释、折叠；深读叠加注解与链条。

决策

原文块一个不丢。压缩靠折叠与注解，不靠删块，读者随时能回到逐字文本。

读数

tabs
03

页签

depth/render.py:608

三个页签：速览「编译 · 5–8 分钟」、标准「逐字原文」、深读「逐字 · 论证注」。没有 JavaScript 时两棵树同时可见。

决策

先给读得完的版本，再给逐字回查。页签不改变内容，只改变可见性。

读数

深读缺失时只显示提示，不空白；页脚 colophon 记 prompt_version、生成时间、渲染版本。

swap
04

落盘交换

store.py:275

先写 stage 的结构、账、层文件，state.json 最后写。然后目录交换 depth/，旧目录做 backup。崩溃时启动 heal_pending_swaps 把 backup 放回。

决策

state 是提交点。state 没换，旧页就还是旧页。备份名每次唯一，两个进程同章也不会互删。

读数

stage 与 backup 都带随机后缀；启动日志报告 healed / cleaned；只剩 stage 时不动它，避免删掉唯一的包。
