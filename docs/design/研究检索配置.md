# 研究检索配置

研究档的检索是可选能力。默认 `READING_SEARCH_PROVIDER=none`：只生成研究议程，不联网，不把模型记忆写成外部事实。

## .env（推荐）

CLI 启动时会依次读取：

1. `BOOK_CORPUS_ENV` 指向的文件；
2. 当前目录 `.env`；
3. `~/.config/book-corpus/.env`。

真实环境变量优先，`.env` 只补缺失的键，不覆盖已有变量。最简单的配置：

```bash
# ~/.config/book-corpus/.env
FIRECRAWL_API_KEY=fc-...
READING_SEARCH_PROVIDER=auto
READING_FETCH_PROVIDER=firecrawl
```

不需要 `export`，也不需要重启 pi。

## 提供方

| `READING_SEARCH_PROVIDER` | 搜索接口 | 需要的 key | 默认地址 |
| --- | --- | --- | --- |
| `none` | 不检索 | 无 | — |
| `auto` | 按 Tavily > Brave > Serper > Firecrawl 的顺序选第一个有 key 的 | 对应 key | — |
| `tavily` | `POST /search` | `TAVILY_API_KEY` | `https://api.tavily.com` |
| `brave` | `GET /res/v1/web/search` | `BRAVE_API_KEY` | `https://api.search.brave.com` |
| `serper` | `POST /search` | `SERPER_API_KEY` | `https://google.serper.dev` |
| `firecrawl` | `POST /v2/search` | `FIRECRAWL_API_KEY` | `https://api.firecrawl.dev` |
| `http` | 自定义 `POST {"query","limit"}` | 可选 `READING_SEARCH_API_KEY` | `READING_SEARCH_ENDPOINT` |

`auto` 只在有 key 时选择；没有 key 就退回 `none`，不会报错。

## 只配一个 Firecrawl key

Firecrawl 同时提供搜索和抓页。最省事的配法：

```dotenv
# ~/.config/book-corpus/.env
FIRECRAWL_API_KEY=fc-...
READING_SEARCH_PROVIDER=firecrawl
READING_FETCH_PROVIDER=firecrawl
```

`READING_FETCH_PROVIDER=firecrawl` 让抓页也走 Firecrawl 的 `/v2/scrape`，返回 Markdown；不设时默认本地 `HttpPageFetcher`，只走普通 HTTP。

## 复用 pi-web-access 的配置

如果已经通过 pi 的 web-access 配过 key，可以直接复用 `~/.pi/agent/web-search.json`：

```json
{
  "tavilyApiKey": "tvly-...",
  "braveApiKey": "brv-...",
  "serperApiKey": "ser-...",
  "firecrawlApiKey": "fc-...",
  "searchProvider": "firecrawl",
  "fetchProvider": "firecrawl"
}
```

`searchProvider` / `fetchProvider` 是可选字段；不写时仍按环境变量或默认值。这样只靠一个配置文件也能启用，不需要 export：

```bash
export READING_SEARCH_PROVIDER=firecrawl   # 可省略
```

也可以用 `PI_WEB_SEARCH_CONFIG=/path/to/web-search.json` 指定别的文件。环境变量优先于配置文件。

## 自定义地址

需要代理、网关或 SearXNG 适配层时：

```bash
export READING_SEARCH_PROVIDER=http
export READING_SEARCH_ENDPOINT="http://127.0.0.1:8080/search"
export READING_SEARCH_API_KEY="optional"
```

该端点必须接收：

```json
{"query": "...", "limit": 2}
```

并返回：

```json
{"results": [{"url": "...", "title": "...", "snippet": "..."}]}
```

## 抓页

默认 `HttpPageFetcher`：只允许 http/https，拒绝私网/环回/链路本地地址，限制重定向、响应大小和 content-type，返回正文文本。

`READING_FETCH_PROVIDER=firecrawl` 改用 Firecrawl 的 `/v2/scrape`，适合 JS 重、反爬强或正文抽取差的页面。Firecrawl 抓页失败会降级为 `fetch_failed`，不会中断章节生成。

## 失败语义

- 没有 provider：所有判断 `not_searched`，研究页只显示议程。
- 搜索失败：该查询 `status=error`，相关判断 `not_found` 或 `unverified`。
- 抓页失败：该 URL 记 `fetch_failed`，继续处理其他命中。
- 核验不通过：引用不写入 `verified`，判断保留但标 `unverified`。
- `已核验` 必须有 URL、逐字支持引文和访问时间；有争议的经验性判断需要两个独立域名。
- 超过 180 天的引用只给 stale 提示，不自动删除。
