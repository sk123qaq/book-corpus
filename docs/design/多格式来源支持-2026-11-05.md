# 多格式来源支持（txt / Word / Excel / PPT / md）

状态：implemented · 2026-11-05
验收：`uv run --frozen pytest tests/test_docs_gate.py tests/test_docs_plan.py -q`

## 1. 目标

收件箱与导入只接受 11 种后缀：`epub mobi azw3 azw pdf txt md docx xlsx xls pptx`。其余（含 `.doc`、`.ppt`、`.csv`、`.djvu`）在收件箱里不显示、上传被拒。

导入成功后：

1. `txt / docx / xlsx / xls / pptx` 自动转成 Markdown，产物落 `books/<uid>/md/`（README + `<书名>.md` + `.manifest.json` + 可选 `images/`），**不分章**（`chapters=1`）。
2. 源文件本身是 `.md`：原样复制到 `md/<书名>.md`，只补 README 与 manifest，不重排正文。
3. 转换任务由 `import.apply` 成功后在后台自动排入；「新书导入」页显示进度、逐本状态与失败重试。
4. 自动链同时覆盖「库中遗漏的 doc 类旧账」（补转），页面显示「本次新书 N / 补转 M」，M=0 时不显示补转字样。
5. 覆盖规则：manifest 里的源 sha 与当前源一致 → 跳过；不一致 → 旧 `md/` 整目录移到 `工作区/批次/覆盖-<时间戳>/<uid>/` 备份后重生成。
6. 失败隔离：单本失败不影响其他书；整任务状态为 failed、摘要「完成 7/9，失败 2」，失败行可单本重试。单本上限 200 MB / 300 秒，超限直接失败并写明原因。
7. 编码：txt 先 UTF-8；charset-normalizer 置信度 <0.5 时依次试 GB18030、UTF-8(errors=replace)，manifest 记 `charset` 与 `charset_fallback`。

## 2. 不做

- `.doc` / `.ppt` / `.djvu` / `.csv` 的转换；不改 PDF 管线；不拆章；不做 OCR；不提供「每本一个 job」；不把逐本状态写进 `derived` 表。

## 3. 架构（Data over API）

### 3.1 一个 job，两条命令 + 重建

`docs.run`（写任务）由 `_finalize` 在 `import.apply` 成功后自动排入，命令序列：

1. `docs_to_md.py plan --root <root> --job-dir <job> [--applied <apply-job>/applied.json] [--only B0001,B0002]`
2. `docs_to_md.py convert --root <root> --job-dir <job>`
3. `build_library.py --emit-json`
4. `gen_book_catalog.py`

`convert` 遇到单本失败只记 report，进程仍返回 0，保证第 3、4 步执行；只有基础设施错误（job 目录不可写、report 无法生成）才非 0。`gate_docs` 读 `report.json` 判定成败。

### 3.2 job 目录文件（唯一真相）

```
工作区/运维/jobs/<job_id>/
  worklist.json     plan 产物：[{uid,title,format,path,sha256,reason:"new|backfill",skipped?}]
  progress.json     convert 每本前后原子写：{phase,done,total,current,updated_at}
  report.json       convert 结束写：见下
  books/<uid>.json  逐本明细（同 report.items 一行）
  applied.json      仅 import.apply 有：{"version":1,"conflicts":0,"applied":[{uid,file,format,action}],"failed":[]}
  docs-seed.json    仅 import.apply 有：{"docs_job":"<id>"} 供前端接棒
```

`report.json`：

```json
{"version":1,"job_id":"20261105-111530-a1b2","generated_at":"...",
 "scope":{"new":3,"backfill":5},
 "summary":{"total":8,"done":6,"skipped":1,"failed":1},
 "items":[{"uid":"B0102","title":"某书","format":"docx","status":"done|skipped|failed",
   "reason":"","md":"books/B0102/md/某书.md","chars":183422,"images":7,"md_bytes":201133,
   "charset":"utf-8","charset_fallback":false,"elapsed_ms":18321,
   "backup":"工作区/批次/覆盖-20261105-111530/B0102","error":""}]}
```

失败 `reason` 枚举：`too-large / timeout / convert-error / empty-output / source-missing / source-changed / venv-missing / unsupported`。

### 3.3 落地契约（与 PDF 单文件一致）

- `README.md`：复用 `pdf_ocr_to_md.py:169` 的 `write_readme(out_dir, title, collection, author, date, chapters=1, images, source_name, toc=[(title, md_file)], unlisted="- 无（整本单文件）")`。
- 正文：`md/<sanitize_filename(title, uid)>.md`，front matter `title/author/source/pages` 可选；正文必须有一级标题（`# 书名`），原文件已有 H1 时保留。
- `.manifest.json`：`uid, method, tool_version, source, source_sha256, chapters:1, bytes, chars, images, images_dropped, structure:"single", single_file:true, charset, charset_fallback, generated_at, assembler:"docs_to_md.py", verified:false`。
  - `source_sha256` 必须是**源文件** sha（`v_pending_md` 用它比对）。
  - `method` 取值 `markitdown-docx / markitdown-xlsx / markitdown-xls / markitdown-pptx / text-utf8 / text-gb18030 / copy-md`；不得留空，否则 `build_library.py:255` 回落 `ebook-to-md`。
  - `tool_version`：`markitdown 0.1.9` 或 `text 1` / `copy 1`。
- 原子落地：先写 `books/<uid>/.md-build-<pid>/`，成功后旧 `md/` rename 到备份区，再 `os.rename` 临时目录为 `md/`。**绝不直接写 `md/`**（`build_library.py:252` 目录存在即 done）。
- 正文为空 → `convert-error`，删临时目录，不动旧 `md/`。

### 3.4 图片

markitdown 默认把图片内联为 data URI。worker 落盘时扫描 `![alt](data:image/<ext>;base64,...)` 与 `<img src="data:...">`，写到 `images/img-<n>.<ext>`，改成相对链接；解不出就整段删除并累加 `images_dropped`。图片计数写 manifest 与 report。

### 3.5 环境隔离

- 新模块 `src/bookcorpus/docenv.py`，照抄 `pdfenv.py`：`REQUIREMENTS = ("markitdown[docx,xlsx,xls,pptx]==0.1.9",)`、`DISABLE_ENV="BOOKS_NO_DOCS_VENV"`、`venv_dir(root) = 工作区/.venv-docs`、`python()/create()/versions()/disabled()`。
- 同目录加 `requirements-docs.txt`（人读副本），测试校验二者一致。
- `docs_to_md.py convert` 开始时 `docenv.ensure()`：缺 venv 就建（900s 超时，日志打印）；装不上 → 整个 job 报 `venv-missing`。`--worker` 由 venv python 调用。
- `book-corpus venv` 同时建 PDF 与 docs 环境；`doctor` 增一行 `docs-venv`（缺只 warn）。

### 3.6 脚本接口

```
docs_to_md.py plan    --root R --job-dir J [--applied P] [--only B0001,B0002]
docs_to_md.py convert --root R --job-dir J
docs_to_md.py worker  --source S --format F --out DIR     # 仅 venv 内调用
```

- `plan`：只读 `build/library.db`。backfill = `v_pending_md`（`build_library.py:72`）中主源格式 ∈ DOC_FORMATS；new = `--applied` 中 action=add 且格式 ∈ DOC_FORMATS（用真 uid）；`--only` 覆盖前两者；按 uid 排序去重；写 `worklist.json`。跳过：`md/` 存在且 manifest 源 sha 相同 → worklist 标 `skipped`（不占名额）。
- `convert`：逐本处理。格式分派：`txt/md` 主进程；`docx/xlsx/xls/pptx` 起 venv 子进程（`start_new_session=True`，300s 超时后 `os.killpg` 杀整组）。父进程只信子进程 stdout 的一行 JSON：`{ok,chars,images,images_dropped,warnings,error}`。
- 200 MB 在起子进程前判断；超限 `too-large`。
- `convert` 结束时写 `report.json`、清 `progress.json.current`、追加 `工作区/批次/docs/journal.tsv`（`ts uid status reason`）。

### 3.7 服务端

- `server.py:743` `KINDS` 增 `"docs.run": {"readonly": False, "gate": "gate_docs"}`（必须可写：它写 `books/<uid>/md/`，并与导入串行）。
- 新 `gate_docs`：`report.json` 缺失 → failed；`summary.failed > 0` → failed 且摘要「完成 N/M，失败 K」；否则 succeeded。
- `_finalize`（`server.py:1086`）：`import.apply` succeeded 时读 job 根 `applied.json`，若含 DOC_FORMATS 行则提交 `docs.run` 并把新 job id 写回 `docs-seed.json`。幂等：`docs-seed.json` 已存在则跳过。
- `ingest.py apply` 增 `--result <path>`，写 `{"version":1,"conflicts":...,"applied":[{uid,file,format,action}],"failed":[...]}`；`api_import_apply` 命令加 `--result <job>/applied.json`。
- 新端点：
  - `POST /api/docs/run` `{uids?:[]}` → 409 if writer busy（复用 `writer_busy` 逻辑）；提交 `docs.run`（带 `--only`）。
  - `GET /api/docs/report?job_id=` → `{ok,job_id,state,progress,report}`；缺 job_id 取最近 docs.run。
  - `GET /api/job` 对 `import.apply` 附带 `docs_job`（读 `docs-seed.json`）。
- `api_job_files` 白名单（`server.py:2430`）加 `worklist.json/progress.json/report.json/applied.json/docs-seed.json` 与 `books/<uid>.json`。
- `api_upload`（`:2592`）与 `App.inbox`、`ingest.scan` 共用 `lib_common` 的 `ACCEPT_EXTS` / `REJECT_EXTS`；上传非白名单返回 400。
- `WRITE_ROUTES` 加 `/api/docs/run`；路由表挂号。

### 3.8 前端（新书导入页）

- 导入页投递区文案 + `accept=".epub,.mobi,.azw3,.azw,.pdf,.txt,.md,.docx,.xlsx,.xls,.pptx"`。
- 新增 `docsCard`：显示「本次新书 N / 补转 M」、总进度 N/M、逐本行（书名、格式、状态、耗时、字数、失败原因）、失败行「重试」按钮（`POST /api/docs/run {uids:[...]}`）。
- 数据：`GET /api/docs/report`（2.5s 轮询，直到 job 结算）；无 docs 任务时整卡隐藏。
- 轮询复用现有 `watchJob` / tick 机制，局部重绘，不整页刷新。

### 3.9 格式与排名（ingest.py:43）

```
FORMATS = {epub:3, mobi:2, azw3:2, azw:2, pdf:1, docx:1, xlsx:1, xls:1, pptx:1, md:1, txt:0}
```

- `azw` 补 2（现状漏了，rank 0）。
- 新格式 rank 1：新书直接 add；与已有 epub 同名落 `review`（人工选换源），不自动替换。
- `scan` 用白名单，不再静默接受未知格式；保留 `readme.md/readme.txt` 跳过并在日志里列数量。
- `lib_common.py:74` `EXT` 增 `.docx/.xlsx/.xls/.pptx/.md`；新增 `DOC_FORMATS` / `ACCEPT_EXTS` / `REJECT_EXTS` 单一来源。
- `doc_numbers.py` 的 `PENDING_KEYS` 去掉 `djvu`，加 doc 格式（待转口径随白名单走），测试随之更新。

## 5. 必须守住的坑

1. `source_rank` 静默 0 → 未知格式落 review，整批 apply exit 2；白名单 + FORMATS 同步 + 显式未知格式守卫。
2. `build_library.py:252` 目录存在即 done → 必须临时目录 + rename。
3. manifest 的 `source_sha256` 写源文件 sha，`method` 不能空，`generated_at` 不在 rebuild 时刷新。
4. `free_path` 会给 `md/<书名>.md` 加 `-2`，造成两内容文件 → 用 `install_collection.py` 的整目录替换模式。
5. uid 只信 `applied.json`，不信 plan.json。
6. 磁盘上的 `md/` 若无 manifest → 不跳过，重生成并备份。
7. `tables/.ingest.lock` 陈旧会让 apply 直接退出（不在本任务修，但验收时清干净）。
8. docs.run 是写任务，长批次独占写锁；前端对 409 给出「有任务在跑」提示。
9. xls 依赖 xlrd 必须进 extras；worker 里 import 失败要回 `convert-error` 而不是崩栈。
10. 生成 md 的超大 data URI（>50 MB）记 warning，但仍落盘抽图。

## 6. 任务拆分

- **T1 后端核心**（一个写者）：`docenv.py`、`docs_to_md.py`、manifest/README、图片抽取、编码、限制、原子落地、备份、journal；`ingest.py` 格式/白名单/`--result`；`lib_common` 常量；测试。
- **T2 服务端接线**：KINDS/gate_docs/_finalize 自动链/端点/暂存白名单/上传过滤；对应测试。
- **T3 前端**：导入页卡片、accept、轮询、重试；文案与 CONTRACT/AGENTS 同步。
- **T4 验收**：真实样本、临时书库副本、端到端、verify/audit/pytest/ruff，产出证据。

T1 先落地并自测通过后再做 T2；T2 合并后做 T3；T4 独立跑并只报告，不顺手改代码（发现问题回给 T1/T2 修复）。
