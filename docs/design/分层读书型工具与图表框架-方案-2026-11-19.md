# 分层读书型工具与图表框架方案

状态：proposed · 2026-11-19

## 1. 背景与要解决的问题

当前 `book-corpus` 的两条核心主线已打通：
- **书库检索（`apps/demo/`，8765）**：跨库找书、找段、带证据流式回答，并可通过 `/open` 精准落入阅读页段落。
- **分层读（`apps/reading/`，8771）**：章节 100% 正文直出，提供知识地图、核心术语与划词伴读工具（`diagram` / `explain` / `translate` / `critique` / `ask`）。

在进一步丰富“分层读”辅助工具时，对照《如何阅读一本书》的阅读方法论与当前代码实现（截至 2026-11-19），存在两处结构性短板：

1. **工具“千书一面”，未按阅读机制差异化**：
   2026-11-16 重构后，代码全面撤下了强阻塞式的“读法工单”，但同时把所有书的伴读提示词压成了同一套通用模板。小说、历史、哲学、科学、社科与实用书面对的核心阅读难点完全不同（如实用书重动作转化、哲学书重定义辨析与逻辑推演、历史书重多视角平行时间线、社科重因果回路与术语边界），需要按书型提供有针对性的图表与扩展知识。
2. **图表“框架泛化 + 布局简陋”，导致模型不稳定且观感粗糙**：
   目前 `src/bookcorpus/reading/diagrams.py` 与 `service.py` 已经采用了“模型吐 JSON → 脚本渲染 HTML/SVG”的正确方向，但实际落地过于粗糙：
   - **Schema 过度合并**：`tree / network / argument / flow / timeline` 五种图族共用同一个 `{nodes, edges}` 结构，模型缺乏图型专属字段约束（没有时间泳道、没有正负反馈极性、没有坐标曲线、没有论点角色），容易自由发挥或退化。
   - **布局算法缺位**：`_node_svg()` 仅按 3 列固定网格硬排节点（`divmod(idx, cols)`）再连直线，节点稍多即连线交叉、文本截断、排版呆板，缺乏真正的图论自动布局与可视化图表组件。
   - **原文锚点回链断裂**：划词图解的节点未强制携带 `block`（`B01..Bnn`），前端 `chapter.js` 也未将图内节点点击绑定到段落跳转（`focusBlock`）。

## 2. 核心决策一：书的分类要不要改？在哪一层处理？

### 2.1 结论：不重改底层人账，在“分层读消费侧”新增一层轻映射

**不要推翻或重分现有的 `tables/ledger.db:分类`（11 大类 / 46 小类学科词表）**，理由如下：
1. **服务目标不同**：人账 `分类` 是面向**藏书管理、检索过滤、PDF 分诊与书目导航**的“学科/题材分类”，契合本库实际语料结构（1,956 本书中 1,418 本为文学，另有大量游戏设定集、古建图录、影视漫画）。
2. **阅读维度跨学科且可切换**：同一本书的不同章节往往需要不同读法（如《万历十五年》既是历史叙事又包含制度结构分析），把《如何阅读一本书》的阅读法写死进全库人账或物理目录，维护成本高且容易打架。
3. **历史经验教训**：此前 `读法` 表下线（参见 [阅读页重构方案](阅读页重构-正文伴读与工具台-2026-11-15.md)）的核心原因，是把分类做成了**阻塞直读的审批工单**，而不是“不该区分书型”。

## 3. 核心决策二：分层读工具体系与“固定骨架 + JSON 填槽”设计

严格遵循三条原则：**单图只解决一个核心阅读痛点**、**节点必带 `blocks` 原文锚点可点击回溯**、**用“对比视角”替代“标准答案”**（所有补充知识严格标记 `[原文]` 与 `[补充]`）。

### 3.1 通用底座 + 书型专属工具矩阵

章节页保留现有 4 个通用划词动作（`explain` 讲人话/举例、`translate` 译注还原、`critique` 拆解前提、`ask` 自由追问），同时将**“图解此段（`diagram`）”升级为多蓝图引擎**，并在工具栏/抽屉按当前 `read_type` 动态置顶 **专属图表蓝图** 与 **专属扩展动作**：

| 阅读策略 | 置顶专属图表蓝图（Blueprint） | 专属扩展动作 / 卡片（Extension Action） | 解决的核心痛点 |
|---|---|---|---|
| **实用型** (`practical`) | 1. `flow_swimlane`（SOP 流程 / 泳道步骤图）<br>2. `decision_tree`（条件分支决策树）<br>3. `quadrant_matrix`（优先级 / 成本-收益四象限） | • **行动自检清单（Checklist）**：产出可勾选步骤 + 失效边界/踩坑提示<br>• **模板提取卡**：抽成可套用的公式/话术/评估表 | 防止“看懂了却不知何时用、怎么落地” |
| **想象文学** (`literature`) | 1. `relation_graph`（人物阵营与关系演变图谱）<br>2. `tension_curve`（章节叙事张力 / 情感曲线）<br>3. `spatial_route`（虚构空间/角色迁徙动线拓扑图） | • **意象与隐喻词典**（尤重 `poetry`）：解析高频意象、韵律节奏与情感冲突<br>• **舞台与潜台词提示**（尤重 `drama`）：补足动作/神态/舞台调度提示 | 避免用“找论点”破坏沉浸感，帮助把握人物张力与象征系统 |
| **历史书** (`history`) | 1. `parallel_timeline`（多线平行时间轴：时间 × 阵营/地区泳道）<br>2. `power_hierarchy`（官制 / 条约 / 权力结构树）<br>3. `spatial_route`（战役/疆域态势拓扑图） | • **多史家视角对照 & 横向世界史锚点**：对照同期全球事件，提示作者筛选偏见与跨书检索入口（联动 `8765`） | 解决时空交错混乱与单一史家视角盲区 |
| **科学与数学** (`science`) | 1. `derivation_dag`（公理 → 引理 → 定理推导依赖图）<br>2. `sensitivity_chart`（变量敏感度 / 函数趋势曲线）<br>3. `system_flow`（物理过程 / 实验装置机制图） | • **反常与演进注记**：该理论为推翻何种旧认知而提出 + 成立的极端/近似边界条件<br>• **直觉类比卡**：生活化思想实验 | 降低公式/术语门槛，厘清前提假设与适用范围 |
| **哲学书** (`philosophy`) | 1. `argument_map`（论证逻辑树：前提 → 推论 → 结论 ↔ 反驳）<br>2. `term_contrast`（词义辨析双栏表：日常义 vs 作者专义）<br>3. `lineage_dag`（哲学问题继承与批判谱系） | • **学术交锋对象档案**：识别隐含批驳的学派/前辈 + 经典思想实验对照（如功利 vs 义务论） | 破解“每个汉字都认识，连起来读不懂作者专义词典” |
| **社会科学** (`social`) | 1. `causal_loop`（多变量因果回路图，标 `+`/`-` 反馈与滞后）<br>2. `concept_matrix`（跨学派概念界定对比矩阵）<br>3. `metric_chart`（核心实证统计趋势/对比图） | • **方法与样本局限提示**：标出定性/定量依据与抽样偏差；联动 `8765` 发起“同议题跨书综述” | 应对“事实+历史+哲学混杂”与“学者间术语不统一” |
| **图册与视觉** (`visual`) | 1. `element_matrix`（构图/元素/时期索引表） | • **技法、源流与年代考据注记** | 补足看图时缺少的年代、流派与工艺背景 |

## 4. 核心决策三：图表框架架构与开源组件选型

### 4.1 为什么采用“固定骨架（Blueprint）+ JSON 填槽 + 本地开源渲染”？

1. **解决模型不稳定**：不再让模型同时决定“用什么图 + 叫什么字段 + 怎么排版”。而是针对每种蓝图设计**极简、字段各异的强类型 JSON Schema**。模型只需做信息抽取和结构化填槽（通常 5–15 个短字段），**不输出坐标、颜色、宽高、HTML 或样式**。
2. **解决设计丑与主题割裂**：所有字体、配色、边框、圆角由渲染器统一绑定 `apps/reading/web/assets/tokens.css` 与 `theme.css` 的 CSS 变量（`--paper`、`--ink`、`--cinnabar`、`--pine`），保证在**暖纸 / 冷纸 / 夜读**三种阅读主题下无缝融合。
3. **恪守本地离线与零构建约束**：`apps/reading` 现行架构为 Python stdlib HTTP 服务 + 原生 JS/CSS（无 Node/Vite 构建步骤，无外部 CDN）。全部布局计算、SVG/CSS 网格渲染与实时碰撞质检均放在 `apps/reading/web/assets/` 下本地运行（如需重型统计库亦仅允许单文件静态引入），100% 离线可靠。

### 4.2 五步防重叠图表流水线架构（全图型统一执行）

结合静态原型阶段暴露的真实排版隐患（有向图卡片换行撑高后被盖、跨层边斜穿中间节点、边标签互撞或出界、四象限绝对定位 Y 轴旋转后侵占象限格），正式方案升级为**对所有图表与知识地图统一生效的 5 步闭环**：

1. **Step 1 · 蓝图 Schema 约束（Prompt 路由）**：按当前 `read_type` + 选定蓝图注入专属 Schema，**禁止模型输出任何坐标、颜色、宽高或 HTML**，并要求分离“主标题（≤ 18 字）/ 关系短词（≤ 6 字）”与详细说明 `detail`，强制每条要点携带 `blocks: ["Bxx"]` 与 `source: "原文" | "补充"`。
2. **Step 2 · 模型生成纯语义 JSON**：模型只填槽位（含兼容旧版 `{family, data}` 缓存与新蓝图 `{blueprint, data/items}`）。
3. **Step 3 · 后端审计、文本分流与容错降级（`src/bookcorpus/reading/diagram_audit.py`）**：
   - 剥离代码围栏、轻量修复 JSON，校验并剔除不存在的 `blocks[]` 块号（缺省时兜底回挂选区首块）；
   - **超长文本自动分流**：主标题超过 18 字自动截断并把全文折入可展开 `detail`；边关系超过 6 字收缩进悬浮提示；
   - **畸形/过密兜底**：JSON 残缺或图过于稠密（`nodes > 12`）时自动退化为带 `Bxx` 原文锚点的结构化清单（`fallback_list`），绝不白屏。
4. **Step 4 · 前端“先实测、再避障、后绘制”（`apps/reading/web/assets/diagram_renderer.js`）**：
   - **离屏真实测量（Measure）**：把节点卡片与边标签放进与正文同字体的隐藏容器 `#measure-stage`，读取浏览器真实渲染后的 `getBoundingClientRect()` 宽高，彻底禁止写死 `cardH`。
   - **有向图正交外绕路由（Corridor Layout）**：窄侧栏抽屉默认 `TB` 纵向布局防裁切，宽屏 **「放大全览」** 弹窗下按需开放 `LR` 横排；所有邻层连线走层间无障碍水平通道，**跨层边与回边一律分配左右外侧独立走廊绕过中间卡片**；边标签经矩形碰撞求解找空位，无空位时退化为序号角标 + 底部图例。
   - **四象限独立网格轨道**：彻底弃用 `position:absolute + rotate(-90deg)`，改用 CSS Grid 独立列（左列专放 `vertical-rl` Y 轴，中间十字准星，底行专放 X 轴），从结构上杜绝坐标轴侵入象限格。
   - **曲线与流式表图**：折线图按轴长动态留白并采用错行两层 X 轴刻度；时间轴、对照矩阵与全章树形知识地图全程走弹性 CSS Grid/Flex。
5. **Step 5 · 实时几何碰撞质检与双向联动**：每次渲染后在前端执行 DOM `getBoundingClientRect()` 碰撞自检（节点间、边标签与节点、边标签间、象限坐标轴与格子），并在卡片底栏给出质检状态；所有节点、数据点与 `Bxx` 锚点均绑定 `focusBlock()` 平滑定位正文，钉住旁批同时保留 `figure` JSON 以便切换暖纸/冷纸/夜读主题后重绘。

### 4.3 开源组件与渲染策略选型

结合本仓“无外部 CDN、原生 JS/CSS、零构建步骤、中文多行换行友好、节点可点击回链原文、暖/冷/夜读三主题联动”的要求，按图型专长分层实现：

| 图表大类 | 渲染架构与布局策略 | 为什么这么选 |
|---|---|---|
| **有向图 / 树图 / 因果回路**<br>（`flow_swimlane`, `decision_tree`, `derivation_dag`, `argument_map`, `lineage_dag`, `power_hierarchy`, `causal_loop`, `spatial_route`, `system_flow`, `relation_graph`） | **离屏 DOM 实测宽高 + 自研零依赖正交外绕走廊布局器**（可平滑切换/接入 `@dagrejs/dagre` 或 `elkjs`） | 不引入重型构建流，原生支持跨层外侧走廊绕行、边标签碰撞求解、点击节点展开 `detail`、切换暖/冷/夜读 CSS 变量及点击 `Bxx` 直跳正文；不选用接管 DOM 主题的 Mermaid。 |
| **曲线 / 函数 / 实证统计**<br>（`tension_curve`, `sensitivity_chart`, `metric_chart`） | **动态留白 SVG 样条曲线 + 错行刻度图例**（后续大数据量可选配单文件 `Chart.js`） | 零依赖即时绘制平滑样条与高亮区域，天然继承 `--cinnabar`/`--paper` 主题变量，点击数据点直跳对应 `#blk-Bxx`。 |
| **平行时间轴 / 对照矩阵 / 语义辨析 / 四象限 / 知识地图树** | **声明式 HTML/CSS Grid 独立轨道与流式树组件**（零绝对定位） | 中文多行折行、Sticky 表头、四象限独立坐标轴轨道与横向可折叠知识树天然零重叠，适配桌面窄抽屉与移动端。 |

## 5. 统一 Blueprint JSON 协议示例（以典型三类为例）

模型不再返回千篇一律的 `{nodes, edges}`，而是按选定蓝图填固定槽位。以下三个示例展示“固定骨架 + 强制原文锚点”如何落地：

### 示例 A：哲学书 · 论证逻辑树（`argument_map`）
```json
{
  "blueprint": "argument_map",
  "caption": "康德为何拒绝以经验幸福作为道德基础",
  "reading_note": "先看主前提与结论，再看下方对经验主义的驳斥分支。",
  "data": {
    "nodes": [
      {"id": "A1", "role": "premise", "label": "道德法则必须具有普遍必然性", "blocks": ["B04"], "source": "原文"},
```

## 6. 与“书库检索（8765）”的双向联动设计

用户的核心场景包含“检索问答”与“分层阅读”，两者可在分类与图表上形成闭环：
1. **检索回答借用“对比矩阵/时间轴”骨架**：
   当 `8765` 回答跨多本书的哲学/社科/历史类问题时（特别是“比较 A 和 B 的观点”、“某概念在不同学者间的演进”），`apps/demo` 的回答结构化阶段可直接复用 `concept_matrix` / `parallel_timeline` 骨架生成对比卡片，每格带原文出处链接 `/open?uid=...`。
2. **阅读扩展动作反向调起书库检索**：
   在分层读点击**“多史家视角对照”**或**“同议题跨书综述”**时，除当前章模型的内部总结外，直接复用现有 `buildRelatedHref`（`8765` `mode=related` 或预置 `mode=trace` 查询），把用户从单本书无缝带到跨书对比视野。
