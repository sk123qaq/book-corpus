## 0. 一句话

在 `apps/ops/` 建一个只监听本机的控制台。页面读 `ops_status.py` 的 JSON，排队调 `src/bookcorpus/scripts/` 里的脚本，用 `ops.db` 记任务与日志。页面不写人账、不写 `library.db`、不写 `book.json`、不写 `index.db`。先交付 P0 到 P2，PDF 与删书随后。

## 1. 目标

把现在散在命令行的日常操作收进一个页面：

1. 新书导入，上传或扫收件箱，逐本看分类预填。
2. 电子书拆章，含 verify、audit 与失败后的 agent 修复。
3. 已有 md 的受控重拆，旧 md 先归档。
4. PDF 分诊与 OCR，含 3 张缩略图与模型预判。
5. 删书，原书进冷宫，md、html、json 删除。
6. 数据库、书目表、检索索引、视图与验收的维护。
7. 一个跳到检索演示页的按钮，带健康检查与启动。

## 2. 非目标

- 不做远程访问，不做登录，不做多用户。
- 不编辑已有 1,693 行的分类、书名、保留策略。已有行仍手改 `目录/分类表.csv`。
- 不做全库分类按钮。`classify_books.py` 的模型后端只改脚本，页面只给导入预填与预填表链接。
- 不做彻底删除。冷宫是终点，恢复靠手工。
- 不做 `build_expand.py` 的日常操作，不做向量层，不做阅读版批量生成。
- 不自动改 `目录/系列/` 的卷序文档。
- 不把检索演示页嵌进 iframe。

数字来自 2026-10-24 22:00 前后实测。

- 收件箱有 3 本 EPUB 待入库。

- `split_md_batch.py` 与 `pdf_md_batch.py` 都遵守“批次目录已有 `worklist.tsv` 就以它为准”，但范围账的写法不同：拆章驱动只写一次，转写驱动把 `--uids` 点到的书追加进账，一次只跑一条 route。

## 5. 架构

### 5.1 目录

```text
apps/ops/
  server.py                 本地 HTTP 服务，127.0.0.1:8770
  web/
    index.html
    app.js
    style.css
  ops.db                    任务与步骤，SQLite
  jobs/<id>/
    log.txt                 子进程 stdout + stderr
    pid                     running 时的 PID
    plan.json               导入计划、任务输入
    review.json             PDF 分诊复核
    thumbs/*.png            分诊缩略图
    status.json             子进程写的进度，可选
  search.log                检索演示页的输出
  search.pid
  验收/
    check_ops.py            只读 API 与页面自检
README.md
```

新增脚本放 `src/bookcorpus/scripts/`：

- `ops_status.py` 只读状态 JSON。
- `retire_book.py` 移出流程。
- `ops_pdf_triage.py` PDF 分诊：探针、缩略图、模型预判。
- `classify_model.py` 导入与全库分类共用的模型调用。

### 5.2 技术栈

沿用演示页的零依赖方案。Python 标准库 `http.server.ThreadingHTTPServer`，原生 JS，无前端框架，无 CDN。页面样式复用演示页的纸色、朱红、等宽数字变量，流程轨与状态词沿用全景页的“通、半、缺、外”。

### 5.3 三条只读数据源

- `ops_status.py --json` 给总览与顶栏。
- `ops.db` 给任务列表、步骤、日志路径。
- 各批次的 `worklist.tsv`、`logs/<uid>.json`、`triage_final.csv`、`skipped-pages.tsv` 给单本进度。

页面不复制这些账，只读。

### 6.1 总览

- 六阶段流水线，每个阶段显示当前读数与状态。
- 三本账卡片。人账 `分类表.csv` 行数与修改时间；产物 `library.db`、`index.db`、书目表；机账当前批次与任务。
- 断点清单，只显示与操作相关的 G3、G4、G5、G10、G11。每条给一句现状与一个动作。
- 下一步建议，按优先级排：收件箱待导入、待分诊 PDF、待拆电子书、索引落后、audit WARN、收尾未做。
- 最近 5 个任务，点进日志。

### 6.2 新书导入

上半是上传区与收件箱表。下半是扫描后的计划表。

上传：

- 接受 epub、mobi、azw3、azw、pdf、txt、djvu。
- 单文件上限 2 GB。裸 body 流式写 `库/_收件箱/<文件名>.part`，完成后 `os.replace`。文件名去路径分隔符，拒绝 `..`。
- 用 XMLHttpRequest 显示上传进度。上传不是账本写任务，不占写锁。

扫描：

- 按钮调 `ingest.py scan --json --out 工作区/运维/jobs/<id>/plan.json`。
- 页面读计划，表格列为动作、文件、书名、作者、格式、大小、sha256、一级、二级、保留、说明。
- add 行的 subjects 由 `ingest.py` 现有 `_call_classifier` 预填，模型 `opencode-go/deepseek-v4.1-flash`。低置信行标黄，说明写“需人工确认”。
- 每行可改书名、一级、二级、保留。顶部有“全部采用预填”。
- replace 行必须选目标 uid，并显示旧源与新源。conflict 行必须显式指定 add 或 replace 或 skip。skip 只读。

应用：

- 页面把编辑后的计划写回 `jobs/<id>/plan.json`。
- 调 `ingest.py apply <plan> --apply`。
- 成功后自动接 `build_library.py --emit-json` 与 `gen_book_catalog.py`。
- 门槛是 `conflicts=0`、`未匹配 0 条`。失败保留计划与日志，可改后重跑。
- 入库后按格式给下一步按钮。电子书去 P2 批次，PDF 去分诊。

边界：

- 页面不改 `目录/分类表.csv`。新行只由 `ingest.py apply` 追加。
- 上传只落收件箱，不入账。
- 测试用 `ingest.py --root` 指向临时库，不碰真收件箱。

### 6.3 电子书出正文

默认列表只列 `v_pending_md` 里的 epub、mobi、azw3、azw。列出书名、格式、源大小、源路径、备注。

选择与批次：

- 勾选后点“开始拆章”。页面调 `split_md_batch.py --batch split-ops-<时间戳> --uids B0001,B0002 --workers 4`。
- 批次目录在 `工作区/批次/` 下。脚本在 worklist 不存在时只写所选 uid，之后重跑只读 worklist。
- 旧批次不动。每次新批次有自己的 worklist、logs、out、overrides。

单本状态：

- 从 `logs/<uid>.json` 读 verify rc、audit rc、audit ratio、章节数、图片数、fix 次数、落地或留在暂存区。
- 卡片显示四段：转换、verify、audit、agent 修复。失败时展开日志尾部。
- agent 修复参数用脚本默认值：每本 1 次、整批 3 次、600 秒、模型 `opencode-go/deepseek-v4.1-flash`。页面可改次数与模型，写进命令行。
- 失败书可“只重跑这本”，调 `--only <uid>`。

重拆：

- 高级区单独入口。默认列表不显示已 md 的书。
- 选中后出现“这会替换现有 md”确认，必须勾选。
- 调 `split_md_batch.py --batch resplit-ops-<时间戳> --uids ... --replace --archive-old`。
- `--archive-old` 在落地前把旧 `md/` 移到 `工作区/批次/<批次>/old/<uid>/`，再 rename 新产物。
- 旧 md 归档后仍可人工恢复，页面给路径。

批次结束：

- 自动跑 `build_library --emit-json` 与 `gen_book_catalog`。
- 顶栏出现“去收尾”横幅。索引未重建时徽标亮。

### 6.4 PDF 出正文

上半是队列，下半是新 PDF 分诊。

队列：

- 读 `triage_final.csv`、`skip_list.tsv`、`defer/lang.tsv`。
- 按路线分组：OCR、本地抽文本、不转-记图册、人工确认、日文暂缓。
- 每组显示本数、页数、预计额度。
- 现有 `pdf-ocr-2026-10-19` 批次只读，显示已落地、剩余、skipped-pages。
- Paddle 日额度 20,000 页。额度用尽显示“明日续跑”，不再派发。

新 PDF 分诊：

1. 导入页入库的 PDF，若 `triage_final.csv` 没有该 uid，进入“待分诊”。
2. 点“分诊”，跑 `ops_pdf_triage.py --uid <uid> --out jobs/<id>/`。
3. 脚本依次做：
   - `pdf_census.py --uid <uid> --out census.jsonl`。
   - A/B 类跑 `pdf_text_probe.py --census ... --out text.jsonl`，用 `工作区/.venv-pdf/bin/python`。
   - C/C2 类跑 `pdf_scan_probe.py --census ... --out scan.jsonl --sample 5`，用同一个解释器。
   - 用 pymupdf 渲染 3 张缩略图，首页、正文中页、末页，存 `thumbs/`。
   - 组装指标与提示词，调 `pi -p --no-tools --no-session --no-context-files --no-skills --no-extensions --model opencode-go/deepseek-v4.1-flash "@thumb1.png" "@thumb2.png" "@thumb3.png" "<prompt>"`。
4. 模型回一行 JSON：

```json
{"route":"OCR|本地抽文本|不转-记图册|人工确认|日文暂缓","confidence":0.0,"reason":"..."}
```

5. 页面显示指标、3 张图、模型建议、理由、置信度。
6. 你选最终 route。可改理由。日文暂缓来自语言探针，模型只作参考。
7. 确认后写 `review/<uid>.json`，把分诊 job 的 `triage.csv` 按 uid 合并进 `pdf-ocr-ops-<日期>/triage.csv`，把 `census.jsonl` 与 `text.jsonl`/`scan.jsonl` 按 uid 合并进批次目录，再调 `pdf_apply_review.py --triage <批次>/triage.csv --out-dir <批次> --review <批次>/review`，把人工 route 与模型四列并回 `triage_final.csv` 与 `skip_list.tsv`。同一天多次确认累积在同一批次。确认成功后原分诊任务回写 `succeeded`。
8. 新建 `pdf-ocr-ops-<日期>` 批次，worklist 首次只含确认要转的 uid，同一天再选一批只追加；调 `pdf_md_batch.py --batch ... --route ocr|text`。当天表里没有某本书的分诊行时（前一天确认的），沿用最近一份批次表里那条 route，先跑一次 `pdf_apply_review.py` 把行落进今天的表，再调驱动。

模型建议四列：

- `model_route`
- `model_confidence`
- `model_reason`
- `model_at`

`route` 只写人工确认值。模型建议永远不改 `route`。

提示词规则：

- 文本层覆盖高、乱码率低，选本地抽文本。
- 无文本层但抽页有文字行带，选 OCR。
- 整页图版、画册、写真、杂志，几乎没有文字，选不转-记图册。
- 拿不准选人工确认。
- 语言探针判 ja 时优先日文暂缓。
- 只输出一行 JSON，不要解释，不要代码块。

### 6.5 维护

自动步骤，每次导入、拆章、删书后由任务链执行：

1. `build_library.py --emit-json`。门槛 `conflicts=0`。
2. `gen_book_catalog.py`。门槛 `未匹配 0 条`。

收尾按钮，批次结束后横幅出现，手动点。清单默认全选：

1. `build_para_index.py --rebuild --concepts`。检索索引。
2. `build_topic_views.py`。主题软链。
3. `migrate_layout.py --views`。奖项软链。
4. `audit_state.py --deep`。门槛 FAIL 0。
5. `verify_phase.py`。门槛末行“全过”。
6. `check_p1.py`。门槛“失败 0 项”。

单步按钮放高级面板。`build_index.py` 阅读版只在有 html 变动时手动跑，不默认勾选。

索引落后徽标：

- 读 `library.db` 的 md_done 书与章数，读 `index.db` 的 book 与 chapter，算差集。
- 也算 `index_built_at` 与最新 md mtime。
- 徽标显示“索引落后 N 本 / M 章”。收尾的索引步骤成功后清掉。

Excel：

- 维护页显示 `目录/书目总表.xlsx` 的修改时间、未匹配数、下载链接。
- 同时给 `目录/书目总表.csv` 与 `目录/分类预填.csv` 的链接。
- 页面不改 Excel。

分类：

- 给 `目录/分类预填.csv` 的链接。
- 不放全库分类按钮。
- `classify_books.py` 的模型后端是 CLI 能力，页面只链接预填表。

### 6.6 删书

入口是 uid 或书名搜索。结果卡显示书名、路径、源文件、md 章数、奖项、系列。

预览：

- 按钮调 `retire_book.py --uid <uid> --reason "<理由>" --dry-run --json`。
- 页面弹层显示七层：
  1. 书目录与要删的 md、html、json。
  2. 源文件。每个源显示 sha256、字节、共享本数、动作是 move 还是 hardlink。
  3. 人账行与 DB 行。
  4. expand 行数与 `目录/检索/expand/<uid>.md`。
  5. 奖项行与奖项视图条目。
  6. 主题视图条目。

## 7. 任务模型

### 7.1 表

```sql
CREATE TABLE job (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,
  title TEXT NOT NULL,
  argv TEXT NOT NULL,
  state TEXT NOT NULL,
  pid INTEGER,
  created TEXT NOT NULL,
  started TEXT,
  ended TEXT,
  exit_code INTEGER,
  summary TEXT,
  log_path TEXT,
  batch_dir TEXT,
  plan_hash TEXT
);

CREATE TABLE step (
  job_id TEXT NOT NULL,
  seq INTEGER NOT NULL,
  name TEXT NOT NULL,
  state TEXT NOT NULL,
  detail TEXT,
  started TEXT,
  ended TEXT,
  PRIMARY KEY (job_id, seq)
);
```

### 7.2 状态机

```text
queued -> running -> succeeded
                 -> failed
                 -> cancelled
queued -> awaiting_review -> running -> ...
running -> orphaned（服务重启且 PID 核对不上）
orphaned -> running（接管） | failed
```

- `awaiting_review` 用于导入计划确认与 PDF 分诊确认。它没有子进程。
- 任务成功由门槛判定，服务端读脚本输出的最后几行或 `--report-json`，不看退出码单独决定。
- 一个任务可以有多个步骤。拆章与 PDF 的单本进度不写进 `ops.db`，读批次自己的 `logs/<uid>.json`。

### 7.3 锁

- 写任务互斥。写任务与 HTTP 批次账读改写用 `工作区/运维/.writer.lock` 的 `fcntl.flock(LOCK_EX)`。
- 只读任务（扫描、分诊、查看问题、删书预览）用 `工作区/运维/.reader.lock` 的 `LOCK_SH`，最多两个并行，
  与写任务互不阻塞——写任务开始不等只读任务，只读任务也不排队等写任务（2026-10-27 修订：单锁实现
  把"可与写任务并行"锁成了互等，拆回两把锁）。读写并行安全靠约定：只读任务只写自己的 `jobs/<id>/`，
  写任务的共享文件一律 tmp+replace 原子替换。
- `ingest.py` 自己还有 `.ingest.lock`，作为第二道保险。
- 页面按钮在写任务运行时禁用，状态查询与日志仍可看。

### 7.4 接管

- 服务启动时读 `state=running` 的任务，读 `pid`。
- 核对 `/proc/<pid>/cmdline` 与 `job.argv` 的首个脚本路径一致。
- 一致就恢复日志跟随，任务继续。
- 不一致就标 `orphaned`，页面给“重跑”与“查看日志”。不自动杀进程。

### 7.5 取消

- 页面“停止”发 SIGTERM 给子进程组，等待 10 秒，未退再 SIGKILL。
- 拆章与 PDF 驱动是幂等的，重跑会跳过已落地与暂存区已有产物。
- 索引重建用 tmp + replace，取消不会留下半个索引。

## 11. 安全与边界

- 只绑 `127.0.0.1:8770`。POST 检查 `Origin` 与 `Host` 都是本机，防跨站。

## 14. 已知限制

- 目录名仍是分类表的投影。改分类后目录名要手工 mv，页面只提示，不代做。
- 冷宫恢复是手工。页面不提供恢复按钮。
- 全库分类预填仍是 CLI。页面只给导入预填与预填表链接。
- 索引重建没有细粒度进度。页面显示日志尾部与耗时，不显示百分比。
- PDF 模型建议可能错，错误会进四列但不会改 `route`，人工确认是最后一道闸。
- 系列文档不会自动改，删卷后要人工看预览里的标出项。
- 上传上限 2 GB。更大的文件仍用文件管理器放进收件箱。
- 无登录，只在本机。任何远程访问计划都要先加鉴权与 TLS。
