# 指标口径

检索层评测与性能输出的账。定义以脚本原文为准，`book_eval.py` 的文件头 docstring 与 `probe_b6.py` 的打印是唯一来源，本文只登记到能读懂输出的程度。改口径先改脚本，再回来改本文；两处不一致时以脚本为准。

| 文件 | 作用 |
|---|---|
| `工作区/批次/qa-检索-2026-10-22-书级融合/book_eval.py` | 书级评测，八种方案在 60 题上的名次与证据章 |
| `工作区/批次/qa-检索-2026-10-22-书级融合/probe_b6.py` | B6 实跑，默认查询、旧 mix、文档命令、性能 |
| `工作区/批次/qa-检索-2026-10-22-书级融合/book_gold.tsv` | 评测样本，60 题，long / short / ordinary 各 20 题 |
| `工作区/批次/qa-检索-2026-10-22-书级融合/基线-B2-60题-2026-10-26.tsv` | `best_support` 基线读数，配同名 `.说明.txt` 记 HEAD、索引 built_at 与 gold sha256 |

## 书级评测

`book_eval.py` 跑完先打「样本」「口径」「基线」三块，再打 summary 表。summary 一行一个方案，`sum`、`mean`、`best`、`mix`、`best_support`、`best_top3_support`、`rrf5`、`best_support_length`。

| 指标 | 定义 | 单位 | 来源 |
|---|---|---|---|
| `book_rank` | 可接受书里第一本的名次，1 起，不在候选记 0 | 名次 | `eval-book.tsv` 的 `rank` 列 |
| `hit@10` / `hit@20` | `book_rank` 落在 10 / 20 内 | 比例 | `eval-book.tsv` 的 `hit10` / `hit20`；`summary.tsv` 同名 |
| `mrr` | 1/名次，没进候选记 0，不按截断名次算 | 比例 | `eval-book.tsv` 的 `mrr` 列 |
| `ev_rank` | 可接受章在全库章级名次里的名次，同章去重取该章最好段 | 名次 | `eval-book.tsv` 的 `ev_rank` 列 |
| `ev_hit@10` | `ev_rank` 落在 10 内 | 比例 | `eval-book.tsv` 的 `ev10` 列 |
| `in_book_rank` | 可接受章在目标书内部的名次，按章最好段排 | 名次 | `eval-book.tsv` 的 `in_book_rank` 列 |
| `in_book_top3` | `in_book_rank` 落在 3 内，B3 的每本最多三章拿它比 | 比例 | `eval-book.tsv` 的 `in_book_top3` 列 |
| `long_share@10` `all` | top10 里 500 章以上书的占比，除以 10 后按题平均 | 比例 | `summary.tsv` 的 `long_share10_all` 列 |
| `long_share@10` `nonlong` | 同上去掉 long 层。长书层每题的目标书本身 ≥500 章，合并口径有地板，门槛按这一列读 | 比例 | `summary.tsv` 的 `long_share10_nonlong` 列 |
| `best_ok` | 目标书自己最好的章是不是可接受章 | 比例 | `eval-book.tsv` 的 `best_ok` 列 |

比例一律 0 到 1，按题平均，不乘 100。`gate_hit10`、`gate_single`、`gate_long_share`、`gate_ordinary`、`gate_pass` 是上面几项对 `mix` 的比较结果，四项门槛与 `single_n`、`single_hit10` 的定义写在 `book_eval.py` 文件头 docstring，改门槛先读那里。`top10_types` 是 top10 里各一级分类的平均本数，只作诊断。

基线取 `基线-B2-60题-2026-10-26.tsv` 的 `best_support` 行，打印 `hit10`、`mrr`、`ev10` 三项。这张表是 2026-10-26 20:26 索引重建后第一次完整跑，HEAD `b2bf88c`，gold sha256 `72dcc4fe`，样本 60 题。批次根目录 2026-10-22 的 `summary.tsv` 是旧索引、旧列，不与它比，也不拿别的目录凑数。文件不在就打印「基线未找到」。

## 性能

跑法 `python3 工作区/批次/qa-检索-2026-10-22-书级融合/probe_b6.py --perf`。60 题，五遍，同进程，三路交错。

| 量 | 定义 | 单位 | 来源 |
|---|---|---|---|
| 单题毫秒 | 单题单路的端到端耗时，含规划、取数、弹卡，`time.time()` 前后差 | ms | `live/B6/perf.tsv` 的 `qsearch_mix`、`book_query_mix`、`default` 三列 |
| `p95` | 单遍 60 题毫秒数升序取 `round(0.95*(n-1))` 位，n=60 即第 57 小 | ms | `probe_b6.py` 的 `p95()`，打印与判定共用这一个函数 |
| 遍 | `--passes`，默认 5 | 遍 | `live/B6/perf.tsv` 的 `pass` 列 |
| 五遍交错 | 每遍内按 `(遍号 + 题序) % 3` 轮转三路顺序，同一遍里三路看同一份缓存与噪声，遍与遍之间再取中位 | 顺序 | `probe_b6.py` 的 `perf()` |
| 中位数与极差 | 五个 per-pass p95 的中位、最小、最大 | ms | 输出的「每路 p95」段，落 `live/B6/perf.txt` |
| `default/qsearch_mix` 比值 | 每遍 `default` 的 p95 除 `qsearch_mix` 的 p95，报中位与最大 | 比值 | 输出的「比值」段 |
| `default/book_query_mix` 比值 | 同上，分母换同管线的 mix，只作诊断 | 比值 | 输出的「比值」段 |
| 2 倍线 | `default` 的 p95 <= 2 × `qsearch_mix` 的 p95，按五遍里最差的一遍判 | 比值 | 判定行「默认/旧 qsearch p95 比值最大」 |
| 2000 ms 绝对线 | `default` 的 p95 <= 2000，按五遍里最大的一遍判 | ms | 判定行「默认 p95 最大值」 |

判定过后末行打 `ALL PASS`，否则打 `FAIL` 并以 1 退出。`perf.tsv` 的列固定为 `pass`、`qid` 与三路毫秒，五遍就是 300 行，加遍数不改列。

基线是 `qsearch --book --book-score mix`，即 `qsearch_mix` 列，不是 `book_query --book-score mix`，即 `book_query_mix` 列。后者是同一个 `Planner` 换 scheme 跑，用来分辨慢在管线还是慢在打分；它的 p95 一直贴着 `default`，比值贴着 1，不能当历史基线。输出末行那句「注意」说的就是这条。

`book_eval.py --perf` 是另一台机器，比 `qsearch.search` 加 `rollup_by_book(mix)` 与 `book_score.rank(best_support)`，按题号奇偶交错，单遍，判据同为 2 倍线与 2000 ms。它不是五遍，读数只作对照，正式性能看 `probe_b6.py --perf`。
