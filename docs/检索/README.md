## 0. 为什么要有这一层

现状只有字面匹配。四份独立实测（本方案作者 + 三个外部模型各自跑题）得到同一组事实：

| 事实 | 实测值 | 含义 |
|---|---|---|
| `自由` 命中文件 | 12,458 / 100,096（12.4%） | 字面召回不缺 |
| `自由` 命中书 | 1,027 / 1,310（78%） | **书级完全不收敛**：问"哪本书讲自由"等于问全库 |
| `自由` 出现次数 | 38,112 次，其中 3,459 次是「自由自在/自由度/自由落体/自由贸易/自由讨论」 | **精度也差** |
| 讲主题但不含主题词 | 9 本书独立复现；刘擎单本 173 节里 84 节零命中，含「铁笼」「独立判断」「个人主义」 | **真漏**，且漏的正是最该引的段落 |
| 含枷锁/奴役/不自由/束缚/禁锢/铁笼/压迫 而不含「自由」 | 3,823 个 md / 548 本书 | 漏检面下界 |
| 空行段落（≥20 字） | 4,614,378 段，平均 111 字，**中位 53 字**，73% 不足 100 字 | 按原段建向量＝建 461 万条对白碎片 |
| 500 字合并块 | **821,277 块**，平均 609 字，每本 627 块 | 这才是向量层的单位 |
| 全库检索耗时 | grep 1.0 s / rg 3.2 s（技能文档写的 0.05 s 错了 20–60 倍） | 速度从来不是瓶颈 |
| `库` 正文 | 532,083,380 字符 / 98,789 章 / 1,310 本 | — |

2026-10-21 起 `库/` 少一本：唐诗学书系（B1359，11,619 章）移入 `库/_冷宫/`，md 已删。重建后的索引口径是 87,239 章 / 2,359,595 段 / 1,374 本，其中 69 章是重建时顺带补进索引的 OCR 单文件书（此前未入索引），所以不是 98,789 减 11,619 的简单算术。上表保留 10-20 的实测值，不再逐格改。

结论：**这不是一个"召回不够"的问题，是"召回过剩 + 无排序 + 无别名"三件套。** 所以索引要解决的是排序与别名，向量只是补最后那一段改述。

## 1. 分层与各层的技术手段

| 层 | 解决什么 | 技术手段 | 依赖 |
|---|---|---|---|
| **L0 评测** | 判断改进是否真的有效 | `grep -nF` 行号核验、`sqlite3` 读 `derived`、标准库算 recall@k / MRR、`subprocess` 调 rg 与 `defpass.py` 做基线 | 无 |
| **L1 概念表** | 译名墙、多义噪声 | 人工 TSV；`concept_expand.py` 把概念展开成 OR 组 + 排除正则；`defpass.py --concept` | 无（纯标准库） |
| **L2 词法倒排** | **排序**（12,458 文件 → 前 50 有序）、书级路由 | jieba 分词（userdict 灌书名作者）+ SQLite FTS5（`unicode61`，非 `trigram`）+ `bm25()` + 组覆盖度重排 + tf-idf 概念剖面 | `jieba` |
| **L3 段落向量** | 改述、论证段（段落里一个概念词都没有） | 500 字合并块 → bge-small-zh-v1.5 / bge-m3（ONNX int8）→ fp16 余弦 | `onnxruntime` `tokenizers` `numpy` + 模型文件 |
| **L4 融合** | 双路互补、压对白噪声 | RRF（`Σ 1/(60+rank)`）+ 文体特征降权（引号密度、段长、对白正则） | 同 L3 |
| **L5 流程** | 让技能真的用上它 | `视图/主题/<概念>/` 相对软链树（复用 `视图/奖项` 思路）+ 技能文档改写 + `verify_phase.py` 增一项 | 无 |

> **本表是 v1**：L2 的分词方式、L3 的模型选择、L4 的重排已被 §1.5 改动 1 / 4 / 3 替换；新增的文档扩展层也只在 §1.5 里。

**只有 L3 会把正文编码成语义向量。** L2 的 tf-idf 也是「权重向量」，但它是词频统计，不涉模型、不涉编码；jieba 是分词，不是向量化；v2 的文档扩展是生成文本，也不是向量化。这一点在分期里很关键（见 §2 / §2.1）。

两个实测过的坑，写死在这里：

1. **FTS5 的 `trigram` 分词器对 2 字词（自由/内卷/权力）直接 0 命中**，只认 ≥3 字子串。v1 的结论是「必须 jieba 预分词」——**【v2 改动 1 已推翻】改为 CJK bigram(+unigram) 预切，不装 jieba。**
2. **defpass.py 的 stage 1 用 `rg -l` 粗筛**，段落里没有词就进不了候选集——这正是漏检的机制。`--concept` 只是让词表好用，绕不过这个结构性缺陷；L3 必须绕开 stage 1 独立召回。

## 1.5 v2 修订（2026-10-19，依据外部检索）

五处替换。§1/§2 的原文不删，留作 v1 对照；**冲突处以本节与 §2.1 为准。**

### 改动 1 · 删掉 jieba，改 CJK bigram(+unigram) 索引

- **原**：jieba 分词 + `unicode61` + userdict 灌书名作者。
- **改**：索引侧把中文连续串切成**重叠二元组**，并在**同一位置**附带 unigram（`清华` → 位置 0 放 `清华`+`清`，位置 1 放 `华大`+`华`，…）；查询侧 2 字词按单 token、3 字以上按 phrase（相邻 bigram 序列）。
- **依据**：TREC-5 系列对照实验——纯 bigram 索引不依赖词典，效果**约等于甚至好于**词典分词（[不带词典的中文检索](https://doi.org/10.1145/278459.258532)、[中文 IR 表示对照](https://doi.org/10.1145/278459.258531)：精确率相当、相关文献多 5%、索引空间约 3 倍）；站点搜索实验结论是[两种方法整体无差异，≤3 字查询 bigram 更好](https://dl.acm.org/doi/pdf/10.1145/2838931.2838940)。实现有成熟件：[sqlite-cjk-fts](https://pypi.org/project/sqlite-cjk-fts/)、[sqlite-fts5-bigram](https://pkg.go.dev/github.com/hakazv/sqlite-fts5-bigram)。trigram 对 1–2 字中文词退化成 LIKE 全表扫、实测 3–6 s/查询，见 [hermes-agent 的 CJK bigram PR](https://github.com/NousResearch/hermes-agent/pull/74984)。
- **影响**：P1 的第三方依赖**归零**；「伯林」「书名」「新造术语」不再被切碎；2 字词不再掉进 trigram 的坑。代价：索引膨胀 2–3 倍。
- **替换**：§1 表 L2 行、§1 坑 1、§2 P1 行、§6 解释器约定。

### 改动 2 · 文档扩展取代「每章打概念标签」

- **原**（v1 未写，但 §1.5 讨论过并被否决）：每章发 40–60 个 Noul 判定，落 `chapter_tag` 表。
- **改**：**改索引文本，而不是另立标签表**，两种动作都是研究支持的标准做法：
  1. **上下文前缀**：每章生成 50–100 token 的「本章在讲什么」，**前置到 FTS 索引文本**；
  2. **伪查询**：每章再生成 3–5 条「这一章能回答的检索式」，**追加到索引文本**。必须带少样本正例 + 「每条至少两个正文没出现的词」硬约束，否则模型会写阅读理解题（实测定稿见下）。
- **依据**：[Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)：加 50–100 token 前缀后，检索失败率 −35%（仅向量）/ **−49%**（+BM25）/ −67%（+重排），一次性成本 $1.02/百万 token；[Doc2Query](https://arxiv.org/abs/1904.08375)：追加伪查询使 MAP **+15%**，且不增加查询时算力（它的模型在「段落 → 真实查询」对上训练过）；[Doc2Query++](https://arxiv.org/html/2510.09557)：把**主题词 + 关键词**喂进提示，要求「集体覆盖主题、最小化词汇重叠」；[Query2doc](https://aclanthology.org/2023.emnlp-main.585.pdf)：few-shot 正例是真实查询时 BM25 +3–15%，弱模型收益边际。
- **为什么这条比「一本书一个摘要」强**：前缀与伪查询「有词」而原文没有，正好补上「在说自由但不说自由」这段缝；同时**不丢章节坐标**（逐章生成、逐章挂），BM25 结构完全不用改，词法路全复用，而且打开 `expand/<uid>.md` 就能看见「这句桥为什么存在」。
- **代价**：会幻觉。但**不要靠过滤保召**——[SIGIR 2024 的复现研究](https://dl.acm.org/doi/10.1145/3626772.3657850)发现 Doc2Query− 的过滤提精度却**降 recall**。不要的东西干脆不生成（见下面定稿约束），比生成后再滤更好。Jev 只用于消歧。
- **成本**（按本机价目，实测口径见 §2.1）：输入约 100M token（首 1,200 字 + 目录）、输出约 25M token。`mimo-v2.6-flash`（token plan 内）≈ 0；按量 ≈ $19；`deepseek-flash` ≈ $46。并发 20 约 3–5 小时。
- **实测定稿（2026-10-19，报告见 `工作区/批次/qa-检索-2026-10-19/实验报告-P1.5-文档扩展.md`）**：
  - 形态默认**主题前缀**（批量 5 章 + 每章 800 字 + low + max_output_tokens=2500）：每章 **651 token**，全库 ≈ **$15**；端到端 top3 从 17/27 → **21/27**，均排名 30.4 → 19.5
  - **伪查询不是不能做，是零样本提示词会写阅读理解题**：旧提示产出自带正文没有的 bigram 只 53%，top3 17/27。改成「**少样本正例 + 每条至少两个正文没出现的词**」后新词率 **89%**，top3 **21/27**、均排名 **16.0**，与前缀持平。**但它贵 4 倍**（2,619 vs 651 token/章），所以降为**只补前缀没点到概念词的那些章**（全库约 10–15%，≈$6–9；2026-10-22 实测更正：并集词表 gap 34.7%，126 键 75.0%，见 `工作区/批次/qa-检索-2026-10-22-选章器/实验报告-选章器.md`）
  - 铁笼章 裸 33.7 → 前缀 **1.7** / 伪查询D **2.0**；动物农场结尾 35.3 → **2.3**（两个硬例都修好）
  - **给一整张主题词表给模型反而更差**（19/27）：10 个宽主题词全塞进 5 条检索式，在 BM25 里 IDF 低、稀释信号。文献给的是 BERTopic 挑的少数主题
  - **high 不比 low 好**（同形态 top3 差 0–1 条），token 反而多 5–10%
  - 过滤/消歧用 **`typesafe/jev-1.14.0`**（commandcode 通道 `POST /provider/v1/systemone`，$0.042/M 输入、输出免费，100 问/次上限）：义项消歧实测准（丘吉尔「爱尔兰自由邦」章 0.12 vs 词法命中 35 次）；但**拿它打宽概念标签不收敛**（铁笼章「自主与自由」仅 0.30，10 概念里 8 章都 >0.6 的是「历史与政治」）
- **替换**：§1 表 L3 行（向量不再是补缝主力）、§2 P3 行。

### 改动 3 · 加「重排」层（性价比最高的一步）

- **原**：靠「引号密度/段长」猜文体降权。
- **改**：对 top-30～50 做**交叉编码器重排**；`bge-reranker-base`（C-MTEB 重排 65.4）或 `bge-reranker-large`（66.1），CPU 可行。没有模型时用 TypeSafe `Noul`「这段是实质讨论，还是只出现该词？」兜底。
- **依据**：Anthropic 那组数字里，**重排贡献了从 49% 到 67% 的下降**；[C-MTEB 重排榜](https://github.com/FlagOpen/FlagEmbedding/blob/master/research/C_MTEB/README.md)。
- **影响**：专门用来打「自由法国」那 1,032 次噪声；文体降权退成兜底手段。
- **替换**：§1 表 L4 行、§2 P4 行。

### 改动 4 · 向量层继续降级，且换模型

- **原**：P3 试点 20 本 → P4 全库 821k 块，`bge-small-zh-v1.5`（512 维）。
- **改**：① 顺序降到重排之后，**做完改动 2 再评估还要不要做**；② 若做，模型换 `bge-m3`（1024 维，8k 上下文，可做 late chunking），**不用** `bge-small-zh-v1.5`。
- **依据**：C-MTEB 检索分 `bge-small-zh-v1.5` **61.8** vs `bge-large-zh` **71.5** vs `bge-m3` 更稳（[官方榜](https://github.com/FlagOpen/FlagEmbedding/blob/master/research/C_MTEB/README.md)）；[late chunking](https://arxiv.org/html/2409.04701) 相对 +3.6%；[Dense X Retrieval](https://aclanthology.org/2024.emnlp-main.845/) 证明更细的检索单元（命题级）Recall@20 +10.1，但抽取成本太高，本方案不采用。
- **影响**：向量主要治「用户用了全新说法、且不在这章伪查询里」这一块。**它从地基降为兜底。**
- **替换**：§1 表 L3 行、§2 P3/P4 行、§5 风险表。

### 改动 5 · TypeSafe 从「全库打标」收窄到两处

- **原**：98,789 章 × 40–60 个 Noul ≈ 400 万次判定。
- **改**：只用在 ① **义项消歧**（「自由邦」「自由市场」类专名去掉，离线一次）；② **线上重排 top-20**（每次查询 20 个判定）。**不做生成-再过滤的召回滤除**。
- **依据**：[Doc2Query−](https://arxiv.org/abs/2301.03266) 证明了「生成 + 过滤」这个两段式结构；TypeSafe 的 [Noul](https://docs.typesafe.ai/primitives/noul.md) 与「一次请求多个问题、共享同一份 state」的 [fan-out](https://docs.typesafe.ai/patterns/fan-out.md) 正好对上这个形态。
- **影响**：成本从「百万级判定、单价未知」降到「可先试点 20 本读数」。概念表仍是唯一人账，且被三处共用（BM25 查询扩展 / 书级剖面 / 伪查询提示）。
- **替换**：§2 P3 行、§4 明确不做第 8 条。

### 2.2 基线实测（2026-10-20）

跑法：`eval_retrieval.py --gold <gold.tsv> --system A,B,C,D,E,F,G,H,K,L,M --jobs 8 --out eval-baseline.tsv`，10 档 60 题共 2 分 37 秒（8 并发）。MRR 对没进候选的题记 0。

K 档（查询侧扩短语）无效，原因不是模型给的短语差，而是权重：基底给 3、扩展给 1 时，扩展段落的名次分上限低于基底第 100 名，融合后与 E 逐位相同；把扩展提到等权并改成章级加分，r@10 反而掉到 0.217。这一档的结论是「在已有 60 题上不成立」，不是「查询扩展这条路不通」。

L/M 是唯一把无原词档拉起来的词法手段（0.050 → 0.300 / 0.250），代价是 MRR 从 0.165 掉到 0.145。**这两个数偏乐观**：gold 的 19 个概念里 18 个正好是 `概念表.tsv` 的键，等于让路由在一个含正确答案的小集合里挑。去泄漏测法（从表里删掉这 18 个键再路由）尚未跑。

P1 的验收线是「原词类不低于 A」：E 原词类 14/20 进前 10，A 是 2/20，过。P3 的验收线是「无原词类 ≥70% 进前 20」，E 只有 1/20，而且原因不是排序而是**召回本身没有**：无原词类 20 题里 17 题的目标章根本不在 E 的前 99 个候选里（`eval-index.tsv` 的 `pos` 列为空）。所以重排（P3）救不了这一档，得靠 P1.5 的扩展文本或 P4 的向量。

A/B 两档名次之所以低，不是因为它们慢，而是因为它们没有排序：命中 12,458 个文件时，目标章在 grep 遍历序里的位置等于随机。D 比 A 还差，是因为近义词组把候选池又放大了一圈，而排序仍是零。这一组数就是「召回过剩 + 无排序 + 无别名」三件套的直接测量。

## 4. 明确不做

3. 不把主题写进 `目录/分类表.csv`（唯一人账，一本书一行），不绕过 `build_library.py --emit-json` 改 `book.json`。
4. 不按空行原段直接建向量（461 万段、中位 53 字，全是噪声）。
5. 不用 FTS5 `trigram` 处理中文 2 字词。
6. 不在没有 gold 的情况下宣称「语义检索解决了漏检」。
7. 不做常驻服务、不整库外送 API。
8. **不把 `expand/` 里的上下文前缀、伪查询当原文证据**（见 §3 分界线）。
9. **不给每章打 40–60 个概念标签**（v2 改动 5：改索引文本更便宜、更可解释）。
10. **不用 `bge-small-zh-v1.5`** 做向量层（C-MTEB 检索 61.8，弱于 large-zh 71.5）。
11. **不在未做 P0 评测、未读 20 本试点账单前**把任何 LLM 扩展铺到全库。
12. **不用零样本「生成读者会问的问题」做伪查询**（实测新词率只 53%，相当于把正文又写了一遍）。要生成就带少样本正例 + 「每条至少两个正文没出现的词」硬约束（新词率 89%）。
13. **不拿 Jev 打宽概念标签当索引**（实测闭集不收敛，对硬例反而失效）。
14. **不做「生成-再过滤」的 grounding 滤除**（SIGIR 2024：过滤降 recall）。不想要的东西不生成。
