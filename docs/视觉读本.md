# 视觉读本

同一章的第二形态：一张 xerox 复印稿风格的纸面，用 hero、四张概览卡、章节编号、图版、图表、旁注和 takeaways 把一章的论证骨架摆出来，正文仍逐字取自原文。它不替代四读；四读页顶部有「视觉读本」入口时，两版并存。

## 什么时候用

- 论说、教材、传记、历史等有明确章节结构的书。
- 单章 1,200–30,000 字，图片块占比不超过 55%。
- 文学、短章（<1,200 字）、超长章（>30,000 字）、图册默认退回四读。判决在 `src/bookcorpus/reading/edition/brief.py` 的 `decide_template()`，理由会写进 `brief.json`。

## 流水线

```
章节 md → mdparse 块 → brief 判决 → 模型产出 content.json
        → validate_content → render_edition → audit_edition → 写 edition/
```

模型只产出内容层 JSON，不写 HTML/CSS；原文由程序按块逐字插入，图注、图表数据与旁注才是模型写的。`content.py` 对字段、锚点、图表数据和字数上限做白名单校验；`gate.py` 再核一遍渲染结果：每个原文块必须在页面上出现，图片块必须有 `<figure class="plate">` 和 `<img>`，脚注逐字，不能出现外链资源。

## 生成

页面上：章节工单 →「生成视觉读本（模型约 30–60 秒）」。已有读本时按钮会覆盖重建。

命令行：

```bash
uv run --frozen python - <<'PY'
from bookcorpus.reading.service import ReadingService
s = ReadingService('/home/colaqaq/书库')
r = s.generate_edition('B0003', 6, effort='low')
print(r['status'], r['audit']['errors'], r['audit']['stats'])
PY
```

HTTP：

```bash
curl -s -X POST http://127.0.0.1:8771/api/edition/B0003/6 \
  -H 'Content-Type: application/json' \
  -d '{"effort":"low","overwrite":true}'
# → {"id": "...", ...}，进度看 /records/<id>
```

`effort` 默认 `low`；`model` 不传时用 `deepseek-v4.1-flash`。单章通常 30–60 秒、约 8K tokens。

## 产物

```
工作区/阅读/<uid>/ch/<nn>/edition/
  content.json   编辑层：hero、overview、sections、figures、charts、callouts、takeaways
  index.html     整页（内联 base.css + xerox.css）
  brief.json     字数、图数、判决理由
  audit.json     门禁结果与 stats
```

`Store.save_edition()` 整体替换 `edition/`，失败回滚；四读重生成会保留 `edition/` 与 `agent-standard.html`。

## 调

- 字段与上限：`src/bookcorpus/reading/edition/content.py` 的 `MAX_CHARS`、`CHART_KINDS`。
- 判决阈值：`edition/brief.py` 的 `MIN_HAN`、`MAX_HAN`、`MAX_IMAGE_RATIO`。
- 版式：`edition/styles/base.css` 与 `edition/styles/xerox.css`；`render.py` 只负责 DOM 与内联样式。
- 提示词：`edition/generate.py` 的 `SYSTEM_PROMPT`；改完 bump `PROMPT_VERSION`。
