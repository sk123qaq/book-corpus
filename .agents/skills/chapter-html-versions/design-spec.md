# 最终版设计要求（= 每章给 subagent 的任务书）

> 用法：整段发给一个 subagent，替换 5 个占位符。
> `{{BOOK}}` 书名 ｜ `{{STEM}}` 章节文件名（去掉 .md） ｜ `{{MD}}` 源 md 路径 ｜
> `{{THEME}}` 从 themes.md 选一套 ｜ `{{IMG_LIST}}` 本章图片清单

---

把《{{BOOK}}》**{{STEM}}** 这一章的 markdown 做成一页**可视化阅读版** HTML。

**目标**：读者 10 分钟内抓住这一章在讲什么、有哪几张关键图、能带走什么判断。
凡能用图、表、卡片说清的，就不写成段落。

## 产物

- `$BOOKS_ROOT/books/<uid>/html/{{STEM}}.html`
  （书目录不确定时查 `$BOOKS_ROOT/build/书目总表.csv` 的「路径」列）
- 单文件，CSS 内联在 `<style>`；图片用相对路径 `images/<文件名>`（图片收在同级的 `html/images/`）
- 体量 25–60 KB

## 工作方式

- 一次写出 HTML（单章超过 70KB 时分两块拼接）。
- 用 `read_image` 看本章的原书插图，照原图重建图表。
- 自检：核对下面的 7 个必备区块、核对源文 H2/H3 是否都有对应区块。
- 跑一次 `verify_lite.py`（命令见文末），四项 PASS 即收工。
- 现代事实拿不准的，标「基于逻辑推断」。

## 页面结构（7 个必备区块，按顺序）

1. **封面区**：章号、标题、一句导语、3–5 个关键数字或关键词
2. **目录 / 锚点导航**
3. **知识地图**：从本章 H2 主干导出 **4–7 层**，每层 3–8 个节点，层名用**本章自己的语义**；
   桌面高度 ≤ 1.5 屏；并列清单型章节换成分类树或矩阵承载。
   同时：**每个 H2/H3 标题旁挂一个「所在层」小标签**，层名与地图完全一致。
4. **正文分区**（若干，版式轮换）
5. **今天还成立吗**：3–8 条依赖特定历史／技术／监管／产业结构环境的判断，每条标「已核验」或「基于逻辑推断」；
   本章确无此类命题时，整块省略并在页脚注明「本章无需现代校验」
6. **回看**：一屏读完的结论清单——这一章要记住的判断、清单或步骤
7. **页脚**：来源 + 日期

## 版式与密度

- 用这一套主题：**{{THEME}}**（配色与字体见 `themes.md` 对应条目，全页统一）
- **版式轮换**：连续两个分区用不同的布局。可选：卡片网格 / 左右对照 / 时间线 / 矩阵表 /
  流程条 / 数据块 / 拉引金句 / 案例卡 / 双栏对照 / 步骤条
- 每个 H2 至少配 1 个视觉元素（图、矩阵、卡片组、流程图、对照表都算）
- 正文每 500–700 字由一个视觉元素打断

## 内容处理

- **保留**：全部 H2/H3 标题、核心定义、判断与结论、条件与风险、案例、图表与图题（如「图3–1」）
- **压缩**：长段落改成要点卡/矩阵/对照表，并列清单改成网格，重复表述合并
- **放开**：纯枚举的例证堆砌、历史沿革细节、过渡性铺陈
- **正文可读文字控制在源文的 30–45%**，其余信息交给图表
- 长清单、原始材料可放 `<details>` 折叠（默认收起）

## 图片处理

- 插图用 HTML/CSS/SVG **照原图重建**；矩阵用真 `<table>`（`table-layout:fixed` + 百分比列宽）
- 原书扫描件放进该图下方的 `<details>` 折叠块作参照——重建图与扫描件两者都有
- **图题（如「图3–1」）保留**
- 本章没有插图时，自己画 2–4 张概念图（结构图 / 流程图 / 对照矩阵 / 时间线）

## 三条技术约束

1. `<!DOCTYPE html>` 开头、`</html>` 结尾、`<html lang="zh-CN">`、`<meta charset>` + `<meta viewport>` 必写
2. **正文容器居中**：CSS 里有类似 `main{max-width:1100px;margin:0 auto;padding:0 22px}` 的规则
3. 窄屏不横向溢出：单列 grid 用 `minmax(0,1fr)`；宽表、宽图包在 `overflow-x:auto` 的容器里
