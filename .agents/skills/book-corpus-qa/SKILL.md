# 书库问答

回答问题的成本不在搜索，在读错地方和缺证据。全库逐字检索通常只要几秒，先自己测一遍：

```bash
cd "$BOOKS_ROOT"
time rg -l -g '*.md' '测试词' | wc -l
```

耗时随语料增长，但通常远小于读错一章的成本。所以先把书的形状看清楚，再动手。

下文用 `$BOOKS_ROOT` 指工作区根目录（有 `books.toml` 的那层）。没设这个变量时，先 `cd` 到工作区，或 `export BOOKS_ROOT=$PWD`。

## 四条铁律

1. **以书为准**。先找到原文再写结论。记忆只用来挑检索词和猜章节区间；凡进入答案的事实，必须能指着书里某一行。这本书里的措辞常常和通行说法不同，凭印象写一定错。
2. **元数据先行**。下钻任何章节之前，先读那本书的 `README.md`（章节清单、合集归属、**未收录清单**）。这是全书唯一免费的索引，先读它再决定读哪章。
3. **每条结论一个坐标**。写成 `books/<uid>/md/章节文件.md:行号`，**路径不缩写**。带省略号的路径无法核对，等于没给。
4. **查无即结论**。「未找到原文依据」是合格答案。它证明的是"我搜过并且确认没有"，不是"我没找到"。

## 先判题型，再决定怎么搜

题型决定答案藏在哪，也决定要不要相信关键词检索。

| 题型 | 典型问法 | 答案落点 | 关键词可信度 |
|---|---|---|---|
| **概念·理论** | 某个说法/法则/模型是什么 | 最早出现处给定义，中后段给推演，末章给验证 | 高，术语稳定 |
| **揭底·单点事实** | 凶手是谁、手法、动机、真实身份 | **最后 1–2 章**的揭底段 | 中。揭底章可能一个关键词都不含 |
| **跨卷聚合** | 某人的经历、两人关系线、跨册线索 | 沿线分散，需按阅读序推进 | **低**。第一人称与别名会让检索失效 |
| **主题·归纳** | 作者想表达什么、行为准则、标题含义、某转变的原因 | **没有单点**，原文只给事实链，答案由你合成 | 中。能定位素材，但定位不到论点 |
| **定位·清单** | 某句原文在哪、哪本书讲过 X、书里有没有提 Y | 书级 README 或单点 | 高，一步到位 |
| **对比·评价** | 两书两人两说法的差异 | = 前四类各取一次证据块再合成 | 取决于是哪两类 |

判完题型就把「检索」降级或升级：概念/定位型直接锚点取窗；揭底型从尾部倒着读；聚合型以顺序读为主、检索只用来划边界；归纳型先收齐相印证的素材，再把「原文写明的 / 我归纳的 / 原文没有的」三层分开标注。把第二层混进第一层是这类题最典型的失败。

## 四步流程

**S1 定书**：正文在 `$BOOKS_ROOT/books/<uid>/md/`。先查 `$BOOKS_ROOT/build/书目总表.csv` 的「书名／作者／路径」列，或

```bash
cd "$BOOKS_ROOT"
book-corpus run lq -H "SELECT uid,title,author,path FROM book WHERE title LIKE '%核心词%' OR author LIKE '%核心词%'"
```

`lq.py` 只读打开 `library.db`，字段用制表符分隔。也可以直接 `python3 -m sqlite3 build/library.db "..."`，但输出是 Python 元组，不适合脚本赋值。

书目录名是 uid，不承载书名；书名看 `book.json` 或 `build/书目总表.csv`。系列前缀不在目录名里（看 README 的「合集」字段或 `tables/系列/`）；检索词只取最短的核心词。

*完成判据*：能写出该书的目录路径（`books/<uid>/md/`），并读过它的 README；后续命令都在那个 `md/` 目录里跑。

**S1.5 不知道在哪本书里，先过检索层**（`build/检索/`，可重建产物，只读 `books/`）：

```bash
cd "$BOOKS_ROOT"
book-corpus search '<用户会打的词>' -n 20          # 段落倒排，按相关度排序
book-corpus search --concept <概念键> -n 20         # 同义词组展开，键在 tables/概念表.tsv
book-corpus search '<词>' --auto-concept -n 20      # 把打的词认成概念键（如 过密化 → 内卷）
book-corpus search --concept <概念键> --book -n 20  # 书级路由：「哪本书讲 X」先看这个
book-corpus search '<词>' --route -n 20              # 同上，但让模型先把词认成 3 个概念键再查
```

`--route` 的使用前提很窄：先把问句里的词跟 `tables/概念表.tsv` 对一遍，表里确实有讲这个话题的键时才加 `--route`。表里没有的时候它会硬挑三个不相干的键，把正确答案挤出前 20，比不加还差。拿不准就先不加，跑一遍看结果里是不是真有那个概念的段落。

用法边界：检索层只用来找材料和排候选，**它不是证据**。命中行必须回章节 md 用 `grep -nF` 复核后再引用。问法里一个原文词都没有时，别指望检索层，回到 S1 按书挑。

*完成判据*：拿到一份按名次排好的 `books/<uid>/md/xx.md:行号` 清单，或者明确判定检索层无命中、改走按书阅读。

**S2 定落点**：读 README，按题型选路。

- 概念/定位型：先在 S1.5 的 qsearch 清单里取候选，再在候选章里 `grep -n <最短中文核心词> *.md` 取命中行号。
- 揭底型：直接读最后 1–2 章，再回到前面补案发与线索。
- 聚合型：按 README 的 `NN_` 前缀顺序推进，检索只用来找沿线章节。
- 超长书（千章级）：先看 README 的章节标题，用标题里的实名/地点/事件收窄，再 grep。

*完成判据*：手里有一份候选章节文件清单，或者明确判定"无锚点命中，只能顺序读"。

**S3 取证**：用锚点取窗口，不要读大段。`rg -A45 -B3 '<唯一字符串>' <file>` 取一条引文；确实需要连续叙事（对白、庭审、结尾）才用 `read offset/limit`，一次 80–120 行。

*完成判据*：每条结论都能配一条逐字引文和行号。

**S4 交付**：交付前把每条引文回查一次，`grep -F '<引文首 12 字>' <file>` 确认逐字存在且行号对得上，顺手拿到准确行号。查不上的引文当场改写或降级为"未找到原文依据"。

*完成判据*：所有引文都通过回查，报告里没有未标注出处的断言。

## 六个高频坑

1. **译名墙**：通行问法和书内用词对不上，直接搜 0 命中。常见例子：市场先生→书里作「Market先生」；夹在中间→「进退两难」；延续性/颠覆性创新→「延续性技术/破坏性技术」；第五级领导力→「第5级经理人」；降维打击→原文无此词、作「维度打击」；加害者→「行凶者」。
   **对策**：先用最短的核心字试水（搜「先生」而不是「市场先生」，搜「破坏」而不是「颠覆性」），再看命中量级判断别名对不对；命中量为 0 时先怀疑词，不要先怀疑书。
2. **行号粒度**：正文常按「一段=一行」排版，单行可达数千字，`read` 又不显示行号。**引文只能定位到段**，所以要先用 `cat -n`、`grep -n ''` 或 `sed -n 'Np'` 反查行号，再落笔。
3. **拆书残留**：同一段文字常出现两处（章标题文件与正文小节文件重复、跨章重复、序章与中部重复），引用时固定到一处并说明。开场常混入盗版前置文件（`制作说明`、`精品书生产者`）和前置页占位（肖像、出版说明、各国版本自序），**从第一章顺序读之前先看文件名**。
4. **卷首卷尾未收录**：转换时可能丢弃序言、自序、前言、后记、导读。名著的经典论断常恰好在自序里。遇到「库里翻遍了却没有」的现象，回到 README 的「未收录」清单确认，然后如实告诉用户"该部分未被收录"。这比编一个答案有价值。
5. **书名与文件名不可靠**：卷序要看合集说明而不是排序；文件名里的「第X章」会按部重号，**排序只认 `NN_` 前缀**；有的书是「奇数章标题文件 + 偶数正文文件」交错，不能靠文件名判断内容在哪。
6. **检索语法坑**：中文文件名含括号、引号或间隔号，shell 里必须加引号；`grep` 默认 BRE，模式里写 `|` 要先加 `-E`；`find` 用 `-iname` 而不是 `-pattern`；一次全库 grep 会被输出上限截断，先限定目录再扫。

## 报告格式

```
## 答案           直接回答，分点
## 关键引文       每条附 file:line，路径完整不缩写
## 检索过程       关键命令原样引用，≤6 条
## 遇到的困难     具体到"哪一步卡住、为什么"
## 是否依赖先验记忆  分两层说：哪些只用于选检索词，哪些进了结论（后者必须为 0）
## 置信度         分项给，不要一个笼统的数
```
