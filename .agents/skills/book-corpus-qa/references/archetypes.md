# 六类题型的配方

题型的差别不在难度，在文本可导航性。答案集中、章节粒度细、术语稳定的题快；答案分散、别名多、单文件巨章的题慢。判题型时顺手估一下这三项，就知道这题大概要花多少步。

| 类型 | 答案位置 | 导航难度 | 为什么 |
|---|---|---|---|
| 推理解谜 | 揭底集中在一两章 | 低 | 章节目录细，篇名语义化 |
| 长篇系列叙事 | 沿线分散，跨卷 | 高 | 跨卷、别名、第一人称 |
| 严肃文学 | 无单点，需归并 | 中高 | 答案由多处素材合成 |
| 论说·学术史政 | 定义、推演、验证分段 | 中 | 段=单行，每次命中要啃数千字 |
| 商业·投资·管理 | 概念跨章 | 中高 | 译名落差，答案跨章 |
| 科幻设定 | 跨部，常在巨章 | 高 | 单文件巨章，文件名帮不上忙 |

耗时随语料、硬件与模型变化。要比较自己的语料，跑一批题现测，不要照抄别人的秒数。

## 语料在哪、书怎么定（所有配方共用）

正文在 `$BOOKS_ROOT/books/<uid>/md/`，一本书的章节文件全在它自己的 `md/` 里。`$BOOKS_ROOT` 指工作区根目录（有 `books.toml` 的那层），没设就先 `cd` 到那里或 `export BOOKS_ROOT=$PWD`。

先把两个变量立起来：

```bash
cd "$BOOKS_ROOT"
DB=build/library.db
LQ="book-corpus run lq"
BOOKDIR=$(python3 "$LQ" \
  "SELECT 'books/'||path||'/md' FROM book WHERE title LIKE '%核心词%' LIMIT 1")
ls "$BOOKDIR"
```

下面的配方里，`"<书>"` 就是 `$BOOKDIR`。

- 列候选书：`python3 "$LQ" -H "SELECT uid,title,author,path FROM book WHERE title LIKE '%词%' OR author LIKE '%词%'"`
  `lq.py` 只读打开 library.db。也可以直接用 `python3 -m sqlite3 "$DB" "..."`，但它输出 Python 元组，不适合赋值。
- 系列卷序：`python3 "$LQ" "SELECT volume,title,path FROM book WHERE series='系列名' ORDER BY CAST(volume AS INT)"`。
  卷序说明在 `tables/系列/<系列>-合集说明.md`。系列各卷的公共父目录记作 `$SERIES`。

## 1. 概念·理论型

**问法**：某个说法、法则、模型或概念是什么，怎么推出来的。

**落点**：定义在最早出现处，推演在中后段，验证或应用在末章。三者缺一不可。只给定义就是复述，给出"定义→推演→验证"才是完整回答。

**配方**

```bash
python3 "$LQ" "SELECT uid,title,path FROM book WHERE title LIKE '%短核心词%'"  # 1 定书
sed -n '1,40p' "$BOOKDIR/README.md"    # 2 拿目录与未收录清单
grep -n "核心词\|同义词\|别名" "$BOOKDIR"/*.md | head -40   # 3 看命中分布
sed -n '60,120p' "$BOOKDIR/01_xxx.md"  # 4 取定义段
grep -rn "另一核心词" "$BOOKDIR"/*.md | head -30            # 5 找推演与验证段
grep -F '<引文首12字>' "$BOOKDIR/04_xxx.md"                 # 6 回查行号
```

**注意**：术语稳定、反复出现时关键词可信度最高。但要分清"原文点名的概念"与"我归纳的概念"。原文说"两个重要概念：猜疑链和技术爆炸"，就不要把你自己数的"善意/恶意"也算进去。

## 2. 揭底·单点事实型

**问法**：凶手是谁、手法是什么、动机是什么、某人的真实身份。

**落点**：**最后 1–2 章的揭底段**（侦探陈述、凶手自白、书信、尾声）。这是全书信息密度最高的地方。先整章读它，再决定要不要回填。

**配方**

```bash
ls "<书>/" | tail -6                   # 1 直接看尾部文件
sed -n '1,60p' "<书>/<末章>.md"        # 2 整章读揭底段
grep -n "凶手\|自杀\|自白\|真相\|其实" "<书>"/*.md | tail -20   # 3 定位指认句
grep -n "<被害人名>\|<嫌疑人名>" "<书>"/*.md | head -30        # 4 回填案发与动机
```

**完成判据**：能引出一条**明确的指认句**（"凶手就是…"或自白段），而不是靠线索推演。推演可以作为补充，但必须标明是推演。

**专属翻车点**

- **揭底章可能一个关键词都不含**：真相章里「凶手」出现 0 次，指认全靠"你/她/他们"。进入尾段之后**整章读**，不要靠命中数挑章节。
- **红鲱鱼**：前中期出现最频繁的人往往是误导对象。真相出现在末章。
- **记忆污染风险最高的一类**：超知名作品的结局容易被模型先验补全。规则是先落揭底段，再写结论；答案与揭底段冲突时以书为准。
- **正文可能自相矛盾**：同一章里两个结论的编号前后不一致。并列报告两个编号，别替作者选。

## 3. 跨卷聚合型

**问法**：某人的经历、两人关系线、某个线索贯穿哪几册。

**落点**：沿时间线分散在各卷各章，无单点。

**配方**

```bash
python3 "$LQ" "SELECT volume,title,path FROM book WHERE series='系列名' ORDER BY CAST(volume AS INT)"  # 1 列全系列卷册
cat tables/系列/系列名-合集说明.md   # 2 定卷序（不要按 ls 排序）
for w in 本名 别称1 别称2; do printf "%s=%s\n" "$w" \
  "$(grep -ro "$w" "$SERIES"/*/md | wc -l)"; done  # 3 别名量级比对，必做
grep -rc "人物名\|线索词" "$SERIES"/*/md | grep -v ':0'  # 4 看每卷命中密度
grep -rn "关键动作词" "$SERIES"/*/md | head -30        # 5 定位具体节点
```

**别名量级比对是这一步的命门**：量级异常（0 或个位数）说明词错了，不是书里没有。中文译名不存在、英文名才有命中的情况很常见。第一人称「我」承载主要叙事时不可检索，这类问题以**按 `NN_` 前缀顺序推进**为主，检索只用来划边界。

**专属翻车点**

- **系列里混着前传**：某卷里主角出现次数极少，可能是前传而非本传。开局先甄别哪几卷属于主体。
- **"女主/恋人"可能多义**：不同卷的主线人物不同。遇到多义先声明按哪条线作答。
- **原文可能没有结论句**：关系"正式确立/结婚"这类表述可能根本不存在。定向检索确认无命中后，写"未找到原文依据"。

## 4. 主题·归纳型

**问法**：作者想表达什么、某行为准则是什么、标题的含义、某个转变的原因。

**落点**：**没有单点**。原文不提供论断，只提供分散的事实链与评论性段落。答案是你从多处引文合成出来的。

**配方**：先按主题词全库收敛到 2–4 处相印证的位置，再拼合。成品必须分层标注：

- ① 原文直接写明的（带引文）
- ② 由多处原文合成、原文未如此命名的（标注"归纳"）
- ③ 原文没有的（写"未找到原文依据"）

**完成判据**：报告里三层清楚分开。把 ② 混进 ① 是这类题最典型的失败。

**专属翻车点**

- **作者本人可能否认过这个"寓意"**：遇到这种情况，只引作者原话，不往前加阐释。
- **标题含义常常无解释**：正文不解释标题时，可以引同一作者同期随笔作**间接证据**，但必须注明是推断。
- **旁证文本可能版本冲突**：早期梗概稿的人物设定与定稿不同。一律以定稿正文为准。

## 5. 定位·清单型

**问法**：某句原文在哪、哪本书讲过 X、书里有没有提到 Y。

**落点**：书级 README 或单点命中。**一步到位，不要下钻正文**。

**配方**

```bash
cd "$BOOKS_ROOT/库"
grep -rl "主题词" --include=README.md .          # 1 哪本书讲过，只扫 README
grep -rn "原文片段" --include='*.md' .           # 2 某句在哪，全库直取
grep -rn "X" "$BOOKDIR" ; echo "exit=$?"        # 3 有没有提到，exit=1 就是标准答案
```

**完成判据**：给出 file:line 即完成。**不要因为"顺手"而继续读上下文**。这类题超支的原因几乎都是越界下钻。

**注意**：`grep -l` 扫 README 很划算，每本书的 README 都列了章节标题，等于一份全库主题索引。命中的书超过 3 本时，再下钻到正文确认。

## 6. 对比·评价型

**问法**：两本书、两个人物或两个说法之间的差异。

**做法**：**先各取一次证据块，再对比**。不要边读边比，那样会反复回头，是最容易超支的做法。

**配方**

```bash
# 第一块
grep -n "主题词" "<书A>"/*.md | head -20
# 第二块（独立完成，不要一边比一边找）
grep -n "主题词" "<书B>"/*.md | head -20
# 合成：逐条列出"相同/不同/书A独有/书B独有"，每条附出处
```

**注意**：若两本书是**同一书的不同译本**，先确认用哪一版并全程只用它，否则人名与标点会互相打架。

## 三个示例

**① 查无即结论（揭底型）**
问"侦探最后如何处置凶手"。正文读到末章只得到手稿作者的话："我不知道是谁杀了他们。"真正的定案在《后记》里，而 README 的未收录清单明写「后记 — front/back matter」。正确交付：说明该部分未收录、正文止于何处，并给出正文能确认的部分。**不要从记忆里补一个结局。**

**② 别名量级（聚合型）**
问"主角与女主的经历"。先跑别名量级：中文译名 0 命中，英文名每卷数百次，第一人称「我」承载主线。结论立刻清楚：放弃"搜人名"，改成按卷顺序读，用别名定位关键节点。顺手还能发现某卷是前传。

**③ 译名墙（概念型）**
问"市场先生是什么"。`grep -rn "市场先生"` 零命中，书里译作 `Market先生`（保留英文姓）。对策是先搜核心字"先生"再判断。同类：夹在中间→进退两难、第五级领导力→第5级经理人、降维打击→原文无此词、加害者→行凶者。
