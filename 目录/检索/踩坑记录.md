按类型分。同一类里的现象、根因、别再这么干、正确做法写在同一行，撞上时先查这一份，别重走。

## A 类 模型接口

| 现象 | 根因 | 别再这么干 | 正确做法 |
|---|---|---|---|
| 回包是空字符串，连续两次都空 | `max_output_tokens` 给太小（1200），模型的思考 token 先把额度吃光，正文一个字没剩 | 失败后把上限放大再试一次 | 一次给足（12000），输出长度在提示词里约束。实测一次调用约 6 秒，其中九成是模型自己的思考开销 |
| `HTTP Error 429: Too Many Requests`，一小时内从 0 涨到 926 条 | 24 个线程连打一小时，自己把接口限流了。退避只等 3 秒和 6 秒，对限流等于连续撞 | 限流时加线程，或者用短退避重试 | 并发压到 4 到 8。退避改 5 秒、15 秒、40 秒。限流是自家造成的，不是接口坏了 |
| `The read operation timed out`、`urlopen error _ssl.c:1064: The handshak...` | 同上，并发抢接口 | 判断成「接口挂住，这条路走不通」 | 降到 2 个线程后，60 题只剩 2 题失败，重试一次就过。上午据此误判过一次，把一条本来能用的通道停了 |
| 模型不按格式输出，行首没有编号 | 提示词只说「一行一个」，没给编号契约 | 静默跳过解析不了的行 | 解析要容错（去编号、去引号、限长度），并且要求有效行数达到阈值才算成功。低于阈值当失败处理，让上层重试 |
| 同一批 5 章只回来 3 行 | 模型漏行，`parse()` 对缺失的编号静默返回空 | 认为整批都成功了 | 按编号逐条核对，缺的章单独重排。`parse()` 已改成编号越界时按出现顺序补位，漏行仍会丢章，见已知未修 |
| **换供应商后输出编号全错**，5 章回 `10|`、`11|`、`12|` | 提示词里有两套数字。块编号是 1 到 5，而 `title_of()` 读出的章标题自带序号（三毛那本书的标题就是「10 林妹妹的裙子」）。模型抓了标题里的数字 | 以为模型不守约，去改解析逻辑兜底 | 先消输入歧义。标题以数字开头时把数字剥掉。`--provider mimo` 已加但默认仍是 commandcode |
| **模型对畸形输入整批不返回**，连跑五次 content 都是空 | 待扩章节取到 0 个，提示词里真的没有章节。模型在思考里写「用户说 0 个章节，我应该什么都不输出」，然后交白卷 | 假设模型会兜底 | 提交前校验 `n >= 1`，空批直接跳过不调用 |
| **MiMo token plan 内容风控**，回包 content 是 `The request was rejected because it was considered high risk`，HTTP 200 不是错误码 | 小米 token plan 有内容过滤，命中政治、暴恐等题材就整批拒。实测《1984》原文必拒，去掉书名和专名后放行 | 把 200 当成功；或者判断成网络故障去重试 | 按 `high risk` 字样识别并单独归类（已加 `ContentRejected`）。全书库 22 GB，这类书不会少，所以 MiMo 没进主流程，`--provider` 默认仍是 commandcode |
| 退避 3 秒、6 秒对限流无效 | 429 是配额拒绝，短间隔等于连续撞 | 用固定短退避 | 5 秒、20 秒、45 秒。已改 |
| **`HTTP Error 400: Bad Request`，重试三次全失败**，回包体只说 `invalid request error`，没有具体字段 | deepseek 接口的内容过滤。触发条件是组合而不是单个词：正文里的历史事件表述加上某个统计资料来源的书名同时出现就拒。实测第 5 句（含 1989 年事件表述）单独发 200，第 6 句（《数字中国三十年》版权行）单独发 200，两句一起发必 400；把事件表述去掉放行，把书名换成《数字中国》也放行 | 把 400 当成网络故障去重试；或者以为正文里有非法字符 | 按内容拒绝处理，不要重试同一份内容。真正的修法是拆小：整批 400 就批对半，单章还 400 就把正文对半，哪半能过用哪半。已实现，`expand_chunk` 会自己走到 4 层（`批拆半` → `正文拆半`）。触发这一条的实例是 B0130 第三章，拆半后正常产出 |
| **所有请求 429，退避重试全灭**（15 章 × 3 次加拆半全败） | commandcode **周额度**用尽，不是瞬时限流。响应体写明 `rate_limit_error` 与 reset 时间 | 把 429 一律当自家并发打出的限流去退避 | 先读响应体。写 `weekly usage limit` 就等 reset（本次 2026-10-22T13:33Z）或换 `--provider mimo`。探针一次请求就能分辨（2026-10-21） |
| **拒答文本进了索引**，queries 行里存着「正文为空，无法生成检索式，请补充正文后重试」 | `_parse_queries` 把回包不管内容整段入库，模型的自言自语成了索引文本 | 模型回包直接入库 | 入库前验形态：不足 3 条编号检索式当失败丢弃。已加（2026-10-21） |
| **Jev 1.14 判「前缀有没有点到概念词」与 token 不一致** | 随机 100 章上 Choice 与 token126 一致 62%（kappa 0.13），并集候选下与 token 并集一致 47%（kappa 0.04）。错误是近邻概念当命中（正义→自由）、次要提到判无（前缀含自由却选无）。Jev 以英文为主，CJK 细粒度语义不稳 | 把 Jev 当 token 的校准器或替代品 | 选章用 token 并集；Jev 只在有 500 章人标集时再评估。见 `工作区/批次/qa-检索-2026-10-22-选章器/实验报告-选章器.md`（2026-10-22） |

## B 类 SQLite 与全文索引

| 现象 | 根因 | 别再这么干 | 正确做法 |
|---|---|---|---|
| `sqlite3.DatabaseError: database disk image is malformed` | 外部内容表（external content）的 FTS5 表重复执行 `DELETE` 会把索引写坏 | 用 `DELETE` 加 `rebuild` 做增量更新 | 要么 `DROP` 虚表再建再 `rebuild`，要么干脆全量重建。全库 235 万段只要 5 分半，不值得为它维护增量 |
| 中途 kill 后新写的章查不到 | 只在收尾时 `INSERT INTO expand_fts(expand_fts) VALUES('rebuild')` | 把索引重建当作独立收尾步骤 | 每本书提交时同步插索引。已改成这样，中途停机不丢数据（13:51 kill，库里 66,018 章全部可查） |
| `sqlite3.OperationalError: unable to open database file` | 只读连接打开了一个正在被写的库 | 用同一个连接既读又写 | 只读用 `file:...?mode=ro`，并且容忍并发写造成的短暂失败。`index.db` 5.86 GB，写的时候读会撞 |
| `KeyError: 'key'` 读概念表 | `lib_common.read_csv` 用逗号分隔，概念表是制表符分隔 | 假设项目里所有表都是 csv | 显式 `csv.DictReader(fh, delimiter="\t")`。已修 |
| `expand` 表的 token 累计比真实值大 692 倍 | `main()` 把整本书的 `tin/tout` 赋给该书每一行，行数等于章数 | 用整批的总量当每条的账 | 每行存按书均摊值，真实总量记在 `目录/检索/build.log`。已修，均摊后与日志相差 1.38 倍（同书内每章 token 其实不等，要精确账只能按块记） |
| `expand_fts` 行数与 `expand` 相等，但 3,967 行怎么都查不到 | external-content FTS5 的 `count(*)` 与 rowid 探测都穿到内容表读，行数相等不代表进过索引 | 用行数相等当索引完整性的证据 | 用 MATCH 抽查：行内取 bigram token 查命中，看 rowid 回不回得来。漂移用 `build_expand.py --reindex-fts` 全量重建（8.7 万行 1 秒）（2026-10-21） |
| 新写的 expand 行查不到（09:51 之后写入的全漏） | sink 插 `expand_fts` 时 SELECT 的键用绝对路径，`expand` 表存库相对路径，插入静默 0 行。之前没暴露是 09:51 `--rebuild` 的 FTS rebuild 把旧缺口盖住了 | 同一张表的键在两处各算各的 | relpath 一次算好两处共用；REPLACE 前先删旧 FTS 文档防幽灵。已修（2026-10-21） |
| 读概念表 `KeyError: 'key'`（第二回） | 编辑器保存人账加了 UTF-8 BOM，`DictReader` 首列变成 `\ufeffkey` | 假设人账文件不带 BOM | 读人账一律 `encoding="utf-8-sig"`（`lib_common` 读分类表早已如此）。eval_retrieval/qsearch/build_para_index/concept_expand 四处已改（2026-10-21） |

## C 类 检索评测

| 现象 | 根因 | 别再这么干 | 正确做法 |
|---|---|---|---|
| 60 题全部 0 命中，连明显该中的题也不中 | 把用户原句直接喂给 FTS5，整句被当成一个连续短语（phrase query） | 用问句当检索词 | 基底用关键词，问句只给模型做扩展。`eval_retrieval.py` 的 `terms` 列就是为此加的 |
| MRR 系统性偏高约 0.01 | 没找到的题按「第 99 名」记了 `1/99` 分 | 用截断名次算倒数 | 没进候选记 0。修完后 A 档从 0.009 变 0.008，B 档 0.032 变 0.031 |
| `rg` 连跑两遍 `recall@10` 在 0.017 和 0.033 之间跳 | 多线程遍历顺序不稳 | 当成随机噪声接受 | 加 `--sort path`。已修，两遍逐字节相同 |
| J 档读数与 E 逐题完全相同，像扩展实验无效 | 被测的 15 行根本没进 FTS 索引（见 B 类），不是扩展没用 | 读数异常先怪实验结论或模型 | 先证明被测对象真进了系统（MATCH 抽查、词覆盖诊断），再下结论。修复后同题 0.05→0.25（2026-10-21） |
| 融合两个结果列表，前 100 名一条没变 | 主档权重给 3、副档给 1，副档即使排第一也低于主档第 100 名 | 没量权重就做融合 | 先量权重再下结论。K 档为此白跑一趟 60 题 |
| 概念路由 0.333，删掉 18 个键后掉到 0.033 | gold 的 19 个概念里 18 个正好是概念表的键，等于在含答案的小集合里挑 | 让出题用的词表同时当检索用的词表 | holdout 法，把答案键从表里删掉再测。路由的真实价值只在表覆盖到该话题时成立 |
| 路由在表里没有该话题时硬挑 3 个键，把正确答案挤出去 | 提示词要求「必须挑 3 个」 | 逼模型在不合适的候选里选 | 允许回答「无」，没命中就退回纯段落档。待实现 |
| **宽词层章级 hit 不涨，书级涨** | 宽词别名太常见，目标段落在宽词组里排到 2000 名之外；章级 RRF 每组只取前 100 段，融合前就丢了 | 用单章 gold 评宽词层，或者把宽词直接并进 126 主表 | 宽词只当捞书层。40 题书 hit@10 从 8/40 到 12/40，章 hit@10 从 1/40 到 1/40；严格子集书 2/17 到 5/17。章级先做书级融合，再读 README 选章。见 `工作区/批次/qa-检索-2026-10-22-宽词层/实验报告-宽词层.md`（2026-10-22） |
| 评测跑 611 秒 | 60 题串行，每题一次模型调用 | 评测脚本单线程 | 加 `--jobs`，默认 8 并发。同样的题 38 秒跑完 |

## 供应商对比（2026-10-20 实测，同一批 5 章同一提示词）

| | commandcode `deepseek-v4.1-flash` | 小米 `mimo-v2.6-flash` |
|---|---|---|
| 协议 | Responses API（`/provider/v1/responses`） | OpenAI Chat Completions（`/v1/chat/completions`） |
| 编号守约 | 守约，1 到 5 | 不稳。`effort=high` 下四轮三轮对；默认档四轮里一轮对 |
| 输出长度控制 | `max_output_tokens`，2500 起够用 | 同样字段，但思考 token 吃掉大半，要给 8000 以上 |
| 内容风控 | 无 | **有**。政治、暴恐题材整批拒，回包是 `high risk` 字样而 HTTP 仍是 200 |
| 畸形输入 | 会尽量给结果 | 直接交白卷，思考里写「用户说 0 个章节」 |
| 速度 | 一批 5 章约 6 秒 | 一批 5 章约 10 到 20 秒 |

结论：MiMo 没进主流程。`build_expand.py --provider` 留着当选项，默认 `commandcode`。要用 MiMo 先解决编号歧义和风控拒答两件事。

2026-10-21 补（queries 通道实测 500+ 章）：编号歧义只坑 prefix 批量解析（`parse()` 按编号认领），queries 是单章整段收（`_parse_queries`），mimo 不踩这个坑，本次无偏实验就是它跑的。风控拒答未出现，动物农场（革命题材）与丘吉尔战争回忆录的章都过了。每条检索式 100% 满足「≥2 个正文外词」（bigram 近似），新词率 0.78，低于 deepseek 的 0.83 但同档。
